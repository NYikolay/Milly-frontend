## 1. Контекст и цель

Шторки «Метки» и «Проект» уже открываются в едином expanded-сценарии и
сохраняют семантику `stepDraft` → «Применить»/закрытие. При этом их
содержимое расходится с актуальными фреймами Figma:

- в шторке «Метки» используется `tag.svg` размером `24px`, кольцо выбора
  рисуется точкой `10px`, строки имеют высоту `47px`, поиска нет;
- в шторке «Проект» иконка проекта — плоская `18px`-иконка, окрашенная в
  `project.color.hex`; для «Без проекта» используется `file.svg`; строки
  имеют высоту `50px`, разделитель после последней строки отсутствует,
  поиска нет;
- чип выбранного проекта повторяет плоскую иконку, тогда как на фото
  выбранного проекта под инпутом иконка заключена в цветной круг.

Цель итерации — привести обе шторки и чип проекта к Figma:

- добавить поле «Поиск» с рабочей фильтрацией списков;
- заменить иконки проектов на круглый бейдж `28×28` с отступом `5px` и
  белой иконкой `18×18`; для «Без проекта» использовать `no-project.svg`
  на фоне `app-track` с цветом `app-text`;
- в шторке «Метки» использовать `tag-raw.svg` `18×18` и цвет метки;
- привести кольцо выбора метки, высоты строк, отступы и разделители к
  фреймам;
- переименовать основную кнопку обеих шторок в «Готово»;
- адаптировать обе шторки и чип под тёмную тему через токены `app-*`.

Данные, API, React Query, payload, zustand-стор и семантика
применения/отбрасывания изменений не меняются.

## 2. Пользовательские сценарии

1. Пользователь открывает шторку «Метки». Сверху видно поле «Поиск», ниже
   — список меток: кольцо выбора, `tag-raw.svg` цвета метки, название
   цвета метки и разделитель под каждой строкой. Внизу — «Готово».
2. Пользователь вводит часть названия метки. Список фильтруется без учёта
   регистра; уже выбранные, но скрытые фильтром метки остаются
   выбранными. Очистка поля возвращает полный список.
3. Пользователь вводит запрос, которому не соответствует ни одна метка.
   Под поиском показывается «Ничего не найдено»; «Готово» применяет ранее
   выбранные метки.
4. Пользователь открывает шторку «Проект». Сверху — «Поиск», первая
   строка — «Без проекта» с серым круглым бейджем и `no-project.svg`,
   ниже — проекты с цветным круглым бейджем и белой иконкой; выбранная
   строка отмечена синей галочкой. Внизу — «Готово».
5. Пользователь вводит часть названия проекта. Список проектов
   фильтруется; «Без проекта» остаётся первой строкой всегда. Если
   проектов по запросу нет, под строкой «Без проекта» показывается
   «Ничего не найдено».
6. Пользователь выбирает проект и нажимает «Готово». Чип проекта под
   инпутом показывает тот же круглый бейдж с цветом и белой иконкой
   проекта и название проекта.
7. Пользователь выбирает «Без проекта» и нажимает «Готово». Чип
   показывает серый круглый бейдж с `no-project.svg` и текст «Без
   проекта».
8. Пользователь открывает приложение в тёмной теме. Обе шторки и чип
   сохраняют геометрию и используют тёмные токены: панель `app-card`,
   поле поиска и фон бейджа «Без проекта» `app-track`, разделители
   `app-stroke`, текст `app-text`/`app-text-secondary`. Цветные бейджи
   проектов сохраняют цвет из backend.

## 3. Функциональные требования

### FR-1. Поле поиска

- Новый переиспользуемый примитив
  `app/components/ui/search-field.tsx`, экспорт `SearchField`.
- Пропсы: `value: string`, `onChange: (value: string) => void`,
  `ariaLabel: string`, опциональный `placeholder` (по умолчанию
  `"Поиск"`).
- Разметка:
  - контейнер:
    `flex h-[45px] w-full items-center gap-[10px] rounded-[25px] bg-app-track px-[15px]`
    и
    `focus-within:outline-2 focus-within:-outline-offset-2 focus-within:outline-app-accent`;
  - иконка: `AssetIcon` с `search.svg`, `size-5 shrink-0 text-app-text-secondary`;
  - input: `type="search"`, `value`, `onChange`, `placeholder="Поиск"`,
    `aria-label`, классы
    `min-w-0 flex-1 appearance-none bg-transparent text-[15px] leading-[1.3] text-app-text outline-none placeholder:text-app-text-secondary [&::-webkit-search-cancel-button]:appearance-none`.
- Поле рендерится в обеих шторках над списком при любом состоянии
  (загрузка, ошибка, пусто, результаты).
- Кэшированные строки проектов фильтруются тем же запросом, что и
  загруженные; состояния загрузки/ошибки остаются после строки «Без
  проекта». В «Метках» список во время загрузки/ошибки не показывается,
  поэтому фильтр применяется только к успешно загруженному списку.
- Поле поиска не закрепляется: оно прокручивается вместе с содержимым
  шторки, как остальные элементы тела `BottomSheet`.
- Поле поиска не очищает выбранные значения: скрытый фильтром
  выбранный проект по-прежнему применяется по «Готово».
- Фильтрация выполняется чистой функцией
  `matchesSearchQuery(value: string, query: string): boolean` из
  `app/components/tasks/quick-add/search-filter.ts`:
  `query.trim().toLowerCase()`; пустой запрос соответствует любой строке;
  иначе — `value.toLowerCase().includes(normalizedQuery)`.
- В «Метках» фильтр применяется к загруженным меткам; `visibleSelected`
  по-прежнему строится по полному списку `items`, поэтому скрытые
  фильтром выбранные метки не теряются при «Готово».
- В «Проекте» фильтр применяется только к реальным проектам. Строка
  «Без проекта» не фильтруется и всегда остаётся первой.
- Если запрос непустой, список загружен без ошибки и совпадений нет:
  - в «Метках» вместо списка показывается «Ничего не найдено» в стиле
    `text-[15px] text-app-text-secondary`;
  - в «Проекте» под строкой «Без проекта» показывается «Ничего не
    найдено» в стиле `px-[15px] py-[10px] text-[15px] text-app-text-secondary`.
- Пустой список меток (меток нет вообще) сохраняет существующий текст
  «На текущий момент у вас не создано ни 1 метки» даже при непустом
  запросе: это состояние важнее «Ничего не найдено».
- Геометрия «Меток»: между поиском и блоком списка `15px`; контейнер
  списка имеет горизонтальные отступы `15px` и `gap-[10px]` между
  строками; поэтому строка уже поля поиска на `15px` с каждой стороны.
- Геометрия «Проекта»: поиск и строки идут без дополнительного зазора;
  строка занимает всю ширину контента, а её содержимое центрируется по
  вертикали внутри `59px`.

### FR-2. Иконки и бейджи проектов

- Новый компонент
  `app/components/tasks/quick-add/project-icon-badge.tsx`, экспорт
  `ProjectIconBadge`.
- Пропсы: `icon: string`, `colorHex: string | null`,
  опциональный `className?: string`.
- Бейдж:
  - `flex size-7 shrink-0 items-center justify-center rounded-full p-[5px]`;
  - иконка `AssetIcon` `size-[18px]`;
  - при `colorHex === null`: `bg-app-track text-app-text`, без inline
    `backgroundColor`;
  - при цвете: inline `backgroundColor: colorHex` и `text-white`.
- В `app/lib/projects/project-icons.ts` добавить импорт
  `no-project.svg?no-inline` и экспорт
  `export const NO_PROJECT_ICON: string`.
- `getProjectIcon(icon: string | null)` сохраняет текущее поведение:
  известная иконка → соответствующий asset, `null`/пустая/неизвестная →
  `file.svg`. Для реального проекта с неизвестной иконкой остаётся
  `file.svg`.
- `NO_PROJECT_ICON` используется только для состояния «Без проекта»:
  строка шторки и чип.
- Бейдж используется в строке шторки «Проект» и в чипе проекта под
  инпутом.

### FR-3. Шторка «Проект»

- Над `role="radiogroup"` рендерится `SearchField` с
  `ariaLabel="Поиск проектов"`.
- Строка:
  - кнопка `role="radio"`, `aria-checked`, высота `h-[59px]`, `gap-[15px]`,
    прежние focus-visible и active-классы;
  - индикатор выбора — `check.svg` `size-6 text-app-accent` у выбранной
    строки; у невыбранной — пустой `span size-6 shrink-0`;
  - контентная обёртка
    `flex h-full min-w-0 flex-1 items-center gap-[5px] border-b border-app-stroke`;
  - внутри — `ProjectIconBadge` и название
    `truncate text-[15px] leading-[1.3] text-app-text`.
- Разделитель `border-b border-app-stroke` рисуется после каждой строки,
  включая последнюю.
- «Без проекта» — первая строка всегда, в том числе при непустом поиске;
  `icon={NO_PROJECT_ICON}`, `colorHex={null}`.
- Состояния загрузки и ошибки остаются после строки «Без проекта», перед
  кэшированными проектами; «Повторить» сохраняется.
- Нет отдельного пустого состояния для нулевого количества проектов без
  запроса: показывается только «Без проекта».
- Основная кнопка — «Готово», обёрнута в `mt-auto pt-[15px]`, применяет
  `selectedId` (включая `null`).

### FR-4. Шторка «Метки»

- Над списком рендерится `SearchField` с `ariaLabel="Поиск меток"`.
- Блок контента отделён от поиска на `15px` (обёртка `mt-[15px]`).
- Успешный список — `<ul className="flex flex-col gap-[10px] px-[15px]">`;
  строки уже поля поиска на `15px` с каждой стороны, между строками
  `10px`.
- Строка:
  - кнопка `role="checkbox"`, `aria-checked`, высота `h-[50px]`,
    `gap-[15px]`, прежние focus-visible и active-классы;
  - кольцо выбора `size-5` (`20px`), `rounded-full border`;
    - выбранная: `border-app-accent` и внутренняя точка
      `size-[15px] rounded-full bg-app-accent`;
    - невыбранная: `border-app-text-secondary/55`, без точки;
  - контентная обёртка
    `flex h-full min-w-0 flex-1 items-center gap-[5px] border-b border-app-stroke`;
  - иконка `tag-raw.svg` `size-[18px]` с цветом `label.color.hex`;
  - название `min-w-0 flex-1 truncate text-[15px] leading-[1.3]` с
    цветом `label.color.hex`.
- Разделитель рисуется после каждой строки, включая последнюю.
- Состояния загрузки, ошибки и пустого списка сохраняют существующие
  тексты; поле поиска остаётся видимым.
- Дубликаты меток по `id` отбрасываются, лимит `MAX_LABEL_COUNT = 100`
  сохраняется.
- Основная кнопка — «Готово», обёрнута в `mt-auto pt-[15px]`, применяет
  `uniqueLabelIds(visibleSelected)`.

### FR-5. Чип проекта под инпутом

- Чип проекта в `quick-add-chips.tsx` использует `ProjectIconBadge`:
  - выбранный проект: `icon={getProjectIcon(project.icon)}`,
    `colorHex={project.color.hex}`;
  - без проекта: `icon={NO_PROJECT_ICON}`, `colorHex={null}`.
- Текст чипа: название проекта или «Без проекта»; `aria-label` остаётся
  `Проект: <name>` / `Выбрать проект`.
- Размеры, отступы, порядок чипов и `OptionChip` не меняются.
- Чип меток не меняется: при выбранных метках остаётся `tag.svg`
  `size-[18px]` с цветом первой метки; без меток — `tag-plus.svg`
  `size-6`.

### FR-6. Тёмная тема

- Используются только токены `app-*`; `dark:`-классы и хардкод цветов
  Telegram не добавляются.
- `bg-app-track`, `bg-app-card`, `border-app-stroke`, `text-app-text`,
  `text-app-text-secondary`, `border-app-accent`, `bg-app-accent`
  автоматически меняются через `[data-app-theme="dark"]`.
- Цветные бейджи проектов сохраняют `project.color.hex` в обеих темах;
  глиф остаётся белым (`text-white`).
- Бейдж «Без проекта» в тёмной теме: фон `app-track` (`#303033`), глиф
  `app-text` (`#ffffff`).
- Никаких новых CSS-переменных не требуется.

### FR-7. Доступность

- Поле поиска имеет доступное имя: «Поиск меток» / «Поиск проектов».
- `radiogroup`/`radio`/`checkbox`, `aria-checked`, `aria-label` чипов и
  кнопки «Готово» сохраняются.
- Иконки в бейджах и поле поиска остаются `aria-hidden` через
  `AssetIcon`.
- Focus-visible кольца сохраняются у строк, кнопки и поля поиска.
- Высота строк и поле поиска остаются не меньше `45px`, чтобы не
  уменьшать зоны нажатия.

## 5. Нефункциональные требования

- Новые зависимости не добавляются.
- SSR включён; шторки открываются только после `AuthGate`.
- `useState` для поиска используется только внутри клиентских
  компонентов; на сервере начальное значение — пустая строка, обращений
  к `window`/`document` нет.
- TypeScript strict, без `any`; типы — через `import type`.
- Файлы — `kebab-case`, компоненты — `PascalCase`, алиас `~/`.
- Тесты — Vitest, `app/**/*.test.ts`; среда — `node`, без jsdom.
- Линтера в проекте нет; `npm run lint` не добавлять.

## 7. Критерии приёмки

- [ ] В шторке «Метки» сверху есть поле «Поиск», список фильтруется без
      учёта регистра; при отсутствии совпадений показывается «Ничего не
      найдено».
- [ ] В «Метках» используется `tag-raw.svg` `18×18` цвета метки;
      кольцо выбора `20×20`, выбранная точка `15×15`, невыбранная
      граница `app-text-secondary/55`.
- [ ] Строки меток имеют высоту `50px`, отступы `15px`/`5px` и
      разделитель после каждой строки.
- [ ] В шторке «Проект» сверху есть поле «Поиск»; «Без проекта» всегда
      первая строка с `no-project.svg` на `bg-app-track`.
- [ ] Проекты показываются с круглым бейджем `28×28`, padding `5px`,
      белой иконкой `18×18` на фоне `project.color.hex`.
- [ ] Строки проектов имеют высоту `59px`, галочку `24×24` и
      разделитель после каждой строки.
- [ ] Выбранный проект под инпутом показывает тот же круглый бейдж;
      «Без проекта» — серый бейдж с `no-project.svg`.
- [ ] Обе шторки используют кнопку «Готово»; закрытие без применения
      отбрасывает изменения, «Готово» коммитит их.
- [ ] Скрытые фильтром выбранные метки и проект не теряются при
      «Готово».
- [ ] В «Метках» между поиском и списком `15px`, контейнер списка имеет

- [ ] Чип меток не изменился: `tag.svg`/`tag-plus.svg`.
- [ ] Тёмная тема использует только токены `app-*`; цветные бейджи
      проектов сохраняют цвет backend.
- [ ] `npm test`, `npm run typecheck`, `npm run build` проходят.
- [ ] Вручную проверены light/dark, ширины `320 / 412 / 448px`,

## 8. Принятые решения

1. **Поиск функциональный, а не декоративный.** Фрейм содержит поле
   «Поиск», поэтому оно не только отображается, но и фильтрует списки.
2. **Копирайт пустой выдачи.** В Figma нет состояния «ничего не
   найдено»; вводится текст «Ничего не найдено», чтобы поиск не выглядел
   сломанным.
3. **«Без проекта» не фильтруется.** Это служебный вариант, а не проект;
   он остаётся первым при любом запросе.
4. **Скрытые выбранные метки сохраняются.** Фильтр влияет только на
   отображение; «Готово» применяет полный набор `visibleSelected`.
5. **Кнопка «Готово».** Обе шторки используют текст из Figma вместо
   «Применить»; семантика та же.
6. **`no-project.svg` только для «Без проекта».** Неизвестная иконка
   реального проекта по-прежнему падает в `file.svg`, чтобы не выдавать
   проект за «без проекта».
7. **`tag-raw.svg` только в шторке.** Чип меток под инпутом уже
   соответствует дизайну и не меняется (`tag.svg`/`tag-plus.svg`).
8. **Граница кольца 1px.** У невыбранной метки в макете `1.3px`; для
   единообразия с существующими бордерами используется `1px`, цвет —
   `app-text-secondary/55`.
9. **Бейдж — общий компонент.** Один `ProjectIconBadge` используется и в
   шторке, и в чипе, чтобы стили не разъезжались.
10. **Поиск не закрепляется.** Он прокручивается вместе с телом шторки,
    как остальной контент; отдельный sticky-слой не вводится.
11. **Скрытый проект сохраняется.** Фильтр не сбрасывает `selectedId`;
    «Готово» применяет выбранный проект, даже если его строка скрыта
    запросом.
12. **Нет меток — важнее поиска.** Если меток нет вообще, показывается
    существующий текст «На текущий момент у вас не создано ни 1 метки»
    даже при непустом запросе.
13. **Геометрия списков разная по Figma.** «Метки» имеют зазор `15px` от
    поиска, отступ `15px` по бокам и `10px` между строками; «Проект» —
    строки на всю ширину без зазора от поиска.
