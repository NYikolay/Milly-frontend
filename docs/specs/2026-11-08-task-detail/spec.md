## 1. Контекст и цель

В приложении уже есть два списка задач: `/tasks` («Задачи на сегодня») и
`/tasks/search` («Поиск задач»). Оба используют общий `TodayTaskRow`:
чекбокс завершения интерактивен, шеврон декоративный, перехода в детали
нет. В спецификациях `2026-11-06-today-tasks` и `2026-11-07-task-search`
экран детальной информации задачи явно вынесен за scope.

Backend уже поддерживает всё необходимое: `GET /tasks/{task_id}`,
`POST /tasks/{id}/complete`, `POST /tasks/{id}/uncomplete` и
`DELETE /tasks/{id}`. Новых серверных контрактов не требуется.

Цель итерации — реализовать экран `/tasks/:id` по четырём фреймам Figma:

- просмотр детальной информации задачи в светлой и тёмной теме;
- переход в детали по нажатию на строку задачи из `/tasks` и
  `/tasks/search`;
- завершение и возврат задачи в исходное состояние;
- удаление задачи с подтверждением в нижней модалке;
- возврат назад по истории после удаления;
- состояния загрузки, ошибки и «задача не найдена».

Итерация только про чтение и два действия — завершение и удаление.
Изменение названия, описания, срока, приоритета, меток, проекта и
напоминаний не делается.

## 2. Пользовательские сценарии

1. Пользователь нажимает на строку задачи в `/tasks` или
   `/tasks/search` (не на чекбокс). Открывается `/tasks/:id`: заголовок,
   описание, карточка свойств, дата создания, кнопки «Отметить
   выполненной» и «Удалить задачу». Активна вкладка «Задачи».
2. Пользователь нажимает «Отметить выполненной». Задача оптимистично
   становится выполненной, кнопка меняет текст на «Сделать активной»,
   звучит haptic success. Повторное нажатие возвращает текст «Отметить
   выполненной» и снимает завершение.
3. Запрос завершения упал. Оптимистичное изменение откатывается,
   над кнопками появляется `Не удалось обновить задачу. Попробуйте ещё
   раз.`, звучит haptic error.
4. Пользователь нажимает «Удалить задачу». Снизу открывается модалка:
   «Вы точно хотите удалить задачу?». Для незавершённой задачи серии со
   сроком в будущем дополнительно показано предупреждение о будущих
   задачах серии. «Отмена», оверлей и Escape закрывают модалку без
   удаления.
5. Пользователь подтверждает удаление. `DELETE /tasks/{id}` выполняется,
   модалка закрывается, приложение возвращается на предыдущий экран по
   истории. Если истории нет — на `/tasks`.
6. Удаление упало не с `404`. Модалка остаётся открытой, показывает
   `Не удалось удалить задачу. Попробуйте ещё раз.`, звучит haptic error;
   повторное нажатие отправляет запрос снова.
7. Задача уже удалена на сервере (`404`). Это считается успешным
   удалением: кэш детали очищается, приложение возвращается назад.
8. Пользователь открыл `/tasks/:id` напрямую или обновил страницу.
   Пока идёт bootstrap/auth — скелетон; после авторизации — загрузка
   задачи. Если задачи нет — «Задача не найдена» и «Назад». Если сеть
   упала — «Не удалось загрузить задачу» и «Повторить».
9. Проекты или метки не загрузились. Экран не блокируется: проект
   показывается как «Без проекта», метки — по названиям из задачи с
   цветом-заглушкой `app-success`.
10. Пользователь возвращается из деталей системной кнопкой «Назад»
    Telegram или историей браузера. В Telegram показывается нативная
    `BackButton` (Bot API 6.1+); в браузере используется история.
11. SSR-ответ `/tasks/:id` не содержит защищённых данных задачи,
    проектов и меток — только скелетон загрузки.

## 3. Функциональные требования

### FR-1. Маршрут и навигация

- Добавить маршрут `tasks/:id` в `app/routes.ts` внутри
  `layout("routes/_app.tsx", [...])`, после `tasks/search`:
  - `route("tasks/search", "routes/task-search.tsx")`;
  - `route("tasks/:id", "routes/task-detail.tsx")`.
  Статический `tasks/search` имеет приоритет над динамическим `:id`.
- Route-модуль `app/routes/task-detail.tsx`:
  - `meta`: `title` — `Задача — Milly`, `description` —
    `Детали задачи в Milly` (публичный текст, без данных задачи);
  - без loader/action: защищённые данные загружаются React Query после
    `AuthGate`, как на `/tasks` и `/tasks/search`;
  - `id` читается через `useParams<{ id: string }>()`;
  - невалидный `id` (`Number.isSafeInteger(id) === false` или `id <= 0`)
    показывает состояние «Задача не найдена» без запроса.
- Нижняя навигация на `/tasks/:id`: активна вкладка «Задачи».
  Во всех четырёх фреймах активна «Главная» — это артефакт копирования
  фреймов, как и в спецификации `2026-11-06-today-tasks`; экран относится
  к разделу «Задачи». Вкладки «Главная»/«Задачи» работают через
  существующий `useBottomNavigation`; «Воркспейсы» не меняются.
- Возврат назад:
  - в Telegram показывается нативная `BackButton` (API 6.1+); по клику —
    `navigate(-1)`, если `shouldGoBack(window.history.state)`, иначе
    `navigate("/tasks")`;
  - `BackButton` скрывается при размонтировании экрана;
  - в браузере работает история браузера; отдельная видимая кнопка
    «Назад» в контент не добавляется, потому что её нет во фреймах;
  - после успешного удаления и при `404` используется та же логика
    возврата.
- Нижняя навигация остаётся видимой на экране деталей и на состояниях
  загрузки/ошибки. FAB добавления задачи не показывается.

### FR-2. Данные, API и кэш

- Добавить в `app/lib/tasks/tasks-api.ts`:
  - `fetchTask(taskId: number, signal?: AbortSignal): Promise<TaskResponse>`
    → `GET /tasks/{taskId}`;
  - `deleteTask(taskId: number, signal?: AbortSignal): Promise<void>`
    → `DELETE /tasks/{taskId}` (успех `204` возвращает `undefined`).
- Ключ детального запроса:
  `taskDetailQueryKey(taskId) = ["tasks", "detail", taskId] as const`.
  Префикс `["tasks"]` обязателен: существующие мутации инвалидируют
  `["tasks"]`, и детальный кэш должен обновляться вместе со списками.
- `useTaskDetail(taskId, enabled)`:
  - `useQuery({ queryKey: taskDetailQueryKey(taskId), queryFn: ({ signal }) =>
    fetchTask(taskId, signal), enabled })`.
- Проекты: `useQuery({ queryKey: ["projects"], queryFn: fetchProjects })`
  включается, когда задача загружена и `project_id !== null`.
- Метки: `useQuery({ queryKey: ["labels"], queryFn: fetchLabels })`
  включается, когда задача загружена и `labels.length > 0`. Цвета меток
  берутся из `GET /labels`; названия — из `task.labels`.
- Завершение задачи:
  - `completeTask(taskId)` при `completed_at === null`;
  - `uncompleteTask(taskId)` при `completed_at !== null`;
  - оптимистичное обновление детального кэша:
    `completed_at` и `updated_at` меняются сразу;
  - ошибка откатывает предыдущий снимок;
  - успех заменяет задачу ответом backend;
  - по завершении мутации инвалидируются `["tasks"]` и `["projects"]`.
- Удаление задачи:
  - `deleteTask(taskId)`;
  - успех: удалить `taskDetailQueryKey(taskId)` из кэша, инвалидировать
    `["tasks"]` и `["projects"]`, haptic success, вернуться назад;
  - `404`: считать удалением — очистить кэш, инвалидировать, haptic
    success, вернуться назад;
  - прочие ошибки: haptic error, модалка остаётся открытой, показывается
    inline-ошибка.
- Оптимистичного удаления нет: экран не должен уходить назад, пока
  сервер не подтвердил удаление (кроме `404`).

### FR-3. Заголовок и описание

- Заголовок задачи:
  - `24px`, Bold, `line-height: 29px`, `letter-spacing: -0.8px`,
    `app-text`, выравнивание влево, перенос по словам;
  - блок с отступами `15px` сверху, по бокам и снизу.
- Блок описания показывается, только если `description` не `null` и не
  пустой после `trim`:
  - заголовок `Описание` — `15px`, Semi Bold, `app-text`;
  - текст — `13px`, Regular, `line-height: 1.4`, `app-text-secondary`;
  - переносы строк пользователя сохраняются (`whitespace-pre-wrap`),
    длинные слова ломаются;
  - отступы `15px` по бокам и снизу, промежуток между заголовком и
    текстом `5px`.
- Между блоками заголовка и описания — `8px` (root gap контента).
- Если описания нет, блок не рендерится; заголовок сохраняет нижний
  отступ `15px`.

### FR-4. Карточка свойств

- Карточка: `app-card`, радиус `25px`, внутренние отступы `15px`,
  ширина контента (на экране `412px` — `380px`).
- Пять строк строго в порядке:
  1. `Срок`;
  2. `Напоминание`;
  3. `Приоритет`;
  4. `Теги`;
  5. `Проект`.
- Строка:
  - высота `47px`, без промежутков между строками;
  - разделитель `1px app-stroke` под каждой строкой, кроме последней;
  - ведущая иконка `18×18` цвета `app-text`, затем название `15px`
    Regular `app-text`, промежуток `5px`;
  - значение `13px` Regular, выровнено вправо, `truncate`, промежуток до
    значения `11px`;
  - шеврон `chevron-right.svg` `24×24` цвета `app-text-secondary`,
    декоративный (`aria-hidden`), потому что редактирование вне scope;
  - строки не являются кнопками и не фокусируются.
- Значения:
  - **Срок** — локальные дата и время задачи в часовом поясе
    пользователя: `Сегодня, HH:mm`, `Завтра, HH:mm`, иначе
    `На DD.MM.YYYY, HH:mm` (через существующий `formatDueChip`); цвет
    `app-accent`.
  - **Напоминание** — сводка по FR-5; цвет `app-text-secondary`.
  - **Приоритет** — подпись из `PRIORITY_OPTIONS` (`Срочные и важные`,
    `Важные, но не срочные`, `Срочные, но не важные`,
    `Не срочные и не важные`); цвет `app-text-secondary`.
  - **Теги** — см. FR-6; текст `app-text`.
  - **Проект** — см. FR-6; цвет `app-text-secondary`.
- Ведущие иконки: `calendar.svg`, `bell.svg` (новая), `flag.svg`,
  `tag.svg`, `folder.svg`.
- Если значение не помещается, оно обрезается многоточием; название
  строки остаётся видимым.
- Карточка не меняет высоту строк под длину контента: все строки
  `47px`, значение в одну строку.

### FR-5. Сводка напоминаний

- Новый чистый помощник в `app/lib/tasks/task-detail.ts`:
  `formatTaskReminderSummary(task)`.
- Если `reminders_enabled === false` или среди `reminders` нет
  `enabled === true` — `Нет`.
- Иначе берётся первое включённое правило в порядке ответа API:
  - `before_due` (`offset_minutes`):
    - `0` → `В момент срока`;
    - `1…59` → `За N минут(ы)` с русской плюрализацией;
    - `60…1439` и кратно `60` → `За N час(а/ов)`;
    - `>= 1440` и кратно `1440` → `За N день/дня/дней`;
    - иначе → `За N минут`;
    - если `offset_minutes` отсутствует → `До срока`;
  - `scheduled`:
    - `interval_days === 1` → `Каждый день в HH:mm`;
    - `interval_days >= 2` → `Каждые N день/дня/дней в HH:mm`
      с русской плюрализацией;
    - `time_of_day` обрезается до `HH:mm`;
  - если у правила нет обязательных полей — `По расписанию`.
- Если включённых правил больше одного, к сводке первого добавляется
  ` + N` (например, `За 30 минут + 1`).
- `next_run_at` не отображается.
- У завершённой задачи правила сохраняются, сводка показывается та же.

### FR-6. Метки и проект

- Метки:
  - название: первый элемент `task.labels`; если меток больше одной —
    `<name> + <count - 1>` (например, `Личное + 3`); при одной метке —
    только название;
  - иконка значения — `tag-raw.svg` `18×18`, цвет первой метки из
    `GET /labels` (совпадение по `id`); если метки нет в списке или
    запрос упал — `app-success`;
  - текст значения — `app-text`;
  - если меток нет — `Нет` цветом `app-text-secondary`, без цветной
    иконки значения;
  - ошибка загрузки меток не блокирует экран и не показывает отдельный
    retry: названия уже есть в `task.labels`.
- Проект:
  - если `project_id === null` — `Без проекта`;
  - если проект найден в `GET /projects?limit=100` — его `name`;
  - если проект не найден или запрос проектов упал — `Без проекта`
    (поведение как у `TodayTaskRow`);
  - цвет `app-text-secondary`.
- Ведущая иконка строки «Теги» — `tag.svg`; ведущая иконка строки
  «Проект» — `folder.svg`. `ProjectIconBadge` в карточке не
  используется: во фрейме значение проекта — текст без бейджа.

### FR-7. Дата создания и действия

- Под карточкой — строка `Создано DD.MM.YYYY, HH:mm`:
  - `created_at` в часовом поясе пользователя;
  - `13px`, Regular, `line-height: 1.4`, `app-text-secondary`;
  - отступ `15px` по бокам.
- Кнопки под строкой создания, с верхним отступом `15px`, промежутком
  `10px`, каждая на всю ширину:
  - «Отметить выполненной» / «Сделать активной»:
    - высота `50px`, радиус `25px`, фон `app-card`;
    - текст `15px`, Semi Bold, `app-accent`;
    - при `completed_at === null` — `Отметить выполненной`;
    - при `completed_at !== null` — `Сделать активной`;
  - «Удалить задачу»:
    - та же геометрия, текст `app-destructive`.
- Пока мутация завершения в полёте, кнопка завершения `disabled`,
  `aria-busy`, прозрачность `50`; повторное нажатие не отправляет запрос.
- Кнопка удаления disabled, пока завершение в полёте.
- Обе кнопки имеют focus-стили `outline-2` `app-accent` с
  отрицательным offset и `active:opacity-70`.
- Нажатия сопровождаются haptic selection; успех/ошибка мутации —
  `notification("success"|"error")`.
- Завершение не уводит со экрана: пользователь остаётся на деталях.
- Визуально завершённая задача в деталях не получает зачёркивания
  заголовка: во фреймах нет состояния «выполнено», а требование
  ограничено сменой текста кнопки.

### FR-8. Модалка удаления

- Открывается по кнопке «Удалить задачу»; состояние `isDeleteOpen`
  хранится в route-модуле.
- Используется существующий `Modal` (`variant="sheet"`), портал в
  `document.body`, оверлей `bg-black/40`, позиционирование снизу,
  ширина `max-w-md`, горизонтальные отступы `16px`, нижний отступ
  `max(15px, var(--app-inset-bottom))`.
- Две отдельные панели `app-card` с радиусом `25px` и промежутком
  `10px`:
  1. Панель подтверждения:
     - заголовок `Вы точно хотите удалить задачу?` — `15px`, Semi Bold,
       `app-text`, по центру;
     - предупреждение `При удалении регулярной задачи также удаляются и
       будущие задачи этой серии` — `13px`, Regular,
       `line-height: 1.4`, `app-text-secondary`, по центру;
     - предупреждение показывается только для задачи серии, которая
       будет удалена каскадно:
       `series_id !== null && completed_at === null && due_at > now`;
     - под текстовым блоком — разделитель `1px app-stroke`;
     - действие `Удалить задачу` — `15px`, Semi Bold,
       `app-destructive`, высота `50px`, по центру;
  2. Панель отмены:
     - `Отмена` — `15px`, Semi Bold, `app-accent`, высота `50px`,
       по центру.
- Оверлей, Escape и «Отмена» закрывают модалку, если удаление не в
  полёте.
- Пока удаление в полёте, обе кнопки disabled, `aria-busy`,
  прозрачность `50`; повторное нажатие не отправляет запрос.
- Ошибка удаления (кроме `404`) показывается внутри первой панели над
  действием: `Не удалось удалить задачу. Попробуйте ещё раз.`,
  `13px`, `app-destructive`, `role="alert"`; модалка остаётся открытой.
- При открытии/закрытии ошибка мутации сбрасывается.
- `Modal` получает `labelledBy` заголовка и `describedBy`
  предупреждения только когда оно показано.
- Начальный фокус — на «Отмена» (безопасное действие); после закрытия
  фокус возвращается на кнопку «Удалить задачу» (поведение `Modal`).
- Кнопка в макете «Удалить проект» — опечатка; используется
  «Удалить задачу».
- После успеха/`404`: закрыть модалку, haptic success, вернуться назад
  по FR-1.

### FR-9. Состояния загрузки и ошибок

- Скелетон `TaskDetailSkeleton`:
  - `role="status"`, `aria-busy="true"`,
    `aria-label="Загружаем задачу"`;
  - повторяет геометрию экрана: заголовок в 2 строки, блок описания,
    карточка из 5 строк `47px`, строка создания, две кнопки `50px`;
  - используется в route при `isPending` и в `RouteSkeleton` при
    bootstrap для пути `/tasks/:id`.
- `RouteSkeleton` определяет детальный путь как
  `pathname.startsWith("/tasks/") && !pathname.startsWith("/tasks/search")`
  и рендерит `TaskDetailSkeleton` вместо `TodayTasksSkeleton`.
- Ошибка загрузки без кэша:
  - `ApiError.status === 404` → карточка `Задача не найдена` с кнопкой
    `Назад`;
  - любая другая ошибка → карточка `Не удалось загрузить задачу` с
    кнопкой `Повторить` (вызывает `refetch`);
  - карточки используют `app-card`, радиус `25px`, `p-[15px]`,
    заголовок `17px` Semi Bold, кнопку `15px` Semi Bold `app-accent`,
    `role="alert"`.
- Если данные уже есть, а фоновый refetch упал — показываются данные,
  полноэкранная ошибка не заменяет экран (как на `/tasks`).
- Ошибка завершения — alert над кнопками:
  `Не удалось обновить задачу. Попробуйте ещё раз.`
  (`13px`, `app-destructive`, `role="alert"`).
- Ошибка удаления — внутри модалки по FR-8.
- Ошибки проектов/меток не блокируют экран; используются fallback’и
  FR-6.

### FR-10. Переход из списков задач

- `TodayTaskRow` получает необязательный проп
  `onOpen?: (task: TaskResponse) => void`.
- Если `onOpen` передан, контентная часть строки (название, проект,
  время, флаг, шеврон) рендерится кнопкой:
  - `type="button"`;
  - `aria-label="Открыть задачу: <title>"`;
  - `text-left`, focus-стили, `active:opacity-70`;
  - клик вызывает `onOpen(task)`.
- Чекбокс остаётся отдельной кнопкой `role="checkbox"` и не вложен в
  кнопку открытия. Разделитель и `self-stretch` сохраняются.
- Если `onOpen` не передан, контент остаётся `<div>` (обратная
  совместимость с существующими тестами и использованиями).
- `TodayTaskGroup`, `TodayTasksView` и `SearchResults` получают
  обязательный `onOpenTask` и прокидывают его в строки.
- В `routes/tasks.tsx` и `routes/task-search.tsx`:
  - `handleOpenTask(task)`: `haptics.selection()` и
    `navigate(`/tasks/${task.id}`)`;
  - обработчик передаётся в представление.
- Шеврон в строке становится визуальным индикатором перехода, но
  остаётся декоративной иконкой внутри кнопки.
- Клик по чекбоксу не открывает детали: это отдельная кнопка.

### FR-11. Темы, доступность и Telegram

- Только токены `app-*`; light/dark через `[data-app-theme]`, без
  `dark:` и хардкода цветов. Цвет метки — исключение: приходит из API
  (`label.color.hex`); fallback — `app-success`.
- Все интерактивные элементы — `button`/`a` с `type="button"`,
  доступным именем и focus-стилями.
- Декоративные иконки и шевроны — `aria-hidden="true"`.
- Модалка: focus trap, Escape, закрытие по оверлею, возврат фокуса —
  через существующий `Modal`.
- Safe-area учитывается `AppShell` и `BottomNavigationDock`; контент
  получает нижний отступ
  `calc(89px + max(0px, 30px - var(--app-inset-bottom)))`, чтобы
  последняя кнопка не уходила под навигацию.
- Экран прокручивается по вертикали; нижняя навигация фиксирована.
- Telegram `BackButton` показывается только при `supportsVersion("6.1",
  webApp)` и наличии `webApp.BackButton`; при размонтировании
  скрывается и снимает обработчик. `BackButton` не навигирует
  автоматически — навигацию выполняет наш обработчик.
- Haptics — только через `useTelegram().haptics`.

## 8. Принятые решения

1. **Отдельный маршрут, а не модалка.** Детали задачи — полноценный
   экран `/tasks/:id` под `_app`, потому что во фреймах есть нижняя
   навигация и Telegram-header, а не шторка.
2. **Доступ из обоих списков.** Строка `TodayTaskRow` открывает детали
   и на `/tasks`, и на `/tasks/search`; чекбокс остаётся отдельным
   действием. Это расширяет прежние спецификации, где строка была не
   кликабельной.
3. **Только чтение + два действия.** Строка «Изменить название и
   описание задачи» и интерактивные шевроны не реализуются, потому что
   редактирование вне scope; шевроны декоративные.
4. **Активная вкладка.** На деталях активна «Задачи», хотя на всех
   фреймах активна «Главная»; это тот же артефакт копирования, что и в
   спецификации `2026-11-06-today-tasks`.
5. **Возврат.** В Telegram используется нативная `BackButton`; в
   браузере — история. После удаления — `navigate(-1)` при наличии
   истории, иначе `/tasks`. Видимая кнопка «Назад» в контент не
   добавляется, потому что её нет во фреймах.
6. **Модалка удаления.** Используется существующий `Modal`
   (`variant="sheet"`) с двумя панелями, как в iOS action sheet; новый
   примитив не вводится.
7. **Текст кнопки в модалке.** «Удалить проект» из фреймов — опечатка;
   используется «Удалить задачу».
8. **Предупреждение о серии.** Показывается только когда backend
   каскадно удалит серию: `series_id !== null && completed_at === null &&
   due_at > now`. Для завершённой или просроченной задачи серии
   удаляется только задача, поэтому предупреждение не показывается.
9. **Приоритет.** Значение приоритета — `app-text-secondary`, а не
   красное, как в светлом фрейме: в тёмном фрейме оно серое, а красный
   в приложении означает destructive.
10. **Проект.** При отсутствии проекта или ошибке загрузки списка
    показывается «Без проекта» — как в `TodayTaskRow`.
11. **Метки.** Названия берутся из `task.labels` (они всегда есть в
    ответе), цвета — из `GET /labels`; ошибка цветов не блокирует
    экран, fallback — `app-success`.
12. **Напоминания.** Показывается первое включённое правило + `+ N`;
    `next_run_at` не показывается. Это компактная сводка, а не полный
    список правил.
13. **Завершение без перехода.** После завершения пользователь остаётся
    на деталях; меняется только текст кнопки. Зачёркивание заголовка не
    добавляется, потому что состояния «выполнено» во фреймах нет.
14. **Удаление без оптимизма.** Экран уходит назад только после
    успешного `DELETE` (или `404`), чтобы не показывать ложный успех.
15. **`404` при удалении — успех.** Задача уже отсутствует; повторное
    удаление не требуется, кэш очищается, пользователь возвращается.
16. **Кэш.** Детальный ключ находится под `["tasks"]`, поэтому
    существующие инвалидации списков и прогресса работают без
    специальных обходов.
17. **SSR.** Детальный route не использует loader; при SSR и bootstrap
    рендерится `TaskDetailSkeleton`, защищённые данные не утекают.
