## 1. Контекст и цель

Экран `/tasks/search` уже реализован: сегменты, заголовок, серверный поиск
по `q`, список задач на сегодня, оптимистичное завершение и dev-preview
`?state=filter`. Панель фильтров при этом остаётся визуальной заглушкой:
кнопки `disabled`, фильтры не передаются в `GET /tasks`, состояние
«активного фильтра» существует только в dev-preview.

Цель итерации — реализовать полный сценарий фильтрации по 14 фреймам Figma:

- единая шторка «Фильтры» со списком групп: «Проект», «Метки»,
  «Приоритет», «Статус», «Регулярность»;
- под-шторки групп с возвратом в «Все фильтры» и кнопкой
  «Применить»/«Готово»;
- отдельная шторка «Фильтр по дате», открываемая чипом календаря;
- черновик фильтров: под-шторка применяет изменения только в черновик,
  к списку они применяются по «Применить» в «Все фильтрах»;
- «Сбросить фильтры» под шторкой «Все фильтры» мгновенно сбрасывает
  применённые фильтры и закрывает шторку;
- серверные фильтры `date`, `project_ids`, `priorities`, `status`,
  `recurrence` и `q`; фильтр по меткам — клиентский, `AND`, по уже
  загруженной странице задач;
- активные состояния чипов и счётчик групп на кнопке «Все фильтры».

Backend не меняется. `GET /tasks` не поддерживает `label_ids`, поэтому
метки фильтруются на клиенте. Задачи с `project_id = null` через
`project_ids` не фильтруются, поэтому в фильтре проекта показываются
только реально созданные проекты, без строки «Без проекта».
Периодические серии (`recurrence=periodic`) отдельной опцией не
фильтруются: в Figma только «Ежедневные» и «Разовые».

## 2. Пользовательские сценарии

1. Пользователь нажимает кнопку-иконку «Все фильтры». Открывается
   шторка «Фильтры» с пятью группами. Активные группы подсвечены
   акцентом. Внизу — «Применить», под шторкой — «Сбросить фильтры».
2. Пользователь нажимает «Проект». Открывается под-шторка с поиском,
   списком реальных проектов и кнопкой «Применить».
   «Назад» возвращает в «Все фильтры», не применяя текущие правки;
   крестик, оверлей, Escape или свайп закрывают всю шторку без
   применения черновика.
3. Пользователь выбирает несколько проектов, нажимает «Применить» —
   возвращается в «Все фильтры», строка «Проект» становится акцентной.
   Затем нажимает «Применить» в «Все фильтрах» — шторка закрывается,
   список и заголовок `Задачи на DD.MM.YYYY (N)` обновляются; чип
   «Проект» на панели активен, на кнопке «Все фильтры» — бейдж с числом
   активных групп.
4. Пользователь открывает «Приоритет»: выбирает несколько приоритетов
   (мультивыбор), «Применить». Список фильтруется сервером по
   `priorities`.
5. Пользователь открывает «Статус»: выбирает «Выполненные» или
   «Не выполненные». Повторный тап по выбранной строке снимает фильтр.
   «Применить» фиксирует выбор в черновике.
6. Пользователь открывает «Регулярность»: выбирает «Ежедневные» или
   «Разовые». Повторный тап снимает фильтр. Периодические серии видны
   только без фильтра регулярности.
7. Пользователь открывает «Метки»: видит поиск, список меток с цветными
   иконками и названиями, мультивыбор. «Готово» фиксирует набор в
   черновике. После общего «Применить» показываются только задачи, где
   присутствуют все выбранные метки.
8. Пользователь нажимает чип-календарь. Открывается «Фильтр по дате» с
   текущей датой списка и подписью «Показать все задачи на DD.MM.YYYY».
   Выбор другой даты и «Готово» переводят список на выбранный день;
   заголовок показывает эту дату. Сброс фильтров возвращает на сегодня.
9. Пользователь нажимает «Сбросить фильтры»: все применённые фильтры
   очищаются, шторка закрывается, список возвращается к задачам на
   сегодня без фильтров, бейдж и активные чипы исчезают.
10. Пользователь открывает чип «По приоритету», «Проект» или
    «Периодичность» напрямую — открывается соответствующая под-шторка;
    «назад» из неё ведёт в «Все фильтры», «Применить» фиксирует правку
    в черновике и возвращает в «Все фильтры».
11. Метки загружаются с ошибкой: в под-шторке видно «Не удалось
    загрузить метки» и «Повторить»; выбор не теряется. Пустой список
    меток показывает существующий пустой текст.
12. В dev-режиме `?state=filter` по-прежнему показывает бейдж «1» и
    активный чип «Проект», не меняя фильтры и данные.
13. SSR-ответ `/tasks/search` не содержит защищённых данных задач,
    меток и проектов; шторки не рендерятся на сервере.

## 3. Функциональные требования

### FR-1. Модель фильтров и чистые помощники

- Новый модуль `app/lib/tasks/search-filters.ts`.
- Типы:
  - `SearchStatusFilter = "all" | "open" | "completed"`;
  - `SearchRecurrenceFilter = "all" | "regular" | "one_off"`;
  - `SearchTaskFilters { date: string | null; projectIds: number[];
    priorities: Priority[]; status: SearchStatusFilter;
    recurrence: SearchRecurrenceFilter; labelIds: number[] }`.
- `date = null` означает «сегодня»; конкретное значение — выбранный день.
  Активным фильтр даты считается только при `date !== null`.
- `createDefaultSearchFilters()` возвращает пустые массивы,
  `status: "all"`, `recurrence: "all"`, `date: null`.
- `resolveFilterDate(filters, today)` возвращает `filters.date ?? today`.
  `normalizeFilterDate(date, today)` возвращает `null`, если выбранная
  дата совпадает с `today`, иначе саму дату.
- Активность групп:
  - проект — `projectIds.length > 0`;
  - метки — `labelIds.length > 0`;
  - приоритет — `priorities.length > 0`;
  - статус — `status !== "all"`;
  - регулярность — `recurrence !== "all"`;
  - дата — `date !== null`.
- `countActiveFilterGroups(filters)` — сумма активных групп (0…6).
- `canonicalizeSearchFilters(filters)`:
  - удаляет дубликаты и сортирует `projectIds`, `labelIds` по
    возрастанию;
  - удаляет дубликаты и сортирует `priorities` лексикографически;
  - не меняет `date`, `status`, `recurrence`.
- `searchFiltersFingerprint(filters)` — стабильная строка без даты:
  `p:<ids>|pr:<priorities>|s:<status>|r:<recurrence>|l:<ids>`.
  Дата входит в query key отдельно.
- `toggleSelection<T>(values, value)` добавляет/удаляет значение,
  сохраняя порядок остальных.
- `toggleOptionalValue<T>(current, value)` возвращает `"all"`, если
  `current === value`, иначе `value`; используется статусом и
  регулярностью.
- `pruneMissingIds(selected, available)` удаляет отсутствующие и
  дублирующиеся id, сохраняя порядок.
- `matchesStatusFilter(task, status)`: `open` — `completed_at === null`,
  `completed` — не `null`, `all` — всегда `true`.
- `matchesLabelFilter(task, labelIds)`: при пустом `labelIds` — `true`;
  иначе у задачи должны быть **все** выбранные id (AND).
- `filterTasksForDisplay(tasks, filters)` применяет
  `matchesStatusFilter` и `matchesLabelFilter`, сохраняя порядок API.
  Статус применяется повторно на клиенте, чтобы оптимистичное
  завершение/возврат сразу убирало задачу из списка при активном
  статус-фильтре и откатывалось при ошибке.
- `formatProjectsFound(count)` возвращает «Найдено 1 проект»,
  «Найдено 2 проекта», «Найдено 5 проектов» по русским правилам
  множественного числа (`0`, `11–14`, `5–20` → «проектов»;
  `1`, `21`, `31` → «проект»; `2–4`, `22–24` → «проекта»).
- `STATUS_FILTER_OPTIONS`: «Выполненные» → `completed`,
  «Не выполненные» → `open`.
- `RECURRENCE_FILTER_OPTIONS`: «Ежедневные» → `regular`,
  «Разовые» → `one_off`.
- Помощники не обращаются к `window`/`document` и не зависят от React.

### FR-2. Точки входа и панель фильтров

- Кнопка-иконка «Все фильтры» разблокируется и открывает шаг `all`.
- Чипы «По приоритету», «Проект», «Периодичность» и иконка календаря
  разблокируются и открывают шаги `priority`, `project`, `recurrence`,
  `date` соответственно.
- Любое открытие начинается с черновика, равного применённым фильтрам,
  и сопровождается `haptics.selection()`.
- `OptionChip` при включённой кнопке сам выставляет
  `aria-haspopup="dialog"`; вручную ARIA не дублируется.
- `SearchFilterBar` получает:
  `activeFilterCount`, `activeDate`, `activePriority`, `activeProject`,
  `activeRecurrence`, `onOpenAll`, `onOpenDate`, `onOpenPriority`,
  `onOpenProject`, `onOpenRecurrence`.
- Активность чипов считается по применённым фильтрам:
  - «Все фильтры» — `activeFilterCount > 0`, бейдж `10×10` с числом;
  - дата — `date !== null`;
  - приоритет — `priorities.length > 0`;
  - проект — `projectIds.length > 0`;
  - периодичность — `recurrence !== "all"`.
- Текст чипов не меняется. Активный чип получает
  `border-app-accent text-app-accent` через существующий `OptionChip`.
- Доступное имя кнопки «Все фильтры»: «Все фильтры» или
  «Все фильтры, активно: N». Бейдж — `aria-hidden="true"`.

### FR-3. Шторка «Все фильтры»

- Заголовок «Фильтры»; слева места под back нет; справа крестик.
- Используется один `BottomSheet` с `expanded`, `showCloseButton`,
  `swipeToClose`, `panelAnimateLayout`, `bodyClassName="p-[15px]"`.
- Содержимое — `AllFiltersStep`, строки по порядку:
  1. «Проект» — `folder.svg`;
  2. «Метки» — `tag.svg`;
  3. «Приоритет» — `flag.svg`;
  4. «Статус» — `square-check.svg`;
  5. «Регулярность» — `repeat.svg`.
- Строка: кнопка высотой `47px`, gap `5px` между иконкой `18×18` и
  текстом `15px`, `chevron-right.svg` `24×24` справа цветом
  `app-text-secondary`, разделитель `1px app-stroke` снизу у всех,
  кроме последней. Между строками gap `15px`.
- Активная группа: текст и иконка `app-accent`; у кнопки доступное имя
  «`<Название>`, активно» (визуально скрытый суффикс или `aria-label`).
  Неактивная — `app-text`.
- Нажатие строки открывает соответствующий шаг; `aria-haspopup="dialog"`.
- Внизу панели, прижата через `mt-auto pt-[15px]`, кнопка
  `BottomSheetPrimaryAction` «Применить»; по нажатию применяет черновик
  к списку и закрывает шторку.
- В `footer` шторки (вне панели, ниже неё) — `BottomSheetAction` с
  `tone="destructive"` и текстом «Сбросить фильтры»; по нажатию
  мгновенно сбрасывает применённые фильтры и закрывает шторку. У
  `BottomSheetAction` появляется проп
  `tone?: "accent" | "destructive"` (по умолчанию `"accent"`), чтобы не
  смешивать `text-app-accent` и `text-app-destructive` в одном
  `className`.

### FR-4. Фильтр по проекту

- Заголовок «Фильтр по проекту», back слева, крестик справа.
- `SearchField` с `ariaLabel="Поиск проектов"` и placeholder «Поиск»;
  фильтрация без учёта регистра через `matchesSearchQuery`.
- Между поиском и содержимым — `mt-[15px]`, как в фильтре меток.
- Под поиском — строка статистики `13px/1.4`:
  - слева `formatProjectsFound(filteredProjects.length)` цветом
    `app-text-secondary`; считаются проекты после поиска;
  - справа кнопка «Сбросить» `13px` цветом `app-destructive`;
    показывается только при непустом выборе и очищает выбранные
    проекты.
- Список:
  - только реальные проекты — строки `50px`, `ProjectIconBadge`
    проекта и название `15px`, разделитель под каждой строкой, кроме
    последней;
  - строки «Без проекта» нет;
  - мультивыбор: `role="group" aria-label="Проекты"`, строки
    `role="checkbox"` и `aria-checked`.
- Круг выбора `20×20`: невыбран — `border-app-text-secondary/55`;
  выбран — `border-app-accent` и внутренняя точка `15×15`
  `bg-app-accent`.
- Состояния: «Загружаем проекты…» и «Не удалось загрузить проекты» +
  «Повторить» показываются над списком проектов; пустой результат
  поиска — «Ничего не найдено».
- «Применить» прижата внизу; фиксирует выбранные id в черновике и
  возвращает в «Все фильтры».
- Выбранные проекты уходят в `GET /tasks` как повторяемый
  `project_ids` (канонический порядок).
- Если загруженный список проектов не содержит выбранный id, id
  вычищается из черновика и применённых фильтров.

### FR-5. Фильтр по приоритету

- Заголовок «Фильтр по приоритету», back, крестик.
- Строки из `PRIORITY_OPTIONS` в существующем порядке, высота `50px`,
  без зазоров, разделитель под каждой, кроме последней.
- Мультивыбор: `role="group" aria-label="Приоритет задачи"`, строки
  `role="checkbox"`, круг выбора `20×20` слева, точка `15×15`.
- Повторный тап снимает/ставит приоритет.
- «Применить» фиксирует массив в черновике и возвращает в
  «Все фильтры».
- Выбранные приоритеты уходят в `GET /tasks` как повторяемый
  `priorities`.

### FR-6. Фильтр по статусу

- Заголовок «Фильтр по статусу», back, крестик.
- Строки: «Выполненные» (`completed`) и «Не выполненные» (`open`),
  высота `50px`, разделитель под первой.
- Одиночный выбор с возможностью снятия: `role="radiogroup"
  aria-label="Статус задачи"`, строки `role="radio"`; повторный тап по
  выбранной строке снимает фильтр (`status = "all"`).
- «Применить» пишет `status` в черновик и возвращает в «Все фильтры».
- Значение `all` означает отсутствие фильтра и уходит в API как
  `status=all` (существующее поведение).

### FR-7. Фильтр по регулярности

- Заголовок «Фильтр по регулярности», back, крестик.
- Строки: «Ежедневные» (`regular`) и «Разовые» (`one_off`), высота
  `50px`, разделитель под первой.
- Одиночный выбор с повторным тапом для снятия; `role="radiogroup"
  aria-label="Регулярность задачи"`, строки `role="radio"`.
- «Применить» пишет `recurrence` в черновик и возвращает в
  «Все фильтры».
- Опция «Периодические» не добавляется. Задачи периодических серий
  видны только при `recurrence="all"`.

### FR-8. Фильтр по меткам

- Заголовок «Метки» (как в Figma), back в «Все фильтры», крестик.
- `SearchField` с `ariaLabel="Поиск меток"`; фильтрация без учёта
  регистра.
- Список: gap `10px`, строки `50px`, мультивыбор
  `role="group" aria-label="Метки"`, строки `role="checkbox"`.
- Строка: круг выбора `20×20` слева, `tag-raw.svg` `18×18` цветом
  метки, название `15px` цветом `label.color.hex`, разделитель под
  строкой.
- Выбранные под поиском не теряются; отсутствующие в загруженном
  списке id вычищаются при применении и при загрузке данных.
- Состояния: «Загружаем метки…», «Не удалось загрузить метки» +
  «Повторить», «На текущий момент у вас не создано ни 1 метки»,
  «Ничего не найдено».
- «Готово» фиксирует массив `labelIds` в черновике и возвращает в
  «Все фильтры».
- Метки не уходят в API. После общего «Применить» список задач
  клиентски фильтруется через `filterTasksForDisplay` по AND: в задаче
  должны быть все выбранные метки.
- Количество в заголовке `Задачи на DD.MM.YYYY (N)` считается после
  клиентской фильтрации; `(0)` и пустое состояние показываются, если
  фильтр меток не дал совпадений.

### FR-9. Фильтр по дате

- Чип-календарь открывает шаг `date`; заголовок «Фильтр по дате»
  (в Figma заголовок внутреннего слоя — «Фильтр по дате и времени», но
  времени в шторке нет; это устаревший слой от быстрого создания).
- Содержимое: существующий `Calendar` без ограничения снизу по
  сегодняшнему дню (`minDate`/`maxDate` по умолчанию), значение —
  `filters.date ?? today`, `today` передаётся для `aria-current`.
- Под календарём `mt-[15px]`, текст `13px/1.4` цветом
  `app-text-secondary`: «Показать все задачи на DD.MM.YYYY»
  (`formatNumericDate`), обновляется при выборе даты. Это подпись, не
  ссылка.
- «Готово» прижата внизу; пишет в черновик
  `normalizeFilterDate(selectedDate, today)` — выбор сегодняшней даты
  означает отсутствие фильтра, другая дата — активный фильтр.
- `date` уходит в `GET /tasks`; заголовок результатов показывает
  выбранную дату. Сброс всех фильтров возвращает на сегодня.

### FR-10. Черновик, применение, возврат и закрытие

- Состояние шторки: `step: FiltersStep | null`, `draft`, `applied`,
  `openedDirectly`. `FiltersStep = "all" | "project" | "labels" |
  "priority" | "status" | "recurrence" | "date"`.
- Открытие при закрытой шторке: `draft = applied`, `openedDirectly = true`,
  затем `step`. Открытие под-шага из уже открытой шторки сохраняет
  текущий `draft` и ставит `openedDirectly = false`.
- «Применить»/«Готово» под-шага, открытого из «Все фильтры»:
  канонизированный патч попадает в `draft`, `step = "all"`. Шторка не
  закрывается и не пересоздаётся.
- «Применить»/«Готово» под-шага, открытого напрямую с чипа панели:
  канонизированный патч сразу попадает в `applied` и `draft`,
  `step = null`; шторка закрывается, список перезапрашивается.
- «Назад»: `step = "all"`; неприменённые изменения текущего шага
  отбрасываются, ранее применённые в `draft` под-фильтры сохраняются.
- Крестик, клик по оверлею, Escape и свайп вниз закрывают всю шторку;
  `draft` отбрасывается, к списку ничего не применяется.
- «Применить» в «Все фильтрах»: `applied = canonicalize(draft)`,
  `step = null`; изменение `applied` меняет query key и перезапрашивает
  список.
- «Сбросить фильтры»: `applied = default`, `draft = default`,
  `step = null` немедленно; список перезапрашивается без фильтров.
- Переходы между шагами — смена содержимого одной `BottomSheet`, без
  закрытия/открытия и без отдельных `Modal`.
- После закрытия фокус возвращается на элемент, открывший шторку, за
  счёт `Modal` (сохранение `document.activeElement`).

### FR-11. Данные, запросы и кэш

- `TaskListQuery` расширяется:
  `project_ids?: number[]`, `priorities?: Priority[]`,
  `recurrence?: TaskRecurrence | "all"`.
- `buildTaskListPath`:
  - `date` — как есть;
  - `project_ids` — повторяемый параметр через `append`, id по
    возрастанию;
  - `priorities` — повторяемый параметр через `append`, в
    каноническом порядке;
  - `status` — как есть;
  - `recurrence` — только если значение задано и не `"all"`;
  - `limit`, `cursor`, `q` — как сейчас; пустой `q` не отправляется.
- `buildSearchTaskListQuery(filters, today, query)` возвращает
  `TaskListQuery` с `limit: 100`, датой
  `resolveFilterDate(filters, today)`, `status = filters.status`,
  `project_ids = filters.projectIds`, `priorities = filters.priorities`,
  `recurrence = filters.recurrence`, `q` только для непустого
  `query.trim()`.
- `searchTasksQueryKey(timeZone, date, query, filters)`:
  `["tasks", "search", timeZone, date, query,
  searchFiltersFingerprint(filters)]`.
- `useSearchTasksData(timeZone, today, query, filters)` и
  `useToggleSearchTaskCompletion(timeZone, today, query, filters)`
  используют один и тот же ключ и `buildSearchTaskListQuery`.
- `placeholderData: keepPreviousData` сохраняется; при смене фильтров
  старый список остаётся до ответа.
- Проекты: существующий запрос `["projects"]` через `fetchProjects`.
- Метки: новый запрос `["labels"]` через `fetchLabels` на маршруте
  после `AuthGate`; ошибка не блокирует список задач, только шторку
  меток.
- Пагинация не реализуется: `limit=100`, `next_cursor` игнорируется.
- Отображение: `filterTasksForDisplay(results.items, applied)` перед
  `SearchResults`; количество и пустое состояние считаются по
  отфильтрованному массиву.
- Оптимистичное завершение/возврат работает по кэшу серверного ответа;
  при активном статус-фильтре строка исчезает/возвращается сразу
  благодаря `filterTasksForDisplay`, а `onSettled` инвалидирует
  `["tasks"]` и `["projects"]`.
- `next_cursor` сохраняется в оптимистичном обновлении (существующее
  поведение).

## 8. Принятые решения

- «Метки» открываются строкой в «Все фильтрах»; отдельного чипа на
  панели нет, чтобы не менять состав панели из макета.
- Под-шторки применяют изменения в черновик и возвращают в
  «Все фильтры»; к списку фильтры применяются только общим
  «Применить».
- «Сбросить фильтры» сбрасывает сразу и закрывает шторку — решение
  пользователя.
- Чипы открывают под-шторки напрямую; «назад» ведёт в «Все фильтры».
- Дата заменяет день списка, а не сужает выдачу поверх «всех дат»;
  по умолчанию сегодня, сброс возвращает на сегодня.
- `date = null` — «сегодня»; выбор сегодняшней даты нормализуется в
  `null`, поэтому фильтр даты не активен.
- Статус и регулярность — одиночный выбор с повторным тапом для
  снятия; опций «Все» и «Просроченные» нет, чтобы не расширять макет.
- Регулярность: только «Ежедневные» и «Разовые»; периодические серии
  отдельно не фильтруются.
- Проект фильтруется сервером через `project_ids`; в фильтре только
  реально созданные проекты. Задачи без проекта через `project_ids` не
  фильтруются, а строки «Без проекта» в фильтре нет, потому что backend
  не поддерживает фильтр задач без проекта.
- Метки фильтруются на клиенте по AND среди загруженных `limit=100`;
  серверный `label_ids` вне scope.
- Счётчик бейджа — число активных групп (0…6); чипы подсвечиваются по
  своим применённым фильтрам; дата активна при `date !== null`.
- Заголовок шторки даты — «Фильтр по дате»: времени в макете нет,
  внутренний слой «Фильтр по дате и времени» устарел.
- Заголовок шторки меток — «Метки» по Figma; кнопка — «Готово».
  В макете у этой шторки нет back, но по общему правилу под-фильтров
  добавляется back в «Все фильтры».
- «Найдено N проекта» считается по результатам поиска без «Без
  проекта»; склонение — по русским правилам.
- Одновременно живёт одна `BottomSheet`; переходы между шагами — смена
  содержимого, без вложенных `Modal`.
- Dev-preview остаётся визуальным и не участвует в модели фильтров.
- Фокус после закрытия возвращает `Modal`; отдельный focus-store не
  вводится.
