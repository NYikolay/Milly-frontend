# Milly — главный экран (SDD Specification)

**Статус:** draft for approval  
**Дата:** 2026-11-02  
**Область:** `frontend/`  
**Figma:** `20:4297` (Главная, light), `20:4484` (Главная, dark), `27:922` (Главное меню — отсутствие задач, light), `27:1166` (Главное меню — отсутствие задач, dark)

## 1. Контекст и цель

Нужно привести главный экран Milly в соответствие с четырьмя макетами Figma и подготовить экран к будущему подключению задач с backend. Сейчас backend/API задач отсутствует, поэтому данные для счётчика берутся из mock-источника через route loader. Контракт данных и место загрузки должны позволить позже заменить mock на реальный запрос без переписывания UI.

Главный экран — часть Telegram Mini App. Верхняя панель на макетах (закрыть, «Milly / мини-приложение», «...») — нативный header Telegram, а не часть React-разметки. Приложение не должно рисовать собственный header поверх него.

## 2. Пользовательские сценарии

1. Пользователь открывает Mini App и видит заголовок «Задачи на сегодня», текущую дату, прогресс дня, быстрый доступ и FAQ.
2. Если на сегодня задач нет, пользователь видит пустое состояние: «Задач на сегодня нет 😴», приглашение создать первую задачу и только два быстрых действия — «Голосом» и «Интерактивно».
3. Пользователь переключает тему Telegram — экран автоматически меняет палитру без перезагрузки.
4. Пользователь нажимает на карточку прогресса, быстрое действие, строку FAQ или вкладку нижнего меню — получает haptic-отклик. Переходы на другие экраны пока не выполняются.

## 3. Функциональные требования

### FR-1. Заголовок и дата

- Заголовок при наличии задач: `Задачи на сегодня`.
- Заголовок при отсутствии задач: `Задач на сегодня нет 😴`.
- Подзаголовок — текущая дата на русском языке, например `Четверг, 30 октября`.
- Дата вычисляется в loader и передаётся в компонент как готовая строка. Это исключает расхождение SSR/CSR и позволяет позже получать дату с backend.
- Заголовок — `h1`, дата — обычный текст.

### FR-2. Карточка прогресса дня

- Карточка содержит заголовок, подпись, chevron и шкалу прогресса; верхняя строка карточки кликабельна.
- Если `total > 0`:
  - заголовок: `Всё идёт по плану`;
  - подпись: `${completed} из ${total} задач выполнено`;
  - заполненная часть шкалы: `completed / total`, ограниченная диапазоном `0…100%`.
- Если `total === 0`:
  - заголовок: `Чем займёмся?`;
  - подпись: `Создайте первую задачу на сегодня`;
  - шкала показывает маркер `7px` цвета accent, как в макете, а не математически рассчитанный процент.
- `completed` ограничивается диапазоном `0…total`; при `total === 0` значение считается `0`.
- Верхняя строка карточки имеет семантику `button`; шкала имеет семантику `progressbar` и не вкладывается в `button`.

### FR-3. Быстрый доступ

- Секция всегда содержит заголовок `Быстрый доступ`.
- Если `total > 0`, показываются три карточки:
  1. `Голосом` — `Опишите словами задачу, мы добавим её в ваш список дел`;
  2. `Интерактивно` — `Заполните форму для добавления задачи`;
  3. `Поиск задач` — `Ищите, фильтруйте и сортируйте ваши задачи`.
- Если `total === 0`, показываются только первые две карточки. Карточка «Поиск задач» отсутствует, как в макетах пустого состояния.
- Каждая карточка — кнопка с haptic-откликом; навигация пока не выполняется.

### FR-4. FAQ

- Секция всегда содержит заголовок `FAQ`.
- В карточке две кликабельные строки:
  1. `Milly` — `Изучите возможности приложения`;
  2. `Экспорт данных` — `Выгрузка данных в удобный формат`.
- Иконки: `Logo.svg` и `excel_logo.svg` из `app/assets/icons/`.
- Между строками — разделитель, начинающийся после иконки (не на всю ширину карточки).
- Строки — кнопки с haptic-откликом; навигация пока не выполняется.

### FR-5. Нижнее меню

- Сохраняется текущая вёрстка `BottomNavigation`: glass-панель, высота 65 px, скругление, 4 вкладки, активная вкладка «Главная».
- Меняется только источник иконок: используются `home.svg`, `tasks.svg`, `card.svg`, `coop.svg` из `app/assets/icons/`.
- Иконки должны окрашиваться в цвет активной/неактивной вкладки, включая синий `#007AFF` для активной.
- Логика выбора вкладки и haptic-отклик сохраняются.

## 4. Данные и состояния

### 4.1. Контракт

```ts
interface DailyTasksSummary {
  total: number;
  completed: number;
}
```

- `total >= 0`.
- `completed` нормализуется в `0…total`.
- Пустое состояние определяется только по `total === 0`.
- В loader также возвращается `dateLabel: string`.

### 4.2. Mock и preview

- По умолчанию mock возвращает `{ total: 6, completed: 2 }` — это состояние «Главная».
- Для проверки пустого состояния поддерживается query-параметр `?state=empty`: loader возвращает `{ total: 0, completed: 0 }`.
- Любое другое значение `state` игнорируется.
- `?state=empty` — preview-механизм на время отсутствия backend; после подключения API его можно удалить, не меняя компоненты. Проверка `state` выполняется до запроса `summary`, чтобы preview не зависел от будущего API.
- После подключения backend loader должен вернуть ту же форму данных; UI не должен знать, откуда пришли числа.

## 5. Визуальная спецификация

### 5.1. Палитра

Цвета из присланной палитры заводятся в Tailwind-токены `app-*`. В `:root` — light, в `:root[data-app-theme="dark"]` — dark.

| Токен | Light | Dark | Назначение |
|---|---|---|---|
| `app-bg` | `#F2F2F7` | `#171717` | фон экрана |
| `app-card` | `#FFFFFF` | `#212121` | карточки, FAQ |
| `app-text` | `#303033` | `#FFFFFF` | основной текст |
| `app-text-secondary` | `#7A7D83` | `#7A7D83` | подписи, дата, заголовки секций |
| `app-hint` | `#A2ACB0` | `#A2ACB0` | вспомогательный/приглушённый текст |
| `app-stroke` | `#E9E9EE` | `#303033` | разделители, обводки |
| `app-accent` | `#007AFF` | `#007AFF` | прогресс, активная вкладка |
| `app-accent-soft` | `#EAF3FF` | `#31373F` | мягкий фон иконки микрофона |
| `app-track` | `#F2F2F7` | `#303033` | трек прогресса |
| `app-destructive` | `#E53935` | `#E53935` | destructive-цвет |
| `app-success` | `#31D158` | `#32E55E` | success-цвет |

Примечания:

- `secondary_text_color` из палитры (`#7A7D83`) используется для даты, подписей карточек и заголовков секций.
- `hint_color` (`#A2ACB0`) заводится отдельным токеном и не подменяет `secondary_text_color`.
- Существующие `tg-*` токены и glass-стили нижнего меню не удаляются.

### 5.2. Сетка и отступы

- Контент ограничен `max-w-md` (текущий `AppShell`).
- Боковой отступ контента — `15px`.
- Вертикальный gap между крупными блоками — `8px`.
- Заголовки секций имеют дополнительный отступ `15px` слева.
- Карточки занимают всю ширину контента; внутри — padding `15px`.
- На экране 412 px карточки визуально close to Figma (380 px), допускается 382 px из-за требования 15 px.
- Сетка быстрого доступа: 2 колонки, горизонтальный gap `10px`, вертикальный gap `8px`, карточки растягиваются по высоте; третья карточка занимает половину ширины во втором ряду.
- На узких экранах (320 px) карточки не должны обрезать текст: высота карточек может увеличиваться, контент переносится.

### 5.3. Типографика

| Элемент | Размер / вес | Line-height | Цвет |
|---|---|---|---|
| Заголовок экрана | 24 px / 700, tracking `-0.8px` | auto | `app-text` |
| Дата | 13 px / 400 | 1.4 | `app-text-secondary` |
| Заголовок секции | 15 px / 600 | 18 px | `app-text-secondary` |
| Заголовок карточки прогресса | 17 px / 600 | 1.4 | `app-text` |
| Подпись прогресса | 13 px / 400 | 1.4 | `app-text-secondary` |
| Заголовок быстрой карточки | 15 px / 600 | 18 px | `app-text` |
| Описание быстрой карточки | 12 px / 400 | 1.4 | `app-text-secondary` |

| Описание FAQ-строки | 13 px / 400 | 1.4 | `app-text-secondary` |

Шрифт — Inter (уже подключён в `root.tsx`).

### 5.4. Карточка прогресса

- Радиус `25px`, padding `15px`, внутренний gap `10px`.
- Верхняя строка — `button`: текст слева, chevron `24px` справа. Шкала находится вне кнопки, чтобы `progressbar` не терял семантику внутри `button`.
- Внутри текстового блока gap `3px`.
- Шкала: высота `4px`, радиус `4px`, фон `app-track`, заполнение `app-accent`.
- Размер карточки в макете: `380 × 89px`; высота складывается из `15 + 45 + 10 + 4 + 15`.
- Chevron приглушённый (`app-text-secondary`).

### 5.5. Карточка быстрого доступа

- Радиус `25px`, padding `15px`, внутренний gap `10px`.
- Размер в макете: `185 × 165px`; минимальная высота — `165px`.
- Иконка: контейнер `50 × 50px`.
- Для «Голосом»: мягкий круг `app-accent-soft`, внутри — синий круг микрофона из `micro.svg`; визуально синий круг `40 × 40px` с тенью.
- Для «Интерактивно»: emoji `📝` в контейнере `50 × 50px`.
- Для «Поиск задач»: emoji `🔍` в контейнере `50 × 50px`.
- Текст центрирован; заголовок и описание разделены gap `5px`.

### 5.6. FAQ-карточка

- Радиус `25px`, padding `15px`, фон `app-card`.
- В макете: `380 × 164px`; строка — `67px`.
- Иконка `35 × 35px`, gap до текста `12px`.
- Текстовая часть: заголовок и описание с gap `6px`.
- Chevron `24px` справа, цвет `app-text-secondary`.
- Разделитель `1px` цвета `app-stroke` между строками, начинается после иконки.
- Иконки `Logo.svg` и `excel_logo.svg` не перекрашиваются.

### 5.7. Нижнее меню

- Внешний вид и геометрия сохраняются по текущей реализации.
- Иконки `24 × 24px`; для `coop.svg` допускается контейнер `24 × 28px`, чтобы сохранить пропорции исходника.
- Активная иконка и подпись — `app-accent` / `app-tab-accent`; неактивные — `app-tab-inactive`.
- Иконки монохромные SVG из ассетов; для перекраски используется CSS mask + `currentColor`.

## 6. Темы и Telegram

- Активная тема определяется `Telegram.WebApp.colorScheme` через существующий `TelegramProvider`.
- Провайдер выставляет `data-app-theme="light|dark"`; CSS-переменные переключаются без участия компонентов экрана.
- Вне Telegram (браузер) сохраняется fallback по `prefers-color-scheme`.
- Верхний нативный header Telegram не рендерится приложением.
- Безопасные зоны применяет `AppShell`; фиксированные отступы под чёлку/навигацию не добавляются.
- Нижнее меню зафиксировано поверх контента (`position: fixed`) у нижней границы экрана и остаётся видимым при скролле; отступ снизу учитывает нижнюю безопасную зону, контент имеет запас снизу, чтобы меню его не перекрывало.

## 7. Доступность

- Кнопки имеют `type="button"` и доступные названия; декоративные иконки — `aria-hidden`.
- Шкала прогресса имеет `role="progressbar"`, `aria-valuemin`, `aria-valuemax`, `aria-valuenow` и не вложена в `button`.
- Заголовок экрана — `h1`, заголовки секций — `h2`.
- Изображения-иконки с декоративным смыслом имеют пустой `alt`.
- Фокус и tap-target не меньше текущих размеров кнопок.

## 8. Нефункциональные требования

- SSR сохраняется; loader используется для данных.
- Нет доступа к `window`/`document` на верхнем уровне модулей.
- Нет новых зависимостей.
- TypeScript strict, без `any`.
- Внешний вид адаптивен от 320 до `max-w-md`.
- Тестовый фреймворк и линтер в проекте отсутствуют; новые инструменты в рамках этой задачи не добавляются.

## 9. Вне scope

- Реальный API задач, авторизация и backend-валидация.
- Экраны голосового ввода, интерактивного создания, поиска, FAQ и экспорта.
- Навигация по нижним вкладкам, кроме активной «Главная».
- Анимации, skeleton/loading-состояния, обработка сетевых ошибок.
- Настройка тестового фреймворка и линтера.
- Изменение нативного Telegram header.

- [ ] Экран по умолчанию соответствует `20:4297` / `20:4484`: title, дата, прогресс 2/6, три карточки быстрого доступа, FAQ.
- [ ] `?state=empty` соответствует `27:922` / `27:1166`: пустой заголовок, «Чем займёмся?», две карточки быстрого доступа, FAQ, маркер прогресса 7 px.
- [ ] Светлая и тёмная темы используют палитру из раздела 5.1 и переключаются по Telegram.
- [ ] Самодельный header (аватар, grid, настройки) отсутствует.
- [ ] Нижнее меню сохраняет вёрстку, но использует `home.svg`, `tasks.svg`, `card.svg`, `coop.svg`.
- [ ] Все кнопки дают haptic-отклик и не ведут на несуществующие маршруты.
- [ ] `npm run typecheck` и `npm run build` проходят.
- [ ] SSR-ответ содержит заголовок, дату и контент; `?state=empty` содержит пустое состояние.
- [ ] Экран не ломается на 320 px и не растягивается шире `max-w-md`.

## 11. Принятые решения

- SDD-документы лежат в `docs/specs/2026-11-02-home-dashboard/`.
- Оба состояния доступны через mock loader + `?state=empty`.
- Нативный header Telegram не дублируется в React.
- Кнопки быстрого доступа и FAQ пока работают как placeholder + haptics.
- Фактические иконки лежат в `app/assets/icons/` (не в `public/assets/icons/`); используем их.
- При расхождении «16 px в Figma» и «15 px в задании» приоритет у 15 px для боковых отступов контента; нижнее меню сохраняет текущие 16 px.
