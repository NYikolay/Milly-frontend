## 1. Контекст и цель

В `2026-11-08-task-detail` строка «Проект» карточки свойств была
неинтерактивной, а изменение проекта — вне scope. В
`2026-11-07-quick-add-label-project-figma` уже реализованы список
проектов из `GET /projects?limit=100`, бейдж проекта с цветом из backend
и белой иконкой, а также выбор «Без проекта». Теперь по фреймам Figma
реализуется отдельная страница выбора проекта задачи.

Страница открывается из строки «Проект» на `/tasks/:id` и позволяет
выбрать активный проект или «Без проекта». Выбор сразу применяется через
`PATCH /tasks/{id}` с `project_id` и возвращает пользователя на
`/tasks/:id`; отдельной кнопки сохранения нет. Новых серверных контрактов
не требуется: `PATCH /tasks/{id}` уже принимает `project_id`, включая
явный `null` для очистки.

## 2. Пользовательские сценарии

1. Пользователь открывает `/tasks/:id`, нажимает строку «Проект».
   Открывается `/tasks/:id/project`: заголовок «Выбор проекта»,
   подсказка «Выберите к какому проекту привязать задачу», карточка с
   «Без проекта» и активными проектами из backend, отметка текущего
   проекта и пояснение «Это позволит вам группировать и фильтровать
   свои задачи».
2. Пользователь выбирает другой проект. Сразу отправляется
   `PATCH /tasks/{id}` с `{ "project_id": <id> }`, приложение
   возвращается назад на `/tasks/:id`, где проект обновляется
   оптимистично; после ответа кэш деталей и проектов ревалидируется.
3. Пользователь выбирает «Без проекта». Если у задачи был проект,
   отправляется `PATCH /tasks/{id}` с `{ "project_id": null }`, и
   приложение возвращается на `/tasks/:id`; детали показывают
   «Без проекта».
4. Пользователь выбирает уже установленный проект или «Без проекта»,
   когда проекта нет. Запрос не отправляется, приложение просто
   возвращается назад: состояние не изменилось.
5. Проекты ещё загружаются. Страница уже показывает заголовок, подсказку,
   строку «Без проекта» и сообщение «Загружаем проекты…»; «Без проекта»
   можно выбрать сразу.
6. Проекты не загрузились. «Без проекта» остаётся доступной, под списком
   видны «Не удалось загрузить проекты» и «Повторить».
7. `PATCH` завершился ошибкой. Пользователь уже вернулся на детали;
   оптимистичное значение откатывается, звучит error haptic и
   показывается toast «Не удалось изменить проект. Попробуйте ещё раз.».
   При `404` дополнительно инвалидируются детали и `["projects"]`, чтобы
   перечитать задачу и список проектов; toast тоже показывается.
8. Пользователь возвращается системной кнопкой Telegram или историей
   браузера, не выбирая вариант. Проект не меняется.
9. Пользователь открыл `/tasks/:id/project` напрямую или обновил
   страницу. Пока идёт bootstrap/auth — скелетон; после авторизации —
   загрузка задачи. Невалидный `id` — «Задача не найдена» без запросов;
   `404` задачи — «Задача не найдена»; другая ошибка — «Не удалось
   загрузить задачу» и «Повторить».
10. SSR-ответ `/tasks/:id/project` не содержит защищённых данных задачи
    и проектов; только скелетон.

## 3. Функциональные требования

### FR-1. Маршрут и навигация

- Добавить маршрут `tasks/:id/project` в `app/routes.ts` внутри
  `layout("routes/_app.tsx", [...])` после `tasks/:id/priority`:
  - `route("tasks/:id/project", "routes/task-project.tsx")`.
- Route-модуль `app/routes/task-project.tsx`:
  - `meta`: `title` — `Проект — Milly`, `description` —
    `Изменение проекта задачи в Milly`;
  - без loader/action: данные загружаются React Query после `AuthGate`;
  - `id` читается через `useParams<{ id: string }>()`;
  - невалидный `id` (`Number.isSafeInteger(id) === false` или `id <= 0`)
    показывает «Задача не найдена» без запросов;
  - `useTaskDetail(taskId, isValidId)` — тот же ключ
    `["tasks","detail",taskId]`, что и на деталях;
  - `useQuery({ ...projectsQueryOptions, enabled: isValidId })` —
    существующий ключ `["projects"]`; задача и проекты загружаются
    параллельно.
- Нижняя навигация: активна вкладка «Задачи» (в Figma активна
  «Главная» — артефакт копирования фреймов, как в других экранах задач).
  FAB добавления задачи не показывается.
- Возврат назад:
  - в Telegram показывается нативная `BackButton` (Bot API 6.1+,
    `useTelegramBackButton`);
  - `navigate(-1)`, если `shouldGoBack(window.history.state)`; иначе
    `/tasks/{taskId}`, а для невалидного `id` — `/tasks`;
  - `BackButton` скрывается при размонтировании;
  - отдельная видимая кнопка «Назад» в контент не добавляется.
- Экран прокручивается вертикально; нижняя навигация фиксирована.

### FR-2. Данные, API и кэш

- `TaskUpdateInput` в `app/lib/tasks/types.ts` расширяется:
  - `project_id?: number | null`.
- Чистый помощник `applyTaskDetailProject(task, projectId)` в
  `app/lib/tasks/task-detail-cache.ts`:
  - возвращает исходную задачу, если данных нет или `project_id` не
    изменился;
  - иначе возвращает копию с новым `project_id` (включая `null`).
- Мутация `useUpdateTaskProject(taskId)` в
  `app/hooks/use-update-task-project.ts`:
  - `mutationFn: (projectId: number | null) =>
    updateTask(taskId, { project_id: projectId })`;
  - перед запросом оптимистично обновляется детальный кэш:
    `project_id` задачи меняется сразу, снимок сохраняется для отката;
  - `onMutate` отменяет текущие запросы детального ключа;
  - ошибка (любой статус): снимок возвращается, error haptic, toast
    «Не удалось изменить проект. Попробуйте ещё раз.»;
  - ошибка `404`: дополнительно инвалидируются детальный ключ и
    `["projects"]`; toast не подавляется, потому что `404` от PATCH
    может означать как отсутствие задачи/серии, так и отсутствие или
    недоступность выбранного проекта;
  - успех: если `updated.id === taskId`, детальный кэш заменяется
    ответом backend; success haptic;
  - `onSettled`: инвалидация `["tasks","detail",taskId]`, `["tasks"]`,
    `["task-series"]`, `["projects"]`; проекты инвалидируются, потому
    что смена проекта меняет прогресс старого и нового проекта;
  - ответ PATCH может представлять другой экземпляр серии, поэтому
    детальный ключ всегда инвалидируется, а не только перезаписывается.
- Запросы идут через существующие `updateTask` / `apiRequest`.
- Явный `null` сохраняется в теле запроса: `requestJson` сериализует
  `{ project_id: null }` через `JSON.stringify`, а не отбрасывает поле.

### FR-3. Заголовок и подсказка

- Контент страницы: тот же каркас, что у деталей и приоритета:
  `flex flex-1 flex-col gap-2 px-4` с
  `paddingBottom: CONTENT_BOTTOM_PADDING`.
- Блок заголовка: `px-[15px] py-[15px]`, `h1` `24px`, Bold,
  `line-height: 29px`, `letter-spacing: -0.8px`, `app-text`,
  перенос по словам, текст «Выбор проекта».
- Подсказка под заголовком: `px-[15px]`, `13px`, Regular,
  `line-height: 1.4`, `app-text-secondary`, текст
  «Выберите к какому проекту привязать задачу».
- Между блоками — `8px` (root `gap-2`).

### FR-4. Карточка выбора проекта

- Карточка: `app-card`, радиус `25px`, внутренние отступы `15px`,
  `role="radiogroup"` с `aria-label="Проект"`.
- Строки строго в порядке:
  1. «Без проекта» — всегда первая, значение `null`;
  2. активные проекты из `GET /projects?limit=100` в порядке backend
     (`lower(name)`, затем `id`); архивные проекты не показываются,
     потому что `fetchProjects` запрашивает без `include_archived`.
- Строка:
  - высота `47px`, ширина на всю карточку;
  - `button` с `type="button"`, `role="radio"`,
    `aria-checked={row.id === task.project_id}`;
  - ведущая ячейка `24×24`, в выбранной строке — иконка `check.svg`
    цвета `app-accent`, в невыбранной — пустое место того же размера;
  - затем `ProjectIconBadge` `28×28`: для реального проекта — фон
    `project.color.hex` из backend и белая иконка
    `getProjectIcon(project.icon)`; для «Без проекта» — `NO_PROJECT_ICON`,
    `bg-app-track` и `app-text` без inline-фона;
  - промежуток между отметкой и бейджем `11px`, между бейджем и текстом
    `5px`;
  - текст `15px`, `line-height: 1.3`, `app-text`, `truncate`;
  - разделитель `1px app-stroke` под текстовой частью каждой строки,
    кроме последней (как в Figma: линия начинается после отметки);
  - focus-стили `outline-2` `app-accent` с отрицательным offset и
    `active:opacity-70`.
- Нажатие на строку:
  - haptic selection;
  - если `project_id` отличается — вызывает `onSelect(projectId)`
    (мутация + возврат назад по FR-1);
  - если совпадает — возврат назад без `PATCH`.
- Pending-состояние не показывается: после выбора сразу выполняется
  переход назад.
- Завершённая задача тоже может менять проект: отдельного запрета нет.
- Если текущий проект задачи в список не попал (например, проект
  заархивирован), ни одна строка не отмечена; «Без проекта» остаётся
  доступной.

### FR-5. Пояснение под карточкой

- Под карточкой — текст `px-[15px]`, `13px`, Regular,
  `line-height: 1.4`, `app-text-secondary`:
  «Это позволит вам группировать и фильтровать свои задачи».
- Перенос строк естественный; блок не является ссылкой и не
  интерактивен.

### FR-6. Состояния загрузки и ошибок

- `TaskProjectSkeleton`:
  - `role="status"`, `aria-busy="true"`,
    `aria-label="Загружаем проект"`;
  - повторяет геометрию: заголовок в 1–2 строки, подсказка, карточка
    `265px` (пять строк по `47px` плюс отступы `15px`), блок пояснения
    в 2–3 строки.
- Route при `isPending` задачи показывает скелетон; при ошибке без
  кэша — существующий `TaskDetailError`:
  - `404` → «Задача не найдена» с «Назад»;
  - прочее → «Не удалось загрузить задачу» с «Повторить» (`refetch`).
- Если данные задачи уже есть, фоновый refetch не скрывает экран.
- Пока проекты загружаются (`projectsQuery.isPending`), страница
  показывает «Без проекта» и сообщение «Загружаем проекты…»; выбранный
  проект станет виден после загрузки.
- Ошибка проектов: «Не удалось загрузить проекты» и кнопка «Повторить»
  (`projectsQuery.refetch`); «Без проекта» остаётся доступной. Если в
  кэше уже есть проекты, список продолжает отображаться и остаётся
  доступным, а ошибка показывается под ним.
- `RouteSkeleton` определяет путь
  `/^\/tasks\/[^/]+\/project\/?$/` и рендерит `TaskProjectSkeleton`
  вместо `TaskDetailSkeleton`.
- Ошибки `PATCH` не блокируют переход назад и показываются toast’ом.

### FR-7. Строка «Проект» на деталях

- `TaskDetailCard` получает необязательный проп
  `onProjectClick?: () => void`.
- Если обработчик передан, строка «Проект» рендерится кнопкой с
  `aria-label="Изменить проект"`; без обработчика остаётся
  неинтерактивной, как раньше.
- `TaskDetailView` получает и пробрасывает `onProjectClick`.
- В `routes/task-detail.tsx` обработчик вызывает
  `haptics.selection()` и `navigate("/tasks/{task.id}/project")`.
- Остальные строки карточки не становятся интерактивными.
- Значение проекта в карточке остаётся текстом без `ProjectIconBadge`.

### FR-8. Темы, доступность и Telegram

- Только токены `app-*`; light/dark через `data-app-theme`, без `dark:`
  и хардкода цветов. Единственное исключение — inline
  `backgroundColor` бейджа из `project.color.hex`, существующий паттерн
  `ProjectIconBadge`.
- Все интерактивные элементы — `button` с `type="button"`, доступным
  именем и focus-стилями.
- `role="radiogroup"` / `role="radio"` и `aria-checked` отражают выбор.
- Safe-area учитывается `AppShell`; контент получает нижний отступ
  `CONTENT_BOTTOM_PADDING`.
- Haptics — только через `useTelegram().haptics`:
  `selection()` на возврате/выборе, `notification("success"|"error")`
  по результату `PATCH`.
- Ширины `320 / 412 / 448px`, light/dark и safe-area не ломаются;
  бейдж `28×28` помещается в строку `47px`.

  странице приоритета.
- Поля поиска проектов, как в шторке быстрого создания, нет: во фреймах
  его нет, список прокручивается вместе со страницей.
- Активная вкладка «Главная» в Figma заменяется на «Задачи» — тот же

  напоминаний, срока и приоритета.
- В Figma первая строка отмечена галочкой как пример; в приложении
  отмечается фактический `task.project_id`.
- Toast ошибки и оптимистичное обновление в Figma отсутствуют:
  добавлены как необходимое поведение мгновенного выбора и возврата.
- Архивные проекты в списке не показываются: backend по умолчанию
  отдаёт только активные, а назначить архивный проект нельзя (`400`).

## 5. Нефункциональные требования

- TypeScript strict, без `any`; типы — через `import type`.
- Новые зависимости не добавляются; используется существующий
  `sonner` toast через `AppToaster`.
- Все API-запросы — через `apiRequest` / `updateTask`; `fetch` в
  компонентах не используется.
- SSR включён; защищённые данные задачи и проектов не попадают в
  SSR-ответ. `useQuery` выполняется только после `AuthGate`.
- Обращений к `window`/`document` на верхнем уровне модулей нет.
- Файлы — `kebab-case`, компоненты — `PascalCase`, алиас `~/*`.
- Линтер не настроен; `npm run lint` не добавлять.
- Тесты — Vitest, среда `node`, без jsdom.

## 8. Принятые решения

1. **Отдельная страница, а не шторка.** Во фреймах — полноэкранный
   макет с нижней навигацией и Telegram-хедером, как у приоритета и
   напоминаний. Страница живёт на `/tasks/:id/project`.
2. **Мгновенный выбор без кнопки сохранения.** Нажатие на строку —
   это и есть подтверждение; кнопки «Применить»/«Готово» нет.
3. **Оптимистичное обновление + немедленный возврат.** Пользователь не
   ждёт сеть на экране выбора: детальный кэш обновляется сразу, переход
   выполняется в том же обработчике, ответ сервера затем ревалидирует
   кэш.
4. **Ошибка после возврата — toast для любого статуса.** Для проекта
   `404` неоднозначен: backend возвращает его и для отсутствующей
   задачи/серии, и для отсутствующего/чужого проекта. Поэтому toast
   показывается всегда, а при `404` дополнительно инвалидируются
   детали и проекты; если задача действительно удалена, экран деталей
   сам покажет «Задача не найдена».
5. **Текущий выбор не отправляется.** Если выбран тот же проект или
   тот же «Без проекта», `PATCH` не нужен; выполняется только возврат.
6. **«Без проекта» очищает через явный `null`.** Отсутствие поля
   означает «не менять», поэтому для очистки отправляется
   `{ project_id: null }`.
7. **Бейдж вместо контурной иконки.** Используется существующий
   `ProjectIconBadge`, чтобы цвет и иконка проекта совпадали с
   быстрым созданием, поиском и строками задач.
8. **Кэш.** Детальный ключ остаётся под `["tasks"]`; после успеха
   инвалидируются `["tasks"]`, `["task-series"]` и `["projects"]`,
   потому что смена проекта меняет прогресс старого и нового проекта,
   а PATCH экземпляра активной серии применяется к серии и будущим
   экземплярам.
9. **Только активные проекты.** Список берётся из существующего
   `fetchProjects` (`/projects?limit=100` без `include_archived`);
   архивные проекты не показываются и не назначаются.
