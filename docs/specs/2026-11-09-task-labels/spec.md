> тёмный считается артефактом копирования. В Figma активно
> «Главная» — тот же артефакт копирования, что и в остальных фреймах задач;
> в приложении активна вкладка «Задачи».

## 1. Контекст и цель

В `2026-11-08-task-detail` строка «Теги» карточки свойств была
неинтерактивной, а изменение меток — вне scope. В
`2026-11-07-quick-add-label-project-figma` уже реализованы список меток из
`GET /labels`, цвета из backend (`label.color.hex`), мультивыбор с
ограничением 100 меток и общий `SearchField`. Backend уже принимает
`label_ids` в `PATCH /tasks/{id}`: это полная замена набора, `[]` очищает,
`null`/отсутствие поля не меняет набор.

Теперь по четырём фреймам Figma реализуется отдельная страница
`/tasks/:id/labels` («Выбор меток задачи»). Она открывается из строки
«Метки» на `/tasks/:id` и позволяет выбрать несколько меток. Каждое
нажатие на метку сразу сохраняется через `PATCH /tasks/{id}` с полным
набором `label_ids`; пользователь остаётся на странице и может продолжить
выбор, а назад возвращается системной кнопкой Telegram или историей
браузера. Отдельной кнопки «Готово» в макетах нет, поэтому используется
автосохранение, как у экрана напоминаний.

Кнопка «Создать метку» на странице присутствует визуально, но создание
меток в этой итерации не реализуется: нажатие ничего не делает.

## 2. Пользовательские сценарии

1. Пользователь открывает `/tasks/:id`, нажимает строку «Метки».
   Открывается `/tasks/:id/labels`: заголовок «Выбор меток задачи»,
   подзаголовок «Выберите или создайте метки для текущей задачи»,
   кнопка «Создать метку», карточка меток с отмеченными текущими метками
   задачи и пояснение «Это позволит вам группировать и фильтровать свои
   задачи».
2. Пользователь нажимает невыбранную метку. Кружок сразу становится
   залитым, отправляется `PATCH /tasks/{id}` с `label_ids`, содержащим
   полный новый набор, и приложение остаётся на странице. Метка в
   детальном кэше задачи обновляется оптимистично.
3. Пользователь нажимает выбранную метку. Она снимается, отправляется
   `PATCH` с оставшимся набором. Если это была последняя метка,
   отправляется `label_ids: []`.
4. Пользователь быстро нажимает несколько меток подряд. Запросы
   сериализуются; на сервер уходят полные наборы в порядке нажатий, а
   итоговое состояние соответствует финальному выбору.
5. Пользователь вводит запрос в поле «Поиск». Список фильтруется по
   названию метки без учёта регистра. Уже выбранные метки, скрытые
   фильтром, остаются выбранными.
6. Пользователь нажимает «Создать метку». Ничего не происходит: запроса,
   перехода, toast и haptic нет.
7. Метки ещё загружаются. Показываются заголовок, подзаголовок, кнопка
   «Создать метку», сообщение «Загружаем метки…» и пояснение; поля поиска
   и карточки нет. Кнопка создания доступна.
8. Метки не загрузились. Показываются заголовок, подзаголовок, кнопка
   «Создать метку», «Не удалось загрузить метки», «Повторить» и
   пояснение. Если в кэше уже есть метки, список продолжает
   отображаться, а ошибка показывается под ним.
9. У пользователя нет ни одной метки. Показываются заголовок, подзаголовок
   «На данный момент у вас отсутствуют какие-либо метки, но вы можете
   создать первую прямо сейчас.», кнопка «Создать метку» и пояснение;
   карточки и поиска нет.
10. `PATCH` завершился ошибкой. Оптимистичное изменение откатывается,
    звучит error haptic и показывается toast «Не удалось изменить метки.
    Попробуйте ещё раз.». При `404` дополнительно инвалидируются детали
    задачи и `["labels"]`. Пользователь остаётся на странице.
11. Пользователь возвращается системной кнопкой Telegram или историей
    браузера. Выбор уже сохранён; на `/tasks/:id` значение «Метки»
    показывает актуальный набор.
12. Пользователь открыл `/tasks/:id/labels` напрямую или обновил
    страницу. Пока идёт bootstrap/auth — скелетон; после авторизации —
    загрузка задачи. Невалидный `id` — «Задача не найдена» без запросов;
    `404` задачи — «Задача не найдена»; другая ошибка — «Не удалось
    загрузить задачу» и «Повторить».
13. SSR-ответ `/tasks/:id/labels` не содержит защищённых данных задачи и
    меток; только скелетон.

## 3. Функциональные требования

### FR-1. Маршрут и навигация

- Добавить маршрут `tasks/:id/labels` в `app/routes.ts` внутри
  `layout("routes/_app.tsx", [...])` после `tasks/:id/project`:
  - `route("tasks/:id/labels", "routes/task-labels.tsx")`.
- Route-модуль `app/routes/task-labels.tsx`:
  - `meta`: `title` — `Метки — Milly`, `description` —
    `Изменение меток задачи в Milly`;
  - без loader/action: данные загружаются React Query после `AuthGate`;
  - `id` читается через `useParams<{ id: string }>()`;
  - невалидный `id` (`Number.isSafeInteger(id) === false` или `id <= 0`)
    показывает «Задача не найдена» без запросов;
  - `useTaskDetail(taskId, isValidId)` — ключ
    `["tasks","detail",taskId]`;
  - `useQuery({ ...labelsQueryOptions, enabled: isValidId })` —
    существующий ключ `["labels"]`; задача и метки загружаются
    параллельно.
- Нижняя навигация: активна вкладка «Задачи» (в Figma активна
  «Главная» — артефакт копирования). FAB добавления задачи не
  показывается.
- Возврат назад:
  - в Telegram показывается нативная `BackButton` (Bot API 6.1+,
    `useTelegramBackButton`);
  - `navigate(-1)`, если `shouldGoBack(window.history.state)`; иначе
    `/tasks/{taskId}`, а для невалидного `id` — `/tasks`;
  - `BackButton` скрывается при размонтировании;
  - отдельная видимая кнопка «Назад» в контент не добавляется.
- Экран прокручивается вертикально; нижняя навигация фиксирована.

### FR-2. Данные, API и кэш

- `TaskUpdateInput` в `app/lib/tasks/types.ts` расширяется:
  - `label_ids?: number[]`.
- Чистый помощник `applyTaskDetailLabels(task, labels)` в
  `app/lib/tasks/task-detail-cache.ts`:
  - `labels` — `readonly LabelRef[]`;
  - возвращает исходную задачу, если данных нет или набор совпадает по
    `id` и `name` в том же порядке;
  - иначе возвращает копию с новым массивом `labels`.
- Вход мутации `TaskLabelsUpdateInput`:
  - `labelIds: number[]` — полный новый набор для `PATCH`;
  - `labels: LabelRef[]` — тот же набор в виде ссылок для оптимистичного
    кэша.
- Мутация `useUpdateTaskLabels(taskId)` в
  `app/hooks/use-update-task-labels.ts`:
  - `scope: { id: "task-labels" }`: быстрые нажатия сериализуются,
    PATCH-запросы уходят в порядке нажатий;
  - `mutationFn` отправляет
    `updateTask(taskId, { label_ids: labelIds })`;
  - перед запросом оптимистично обновляется детальный кэш: `labels`
    задачи заменяются на `labels` из входа, снимок сохраняется для
    отката; `onMutate` отменяет текущие запросы детального ключа;
  - ошибка (любой статус): снимок возвращается, error haptic, toast
    «Не удалось изменить метки. Попробуйте ещё раз.»;
  - ошибка `404`: дополнительно инвалидируются детальный ключ и
    `["labels"]`; toast не подавляется, потому что `404` от PATCH может
    означать как отсутствие задачи, так и удалённую/недоступную метку;
  - успех: если `updated.id === taskId`, детальный кэш заменяется
    ответом backend; success haptic;
  - `onSettled`: инвалидация `["tasks","detail",taskId]`, `["tasks"]` и
    `["task-series"]`; `["labels"]` при успехе не инвалидируется, потому
    что список меток не меняется;
  - ответ PATCH может представлять другой экземпляр серии, поэтому
    детальный ключ всегда инвалидируется.
- Запросы идут через существующие `updateTask` / `apiRequest`.
- Пустой набор сохраняется явно: при снятии последней метки отправляется
  `{ label_ids: [] }`; поле не опускается.
- Максимум меток — 100 (ограничение backend). Если выбрано 100 меток,
  нажатие на невыбранную метку игнорируется без запроса и без toast.
- Новый набор формируется из `task.labels` и нажатой метки; порядок
  `label_ids` и оптимистичного `labels` — порядок `GET /labels`
  (`lower(name)`, затем `id`). Дубликаты меток по `id` отбрасываются.

### FR-3. Заголовок, подзаголовок, кнопка создания и пояснение

- Контент страницы: тот же каркас, что у деталей, приоритета и проекта:
  `flex flex-1 flex-col gap-2 px-4` с
  `paddingBottom: CONTENT_BOTTOM_PADDING`.
- Блок заголовка: `px-[15px] py-[15px]`, `h1` `24px`, Bold,
  `line-height: 29px`, `letter-spacing: -0.8px`, `app-text`,
  перенос по словам, текст «Выбор меток задачи».
- Подзаголовок: `px-[15px]`, `13px`, Regular, `line-height: 1.4`,
  `app-text-secondary`:
  - если метки загружены и список пуст — «На данный момент у вас
    отсутствуют какие-либо метки, но вы можете создать первую прямо
    сейчас.»;
  - в остальных случаях — «Выберите или создайте метки для текущей
    задачи.».
- Кнопка «Создать метку»:
  - `button type="button"` на всю ширину, высота `50px`, радиус `25px`,
    фон `app-card`;
  - контент по центру, промежуток между иконкой и текстом `5px`;
  - ведущая иконка `tag-plus.svg` `18×18` цвета `app-accent`;
  - текст `15px`, Regular, `line-height: 1.3`, `app-accent`;
  - focus-стили `outline-2` `app-accent` с отрицательным offset и
    `active:opacity-70`;
  - кнопка кликабельна и фокусируема, но обработчика нет: нажатие не
    отправляет запрос, не переходит, не показывает toast и не вызывает
    haptic;
  - кнопка показывается всегда: при загрузке, ошибке, пустом списке и
    непустом списке.
- Пояснение: `px-[15px]`, `13px`, Regular, `line-height: 1.4`,
  `app-text-secondary`, текст «Это позволит вам группировать и
  фильтровать свои задачи». Показывается всегда, в том числе в пустом
  состоянии; в пустом состоянии идёт сразу после кнопки создания, без
  карточки.
- Между блоками — `8px` (root `gap-2`).

### FR-4. Поиск меток

- `SearchField` (`ariaLabel="Поиск меток"`, placeholder «Поиск»)
  показывается между кнопкой «Создать метку» и карточкой меток только
  когда есть хотя бы одна загруженная метка (включая закэшированный
  список при фоновом refetch или ошибке).
- Поле не показывается при начальной загрузке, начальной ошибке и пустом
  списке меток.
- Фильтрация — по `label.name` через существующий `matchesSearchQuery`
  (без учёта регистра и лишних пробелов).
- Фильтр только визуальный: он не меняет набор выбранных меток.
  Выбранные метки, скрытые фильтром, остаются выбранными и попадают в
  `PATCH`.
- Если запрос не пуст и среди загруженных меток нет совпадений,
  показывается «Ничего не найдено» вместо строк; карточка остаётся.
- Запрос хранится только в локальном состоянии компонента, не в URL, и
  сбрасывается при размонтировании.

### FR-5. Карточка меток

- Карточка: `app-card`, радиус `25px`, внутренние отступы `15px`,
  `role="group"` с `aria-label="Метки"`.
- Строки — метки из `GET /labels` в порядке backend (`lower(name)`, затем
  `id`), дубликаты по `id` отбрасываются.
- Между строками — `10px` (в Figma карточка с двумя строками `47px`
  имеет высоту `134px`: `15 + 47 + 10 + 47 + 15`).
- Строка:
  - высота `47px`, ширина на всю карточку;
  - `button` с `type="button"`, `role="checkbox"`,
    `aria-checked={selected}`;
  - ведущий индикатор выбора `20×20`, `aria-hidden`:
    - выбран: круг с рамкой `1px app-accent` и внутренним залитым
      кругом `15×15` цвета `app-accent`;
    - не выбран: круг с рамкой `1px app-text-secondary/55`, без
      внутренней заливки;
  - промежуток между индикатором и контентом `15px`;
  - контент `flex h-full min-w-0 flex-1 items-center gap-[5px]`:
    - иконка `tag-raw.svg` `18×18` цвета `label.color.hex`;
    - название `15px`, Regular, `line-height: 1.3`, цвет
      `label.color.hex`, `truncate`;
  - разделитель `1px app-stroke` под контентом каждой строки, кроме
    последней; линия начинается после индикатора выбора;
  - focus-стили `outline-2` `app-accent` с отрицательным offset и
    `active:opacity-70`.
- Нажатие на строку:
  - haptic selection;
  - переключает метку и вызывает мутацию (FR-6);
  - страница не закрывается и не переходит назад.
- Pending-состояние отдельно не показывается: выбор отражается
  оптимистично, без спиннера и без блокировки остальных строк.
- Завершённая задача тоже может менять метки: отдельного запрета нет.
- Если текущая метка задачи отсутствует в `GET /labels` (например,
  удалена), она не показывается и не отмечается; другие метки остаются
  доступными.

### FR-6. Переключение и автосохранение

- Текущий набор — `task.labels` из детального кэша.
- Нажатие на метку:
  - если метка уже выбрана — убирает её из набора;
  - если не выбрана и в наборе меньше 100 меток — добавляет;
  - если не выбрана и в наборе уже 100 — ничего не делает.
- Новый набор отправляется сразу:
  `PATCH /tasks/{id}` с `{ "label_ids": [...] }`, где массив — полный
  новый набор в порядке `GET /labels`.
- Оптимистично детальный кэш обновляется до ответа сервера; на
  `/tasks/:id` при возврате сразу виден новый набор и сводка «Метки».
- После успеха звучит success haptic; toast не показывается.
- После ошибки снимок кэша восстанавливается, звучит error haptic и
  показывается toast «Не удалось изменить метки. Попробуйте ещё раз.».
  При `404` дополнительно инвалидируются детали и `["labels"]`;
  пользователь остаётся на странице.
- Быстрые нажатия сериализуются через `scope: "task-labels"`; каждый
  PATCH отправляет актуальный на момент нажатия полный набор, поэтому
  финальное состояние сервера совпадает с финальным выбором.
- Отдельной кнопки сохранения, «Готово» или индикатора сохранения нет:
  каждое нажатие — самостоятельное сохранение.

### FR-7. Состояния загрузки, ошибок и пустого списка

- `TaskLabelsSkeleton`:
  - `role="status"`, `aria-busy="true"`,
    `aria-label="Загружаем метки"`;
  - повторяет геометрию: заголовок в 1–2 строки, подзаголовок,
    кнопка создания `50px`, поле поиска `45px`, карточка `134px`
    (две строки по `47px` плюс `10px` между ними и отступы `15px`),
    пояснение в 2–3 строки.
- Route при `isPending` задачи показывает скелетон; при ошибке без
  кэша — существующий `TaskDetailError`:
  - `404` → «Задача не найдена» с «Назад»;
  - прочее → «Не удалось загрузить задачу» с «Повторить» (`refetch`).
- Если данные задачи уже есть, фоновый refetch не скрывает экран.
- Начальная загрузка меток (`isPending` и нет данных):
  - под кнопкой создания показывается «Загружаем метки…»;
  - поля поиска и карточки нет;
  - кнопка создания и пояснение остаются.
- Начальная ошибка меток (ошибка и нет данных):
  - «Не удалось загрузить метки» и кнопка «Повторить»
    (`labelsQuery.refetch`);
  - поля поиска и карточки нет;
  - кнопка создания и пояснение остаются.
- Пустой список после загрузки:
  - подзаголовок про отсутствие меток;
  - поля поиска и карточки нет;
  - кнопка создания и пояснение остаются.
- Ошибка или фоновый refetch при уже загруженных метках:
  - список продолжает отображаться и остаётся доступным;
  - при ошибке под карточкой показываются «Не удалось загрузить метки»
    и «Повторить»;
  - при обновлении под карточкой показывается «Загружаем метки…».
- `RouteSkeleton` определяет путь
  `/^\/tasks\/[^/]+\/labels\/?$/` и рендерит `TaskLabelsSkeleton`
  вместо `TaskDetailSkeleton`.
- Ошибки `PATCH` не блокируют страницу и не скрывают список.

### FR-8. Строка «Метки» на деталях задачи

- В `TaskDetailCard` строка `Теги` переименовывается в `Метки`;
  ведущая иконка остаётся `tag.svg`.
- `TaskDetailCard` получает необязательный проп
  `onLabelsClick?: () => void`.
- Если обработчик передан, строка «Метки» рендерится кнопкой с
  `aria-label="Изменить метки"`; без обработчика остаётся
  неинтерактивной, как раньше.
- `TaskDetailView` получает и пробрасывает `onLabelsClick`.
- В `routes/task-detail.tsx` обработчик вызывает
  `haptics.selection()` и `navigate("/tasks/{task.id}/labels")`.
- Значение строки не меняется: первый элемент `task.labels`, при
  нескольких — `<name> + <count - 1>`, цветная иконка `tag-raw.svg`
  первой метки и fallback `app-success`; пустое значение — «Нет».
- Остальные строки карточки не меняются.

### FR-9. Темы, доступность и Telegram

- Только токены `app-*`; light/dark через `data-app-theme`, без `dark:`
  и хардкода цветов. Единственное исключение — inline-цвет метки из
  backend (`label.color.hex`).
- Все интерактивные элементы — `button` с `type="button"`, доступным
  именем и focus-стилями.
- Карточка — `role="group"` с `aria-label="Метки"`; строки —
  `role="checkbox"` с `aria-checked`, отражающим выбор.
- Индикатор выбора декоративный (`aria-hidden`); состояние доступно
  через `aria-checked`.
- Safe-area учитывается `AppShell`; контент получает нижний отступ
  `CONTENT_BOTTOM_PADDING`.
- Haptics — только через `useTelegram().haptics`:
  `selection()` при нажатии на метку и возврате,
  `notification("success"|"error")` по результату `PATCH`.
- Ширины `320 / 412 / 448px`, light/dark и safe-area не ломаются.

## 8. Принятые решения

1. **Отдельная страница, а не шторка.** Во фреймах — полноэкранный
   макет с нижней навигацией и Telegram-хедером, как у приоритета,
   проекта и напоминаний. Страница живёт на `/tasks/:id/labels`.
2. **Автосохранение на каждое нажатие.** Кнопки «Готово» в макетах нет,
   а меток можно выбрать несколько, поэтому страница не закрывается
   после выбора; каждый tap сразу отправляет полный набор. Это
   повторяет автосохранение напоминаний, а не мгновенный возврат
   приоритета/проекта.
3. **PATCH полной заменой.** `label_ids` — полная замена набора; снятие
   последней метки отправляет `[]`, потому что `null`/отсутствие поля
   означают «не менять».
4. **Сериализация мутаций.** `scope: "task-labels"` гарантирует порядок
   PATCH-запросов при быстрых нажатиях и корректный финальный набор.
5. **Оптимистичный кэш и откат.** Детальный кэш обновляется сразу,
   ошибка возвращает снимок; `onSettled` ревалидирует детали, списки
   задач и серии.
6. **Toast для любого статуса ошибки.** `404` от PATCH неоднозначен:
   это может быть отсутствующая задача или удалённая метка. Поэтому toast
   показывается всегда, а при `404` дополнительно инвалидируются детали
   и `["labels"]`.
7. **Кнопка создания — placeholder.** Она должна быть в UI по макету,
   но создание меток делается отдельной итерацией; обработчика нет.
8. **Поиск добавлен.** В макетах его нет, но по требованию задачи он
   нужен; фильтрация клиентская, как в шторке быстрого создания.
9. **Пустой подзаголовок из светлого фрейма.** Тёмный пустой фрейм
   содержит общий текст; выбран более информативный вариант.
10. **Лимит 100.** Backend не принимает больше 100 меток; лишнее
    нажатие игнорируется без запроса, как в быстром создании.
11. **Переименование строки деталей.** «Теги» → «Метки» для единой
    терминологии с заголовком страницы; значение и иконка не меняются.
12. **Семантика мультивыбора.** `role="group"` + `role="checkbox"` +
    `aria-checked`, а не `radiogroup`, потому что выбор
    множественный.
