## 1. Контекст и цель

В `2026-11-08-task-detail` строка «Напоминание» карточки свойств была
неинтерактивной, а редактирование напоминаний — вне scope. В
`2026-11-09-task-due-modal` строка «Срок» стала кнопкой и открывает
нижнюю шторку. Теперь по фреймам Figma реализуется отдельная страница
редактирования автоматических напоминаний задачи.

Страница открывается из строки «Напоминание» на `/tasks/:id` и позволяет:

- включить/выключить автонапоминания;
- настроить правило «До срока задачи» (за сколько минут/часов/дней
  напомнить);
- настроить правило «По расписанию» (каждый день / каждые 2, 3, 4 дня /
  каждую неделю и время);
- сохранять изменения автоматически, без кнопки «Готово».

Правила, значения по умолчанию, payload и ограничения повторяют
быстрое создание задачи на главном экране. Новых серверных контрактов не
требуется: `PATCH /tasks/{id}` принимает `reminders_enabled` и
`reminders` (полная замена правил).

## 2. Пользовательские сценарии

1. Пользователь открывает `/tasks/:id`, нажимает строку «Напоминание».
   Открывается `/tasks/:id/reminders`: заголовок «Автоматические
   напоминания», описание, карточка «Автонапоминания» и, если включено,
   настройки обеих правил.
2. Автонапоминания выключены. Видна подсказка «Включите автонапоминания
   для настройки.», блок «НАСТРОЙКИ» скрыт. Пользователь включает
   мастер-переключатель: настройки появляются, мастер сохраняется
   через `PATCH`.
3. У задачи не было правил. При включении автонапоминаний включается
   правило «До срока задачи» со значением `1 час`, правило «По
   расписанию» остаётся выключенным, и оба состояния сохраняются одним
   `PATCH`.
4. Пользователь меняет число «14» и единицу «Часов». Значение
   сохраняется автоматически; при потере фокуса/Enter отправляется
   актуальное значение.
5. Пользователь включает «По расписанию», выбирает «Каждые 3 дня» и
   время `09:00`. Каждое изменение сохраняется автоматически.
6. Пользователь выключает правило «По расписанию». Правило исчезает из
   `reminders`; если правило «До срока задачи» осталось включённым,
   автонапоминания продолжают работать.
7. Пользователь выключает последнее включённое правило. Мастер
   автоматически выключается, блок «НАСТРОЙКИ» скрывается, подсказка
   появляется снова.
8. Пользователь выключает мастер. Настройки скрываются, сервер
   получает `reminders_enabled: false`; правила на сервере сохраняются.
   При повторном включении мастера правила восстанавливаются.
9. Сохранение упало. На странице видна ошибка «Не удалось сохранить
   напоминания. Попробуйте ещё раз.» и кнопка «Повторить»; значения в
   форме не сбрасываются.
10. Пользователь возвращается назад системной кнопкой Telegram или
    историей браузера; страница деталей показывает обновлённую сводку
    напоминаний.
11. Пользователь открыл `/tasks/:id/reminders` напрямую. Пока идёт
    bootstrap/auth — скелетон; после авторизации — загрузка задачи.
    Невалидный `id` — «Задача не найдена» без запроса; `404` —
    «Задача не найдена»; другая ошибка — «Не удалось загрузить задачу»
    и «Повторить».
12. SSR-ответ `/tasks/:id/reminders` не содержит защищённых данных
    задачи; только скелетон.

## 3. Функциональные требования

### FR-1. Маршрут и навигация

- Добавить маршрут `tasks/:id/reminders` в `app/routes.ts` внутри
  `layout("routes/_app.tsx", [...])` после `tasks/:id`:
  - `route("tasks/:id/reminders", "routes/task-reminders.tsx")`.
- Route-модуль `app/routes/task-reminders.tsx`:
  - `meta`: `title` — `Напоминания — Milly`, `description` —
    `Автоматические напоминания задачи в Milly`;
  - без loader/action: данные загружаются React Query после `AuthGate`;
  - `id` читается через `useParams<{ id: string }>()`;
  - невалидный `id` (`Number.isSafeInteger(id) === false` или `id <= 0`)
    показывает «Задача не найдена» без запроса;
  - `useTaskDetail(taskId, isValidId)` — тот же ключ
    `["tasks","detail",taskId]`, что и на деталях.
- Нижняя навигация: активна вкладка «Задачи»; вкладки работают через
  `useBottomNavigation`. FAB добавления задачи не показывается.
- Возврат назад:
  - в Telegram показывается нативная `BackButton` (Bot API 6.1+,
    `useTelegramBackButton`);
  - `navigate(-1)`, если `shouldGoBack(window.history.state)`; иначе
    `/tasks/{taskId}`, а для невалидного `id` — `/tasks`;
  - `BackButton` скрывается при размонтировании;
  - отдельная видимая кнопка «Назад» в контент не добавляется.
- Экран прокручивается вертикально; нижняя навигация фиксирована.

### FR-2. Данные и API

- `TaskUpdateInput` в `app/lib/tasks/types.ts` расширяется:
  - `reminders_enabled?: boolean`;
  - `reminders?: ReminderInput[]`.
- Мутация `useUpdateTaskReminders(taskId)` в
  `app/hooks/use-update-task-reminders.ts`:
  - `mutationFn: (input: TaskUpdateInput) => updateTask(taskId, input)`;
  - мутации с одинаковым `scope: { id: "task-reminders" }` выполняются
    последовательно (React Query v5), чтобы быстрые изменения не
    применялись в обратном порядке;
  - успех: если `updated.id === taskId` — `setQueryData` детального
    ключа; инвалидация `["tasks","detail",taskId]`, `["tasks"]`,
    `["task-series"]`; haptics success не вызывается (автосохранение
    не должно звенеть на каждое изменение);
  - ошибка: haptics `notification("error")`; при `404` дополнительно
    инвалидируется детальный ключ (маршрут покажет «Задача не
    найдена»);
  - ошибка не откатывает локальные значения формы.
- Ответ PATCH может представлять другой экземпляр серии (как у срока):
  поэтому детальный ключ всегда инвалидируется, а не только
  перезаписывается.
- Запросы идут через существующий `updateTask` / `apiRequest`.

### FR-3. Заголовок, описание и каркас

- Контент страницы: тот же каркас, что у деталей:
  `flex flex-1 flex-col gap-2 px-4` с
  `paddingBottom: CONTENT_BOTTOM_PADDING`.
- Блок заголовка: `px-[15px] py-[15px]`, `h1` `24px`, Bold,
  `line-height: 29px`, `letter-spacing: -0.8px`, `app-text`,
  перенос по словам.
- Описание под заголовком: `px-[15px]`, `13px`, Regular,
  `line-height: 1.4`, `app-text-secondary`, текст
  `Milly напомнит о задаче в Telegram по заданным правилам.`
- Между блоками — `8px` (root `gap-2`).
- Ошибка сохранения показывается отдельным блоком `px-[15px]`:
  - текст `Не удалось сохранить напоминания. Попробуйте ещё раз.`,
    `13px`, `line-height: 1.4`, `app-destructive`, `role="alert"`;
  - кнопка «Повторить» — `15px`, Semi Bold, `app-accent`, focus-стили;
    повторяет последний `TaskUpdateInput`;
  - блок скрывается при следующей успешной попытке или новом
    изменении.

### FR-4. Мастер-переключатель «Автонапоминания»

- Карточка: `flex h-[58px] items-center justify-between gap-[30px]
  rounded-[25px] bg-app-card px-[15px]`.
- Подпись: `15px`, `line-height: 1.3`, `app-text`.
- `Switch` (48×28) — существующий примитив.
- Выключено: под карточкой подсказка
  `Включите автонапоминания для настройки.` — `px-[15px]`, `13px`,
  `line-height: 1.4`, `app-text-secondary`; блок «НАСТРОЙКИ» скрыт.
- Включено: подсказка не показывается, блок «НАСТРОЙКИ» виден.
- Сохранение:
  - выключение отправляет только `{ reminders_enabled: false }`;
    правила на сервере сохраняются;
  - включение отправляет `{ reminders_enabled: true, reminders: [...] }`
    с текущими правилами черновика;
  - включение при отсутствии включённых правил сначала включает правило
    «До срока задачи» со значением по умолчанию (`1 час`), затем
    отправляет мастер и правила.
- Значения скрытых правил остаются в локальном черновике: повторное
  включение мастера в рамках визита восстанавливает настройки.

### FR-5. Правило «До срока задачи»

- Видно только при включённых автонапоминаниях.
- Карточка: `flex flex-col gap-[15px] rounded-[25px] bg-app-card p-[15px]`.
- Шапка: `flex h-7 items-center justify-between gap-[30px]`; подпись
  `До срока задачи` — `15px`, `line-height: 1.3`, `app-text`;
  `Switch` с `-my-2`.
- При включённом правиле:
  - подпись `За сколько до завершения задачи напомнить` — `13px`,
    `line-height: 1.4`, `app-text-secondary`;
  - строка `flex items-start gap-[15px]`:
    - числовой input `114×48`, радиус `28px`, `bg-app-track`,
      по центру, `15px`, Semi Bold, `app-accent`, `inputMode="numeric"`;
    - `SelectField` «Часов» в контейнере `w-[215px]`; опции
      «Минут»/«Часов»/«Дней»;
  - при пустом/невалидном числе подпись `Укажите количество` —
    `13px`, `app-text-secondary`, план не сохраняется;
  - `aria-invalid="true"` на input при невалидном значении.
- Под карточкой: `Напоминание будет выслано в чат с Milly один раз до
  её завершения.` — `px-[15px]`, `13px`, `line-height: 1.4`,
  `app-text-secondary`.
- Выключение правила убирает его из `reminders`. Если это было
  последнее включённое правило — мастер автоматически выключается
  (FR-4), блок настроек скрывается.
- Значение по умолчанию: `1 час`. Существующий `offset_minutes`
  раскладывается на единицу:
  - кратно `1440` → дни;
  - иначе кратно `60` → часы;
  - иначе минуты;
  - `0` сохраняется как `0 минут` (напоминание в момент срока);
  - допустимый диапазон — `0…525600` минут; при переполнении значение
    ограничивается `525600`.

### FR-6. Правило «По расписанию»

- Видно только при включённых автонапоминаниях.
- Карточка и шапка — как в FR-5; подпись `По расписанию`.
- При включённом правиле строка `flex items-end gap-[15px]`:
  - колонка `w-[215px]`: подпись `Повторять` (`13px`,
    `app-text-secondary`) и `SelectField`;
  - колонка `w-[114px]`: подпись `Время` (`13px`) и `TimeInput`
    (`size="compact"`, `114×48`, `app-track`, синий текст).
- Опции периодичности: `1` — «Каждый день», `2` — «Каждые 2 дня»,
  `3` — «Каждые 3 дня», `4` — «Каждые 4 дня», `7` — «Каждую неделю».
  Если у существующего правила `interval_days` не входит в набор,
  добавляется дополнительная опция с русской плюрализацией
  («Каждые N дней») и сохраняется как есть.
- Время: `HH:mm` из `time_of_day` (секунды отбрасываются); пустое/
  невалидное время блокирует сохранение и показывает `Укажите время`.
- Под карточкой: `Напоминание по расписанию будет высылаться в чат с
  Milly каждый заданный промежуток времени.` — `13px`,
  `app-text-secondary`.
- Выключение правила убирает его из `reminders`; если это последнее
  включённое правило — мастер автоматически выключается.
- Значение по умолчанию: «Каждый день», `14:00`.

### FR-7. Автосохранение и payload

- Отдельной кнопки сохранения нет. Изменения сохраняются
  автоматически:
  - переключатели и `SelectField` — сразу;
  - числовой input — сразу при каждом валидном изменении;
  - `TimeInput` — сразу при валидном времени.
- Пока запрос выполняется, элементы не блокируются; мутации
  сериализуются через `scope`.
- Формирование правил повторяет быстрое создание:
  - выключенное правило не отправляется;
  - `before_due`: `kind: "before_due"`, `enabled: true`,
    `offset_minutes` (0…525600);
  - `scheduled`: `kind: "scheduled"`, `enabled: true`, `interval_days`,
    `time_of_day` в формате `HH:mm:00`;
  - если оба правила выключены — `reminders: []`, а мастер
    выключается (`reminders_enabled: false`);
  - при включённом мастере `reminders_enabled: true` отправляется
    вместе с `reminders` (полное желаемое состояние).
- Отправляется полное желаемое состояние; повторная отправка того же
  значения допустима и не считается ошибкой. Невалидное число или
  время не отправляется.
- Без оптимистичного обновления: до ответа показывается локальное
  состояние формы; успех обновляет кэш, ошибка показывается по FR-3.

### FR-8. Состояния загрузки и ошибок

- `TaskRemindersSkeleton`:
  - `role="status"`, `aria-busy="true"`,
    `aria-label="Загружаем напоминания"`;
  - повторяет геометрию: заголовок в 2 строки, описание в 2 строки,
    карточка `58px`, подсказка.
- Route при `isPending` показывает скелетон; при ошибке без кэша —
  существующий `TaskDetailError`:
  - `404` → «Задача не найдена» с «Назад»;
  - прочее → «Не удалось загрузить задачу» с «Повторить» (`refetch`).
- Если данные уже есть, фоновый refetch не скрывает экран.
- `RouteSkeleton` определяет путь
  `/^\/tasks\/[^/]+\/reminders$/` и рендерит `TaskRemindersSkeleton`
  вместо `TaskDetailSkeleton`.
- Ошибки `PATCH` не блокируют экран и не уводят со страницы.

### FR-9. Темы, доступность и Telegram

- Только токены `app-*`; light/dark через `data-app-theme`, без `dark:`
  и хардкода цветов.
- Все интерактивные элементы — `button`/`input` с `type`,
  доступным именем и focus-стилями.
- `Switch` — `role="switch"`, `aria-checked`; `SelectField` — listbox
  с `aria-label`; числовой input — `aria-label`
  «За сколько до завершения задачи напомнить»; время — `aria-label`
  «Время».
- Ошибка — `role="alert"`.
- Safe-area учитывается `AppShell`; контент получает нижний отступ
  `CONTENT_BOTTOM_PADDING`.
- Haptics — только через `useTelegram().haptics`:
  `selection()` на переключателях/выборе, `notification("error")` при
  ошибке сохранения.
- Ширины `320 / 412 / 448px`, light/dark и safe-area не ломаются.

## 8. Принятые решения

1. **Отдельная страница, а не шторка.** Во фреймах — полноэкранный
   макет с нижней навигацией и Telegram-хедером; контента больше, чем
   помещается в шторку. Страница живёт на `/tasks/:id/reminders`.
2. **Автосохранение.** Кнопки сохранения во фреймах нет; изменения
   уходят через `PATCH` сразу. Для чисел/времени сохраняется только
   валидное значение.
3. **Мастер отделён от правил.** Выключение мастера не удаляет
   правила, потому что backend поддерживает мастер-выключатель и
   повторное включение без потери настроек.
4. **Последнее правило выключает мастер.** Если оба правила
   выключены, автонапоминаний нет; мастер переходит в off, подсказка
   возвращается.
5. **Дефолт при включении без правил.** Включается «До срока задачи»
   `1 час` — как в быстром создании; «По расписанию» остаётся off.
6. **Ошибка с повтором.** В автосохранении нет кнопки «Готово»,
   поэтому ошибка сопровождается кнопкой «Повторить», повторяющей
   последний payload.
7. **Сериализация мутаций.** React Query `scope` гарантирует порядок
   PATCH-запросов при быстрых изменениях.
8. **Без success-haptic.** Иначе автосохранение звенит на каждый
   символ; success-haptic остаётся у срока и завершения.
9. **Кэш.** После успеха обновляется детальный ключ и
   инвалидируются `["tasks"]`/`["task-series"]`; проекты не
   затрагиваются, потому что напоминания не влияют на прогресс.
10. **Неизвестный интервал.** Существующее значение не теряется:
    добавляется опция «Каждые N дней», даже если её нет в макете.
11. **Текст ошибки.** «Не удалось сохранить напоминания. Попробуйте
    ещё раз.» — по аналогии с ошибками завершения/срока.
