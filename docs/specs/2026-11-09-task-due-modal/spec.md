# Изменение срока задачи (модалка «Дата и время задачи»)

**Дата:** 2026-11-09
**Figma:** Milly, фреймы `Изменение срока задачи Светлая тема`
(node `34:6719`, панель `54:13627`) и
`Изменение срока задачи. Тёмная тема` (node `34:7851`, панель `34:7949`).

## Цель

На экране деталей задачи (`/tasks/:id`) строка «Срок» открывает нижнюю
шторку, в которой можно изменить дату, время и ежедневную регулярность
задачи. Сохранение идёт через `PATCH /api/v1/tasks/{task_id}`; после успеха
обновляются детали, списки задач, проекты и серии.

## Триггер

- Строка «Срок» в карточке свойств `TaskDetailCard` становится кнопкой с
  `aria-label="Изменить срок"` и открывает шторку.
- Остальные строки карточки («Напоминание», «Приоритет», «Метки», «Проект»)
  имеют собственные экраны и не открывают шторку срока.
- Завершённая задача тоже может менять срок: отдельного запрета нет.

## Внешний вид

- `BottomSheet` с заголовком «Дата и время задачи», крестиком закрытия,
  `panelAnimateLayout` и `swipeToClose`; высота — по содержимому
  (`panelHeight="auto"`). Кнопки «Назад» в шапке нет: шторка одношаговая,
  в светлом фрейме стрелка — наследие общего макета шапки.
- Тело — `p-[15px]`, панель `bg-app-card`, радиус стандартный для
  `BottomSheet` (`25px`).
- Содержимое переиспользует `DueStep`:
  - `Calendar` (ПН…ВС, выбранная дата — синяя пилюля);
  - строка «Время» + `TimeInput` (`type="time"`, 114×44, `bg-app-track`,
    синий текст);
  - строка «Регулярная задача» + `Switch` (48×28);
  - подсказка через существующий `formatDueHint`:
    «Сегодня, 16:00», «На DD.MM.YYYY, HH:mm»,
    «С DD.MM.YYYY, ежедневно в HH:mm»;
  - кнопка «Готово» — 50px, радиус 25px, `bg-app-accent`, белый текст.
- Ошибка сохранения показывается над кнопкой: `role="alert"`,
  `text-app-destructive`, текст «Не удалось изменить срок. Попробуйте ещё раз.».
- Пока запрос выполняется, «Готово» disabled и `aria-busy="true"`.
- Только токены `app-*`, light/dark через `data-app-theme`, без `dark:` и
  хардкода цветов. Ширины 320/412/448 px и safe-area не ломаются.

## Начальные значения

- Дата и время — `task.due_at` в часовом поясе пользователя
  (`formatZonedDate`, `formatZonedTime`).
- Переключатель включён, если `task.recurrence !== "one_off"`
  (для `regular` и `periodic`).
- Просроченная дата подрезается до сегодняшнего дня — как в `DueStep`.
- Пустое/невалидное время блокирует «Готово» и показывает «Укажите время».

## Сохранение и API

`PATCH /api/v1/tasks/{task_id}` (`tasks-update_task`) с подмножеством:

```json
{ "due_at": "2026-11-09T13:00:00.000Z", "recurrence": "regular" }
```

Правила формирования тела:

- `due_at` вычисляется через `zonedDateTimeToIso(date, time, timeZone)`.
- `due_at` отправляется только если момент времени изменился (сравнение
  `Date.getTime()`, а не строк); это не пересоздаёт напоминания зря.
- `recurrence` отправляется только если состояние переключателя изменилось:
  - `one_off → on` → `"regular"` (ежедневная серия);
  - `regular/periodic → off` → `"one_off"` (разовая задача; backend удалит
    будущие незавершённые экземпляры серии);
  - `regular/periodic → on` без изменения → поле не отправляется;
  - `periodic` с включённым переключателем и изменением только даты/времени
    сохраняет интервал (поле `recurrence` не отправляется).
- Если ни `due_at`, ни `recurrence` не изменились, запрос не отправляется,
  шторка просто закрывается.
- `interval_days` не отправляется.

## Кэш и обратная связь

- После успеха: `setQueryData(["tasks","detail",updated.id])` (если id
  совпадает), инвалидация `["tasks","detail",taskId]`, `["tasks"]`,
  `["task-series"]`, `["projects"]`; haptics `success`; шторка закрывается.
- Ответ PATCH может представлять другой экземпляр серии; поэтому старый
  детальный ключ всегда инвалидируется, а не только перезаписывается.
- Ошибка: haptics `error`, текст над кнопкой, шторка остаётся открытой.
  При `404` дополнительно инвалидируется детальный ключ — маршрут сам
  покажет «Задача не найдена», если задача исчезла.
- Оптимистичного обновления нет: до ответа показывается pending-состояние.

## Тесты

- Чистые помощники `getTaskDueDraft` / `buildTaskDueUpdate` (включая
  сравнение моментов с разными offset и сохранение `periodic`).
- `updateTask` формирует `PATCH /tasks/{id}` и тело.
- Мутация инвалидирует нужные ключи, обновляет кэш деталей, отдаёт
  haptics и обрабатывает `404`.
- SSR-рендер `DueStep` (pending/error) и `TaskDueSheet`.
- Строка «Срок» — кнопка только при наличии обработчика.
- Маршрут: открытие/закрытие шторки, передача задачи и ошибки, вызов
  мутации, закрытие после успеха.

## Вне scope

- Изменение названия, описания, проекта, меток, приоритета и напоминаний.
- Периодические серии с интервалом > 1 дня в UI не создаются и не
  редактируются, только сохраняются как есть.
- Подтверждение при выключении регулярности (backend-предупреждение не
  показываем; поведение задокументировано).
