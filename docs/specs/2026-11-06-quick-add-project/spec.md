## 1. Контекст и цель

В inline-форме быстрого создания задачи можно указать срок, метки,
приоритет и автонапоминания, но нельзя выбрать проект. Backend уже
поддерживает `project_id` в `POST /tasks` и `POST /task-series`, а также
отдаёт список проектов через `GET /projects`.

Цель итерации — добавить выбор проекта в форму:

- чип проекта в строке чипов сразу после «Метки»;
- шторка «Проект» со списком активных проектов и пунктом
  «Без проекта»;
- передача выбранного `project_id` при создании задачи или серии;
- иконка проекта из `app/assets/icons/projects-icons/`, окрашенная в
  `project.color.hex`.

По умолчанию выбрано «Без проекта». Создание, редактирование и
архивация проектов остаются вне scope.

## 2. Пользовательские сценарии

1. Пользователь открывает главный экран. В строке чипов после «Метки»
   виден чип «Без проекта» с иконкой `no-project`. Задача создаётся без
   проекта.
2. Пользователь нажимает чип проекта. Открывается шторка «Проект»;
   первая строка «Без проекта» отмечена синей галочкой, ниже — активные
   проекты пользователя.
3. Пользователь выбирает проект и нажимает «Применить». Шторка
   закрывается, чип показывает иконку и название проекта, иконка
   окрашена цветом проекта. Фокус возвращается на чип.
4. Пользователь закрывает шторку без «Применить» (overlay, Escape,
   «назад», «Закрыть»). Выбор отбрасывается, чип и черновик остаются
   прежними.
5. Пользователь создаёт разовую задачу или ежедневную серию. В запрос
   уходит `project_id` выбранного проекта либо `null` для
   «Без проекта».
6. Проекты не загрузились. В шторке доступен «Без проекта», показан
   текст ошибки и кнопка «Повторить». Форму можно отправить без
   проекта.
7. Выбранный проект удалили или архивировали на сервере. Если проект
   удалён, создание возвращает `404`; если архивный — `400`. В обоих
   случаях список проектов обновляется. Если выбранного проекта нет в
   свежем списке, выбор сбрасывается на «Без проекта», черновик остаётся.
   При `404` также обновляется список меток.

## 3. Функциональные требования

### FR-1. Чип проекта

- Чип расположен в строке быстрых действий сразу после чипа «Метки» и
  перед чипом приоритета.
- Базовые стили — существующий `OptionChip`: высота `45px`, радиус
  `50px`, рамка `app-stroke`, фон `app-card`, текст `13px`, максимум
  `200px`, горизонтальное усечение.
- Проект не выбран:
  - иконка `no-project` размером `18×18`, цвет `app-text` через
    `currentColor`;
  - текст «Без проекта»;
  - `aria-label="Выбрать проект"`.
- Проект выбран:
  - иконка проекта размером `18×18`, цвет `project.color.hex`;
  - текст — `project.name`;
  - `aria-label="Проект: <name>"`.
- Чип не получает активный синий стиль — только иконка цветная.
- Чип имеет `aria-haspopup="dialog"`, открывает шаг «Проект».

### FR-2. Шторка «Проект»

- Заголовок — `Проект`. Кнопки «назад» и закрытия X в шапке нет;
  закрытие — overlay, Escape и нижняя кнопка «Закрыть».
- Первая строка списка — «Без проекта». Она показывается всегда, в том
  числе при загрузке, ошибке и пустом списке проектов.
- Ниже — активные проекты из `GET /projects` без архивных.
- Одиночный выбор. У выбранной строки слева синяя галочка `check.svg`
  размером `24×24`; у неостальных — невидимый спейсер `24×24`.
- Строка: высота `50px`, левая часть — индикатор, затем иконка проекта
  `18×18`, затем имя `15px` цветом `app-text`; между индикатором и
  контентом `15px`, между иконкой и именем `5px`.
- Иконка проекта окрашена в `project.color.hex`; у «Без проекта» —
  `app-text`.
- Разделитель `1px app-stroke` между строками; у последней строки
  нижней границы нет.
- Состояния загрузки и ошибки отображаются под строкой «Без проекта»
  в области списка проектов:
  - загрузка: `Загружаем проекты…`;
  - ошибка: `Не удалось загрузить проекты` и кнопка `Повторить`;
  - пустой список: дополнительный текст не показывается.
- Внизу шторки — кнопка `Применить` (`BottomSheetPrimaryAction`),
  высота `50px`, радиус `25px`, `app-accent`, белый текст.
- Выбор внутри шторки меняет только `stepDraft.projectId`. «Применить»
  коммитит значение в `draft`; закрытие без применения отбрасывает
  изменение — как в остальных шагах.
- Нажатие на строку вызывает `onChange(id | null)`, на «Применить» —
  `onApply(selectedId)`.

### FR-3. Данные и API

- `GET /api/v1/projects?limit=100` → `{ items, next_cursor }`. Фронтенд
  читает первую страницу (до 100 активных проектов), `next_cursor`
  игнорируется.
- `ProjectResponse`:

```ts
interface ProjectProgress {
  total: number;
  completed: number;
  remaining: number;
}

interface ProjectResponse {
  id: number;
  name: string;
  description: string | null;
  icon: string | null;
  color: ColorResponse;
  progress: ProjectProgress;
  archived_at: string | null;
  created_at: string;
  updated_at: string;
}
```

- Иконка: имя `project.icon` соответствует базовому имени файла в
  `app/assets/icons/projects-icons/` (`leaf` → `leaf.svg`).
- Если `icon` равен `null`, пустой строке или имени нет в наборе
  `projects-icons`, используется `no-project.svg`.
- В `QuickTaskDraft` добавляется `projectId: number | null`, значение по
  умолчанию — `null`.
- Zod-схема: `projectId` — `number().int().positive().nullable()`.
- `toTaskCreateInput` и `toSeriesCreateInput` добавляют
  `project_id: draft.projectId` (включая `null`).
- Проекты читаются через React Query с ключом `["projects"]`; запрос
  стартует при монтировании inline-формы.
- После успешного создания задачи/серии инвалидируется и `["projects"]`
  (меняется прогресс проекта).

### FR-4. Ошибки и удалённый проект

- Ошибки загрузки списка: текст и «Повторить» по FR-2; «Без проекта»
  остаётся доступным.
- При `404` (удалённый проект или метка) от `POST /tasks` или
  `POST /task-series`:
  - перезапросить `["labels"]` и `["projects"]` (явный `refetch` сам
    обновляет кэш, отдельная инвалидация не нужна);
  - вычистить из `draft` и `stepDraft` метки, которых больше нет;
  - сбросить `projectId` в `null`, если выбранного проекта нет в свежем
    списке;
  - показать `Метки или проект больше недоступны. Обновите список.`.
- При `400` с выбранным проектом (`projectId !== null`) backend может
  вернуть `bad_request`, если проект архивный:
  - перезапросить `["projects"]`;
  - если выбранного проекта нет в успешном свежем списке — сбросить
    `projectId` в `null` и показать тот же текст
    `Метки или проект больше недоступны. Обновите список.`;
  - если проект остался в списке — оставить обычный текст валидации.
- `400` без выбранного проекта не вызывает перезапросов и показывает
  обычный текст валидации.
- Остальные ошибки (`422`, `429`, `5xx`, сеть) обрабатываются
  существующим `describeQuickAddError` без изменений.
- После успеха черновик сбрасывается, `projectId` снова `null`.

### FR-5. Доступность и фокус

- Чип проекта — кнопка с `aria-haspopup="dialog"` и доступным именем по
  FR-1.
- Список — `role="radiogroup"` с `aria-label="Проект"`; строки
  «Без проекта» и проекты — `role="radio"` с `aria-checked`.
- Кнопка «Повторить» имеет понятное имя; ошибка списка — обычный текст
  в области списка.
- Клавиатура, focus trap шторки и возврат фокуса на чип работают через
  существующие `BottomSheet`/`Modal` и `pendingChipFocusRef`.
- Новые фокус-стили — внутреннее кольцо `app-accent`.

## 4. Визуальная спецификация

| Элемент | Значение |
|---|---|
| Чип проекта | `OptionChip`, 45px, радиус 50px, gap 5px |
| Иконка чипа | 18×18 |
| Заголовок шторки | `Проект`, 17px Semi Bold, по центру |
| Строка списка | 50px, полная ширина |
| Индикатор выбора | галочка 24×24 `app-accent` или спейсер |
| Gap индикатор → контент | 15px |
| Иконка проекта | 18×18, цвет `project.color.hex` |
| Gap иконка → имя | 5px |
| Имя проекта | 15px Regular, `app-text` |
| Разделитель | 1px `app-stroke` |
| Кнопка «Применить» | 50px, радиус 25px, `app-accent`, белый 15px Semi Bold |

- Только токены `app-*`; `dark:`-классы и хардкод цветов Telegram не
  добавляются.
- Ширины `320 / 412 / 448px`, light/dark и safe-area не ломаются;
  горизонтальный скролл страницы не появляется.

## 5. Нефункциональные требования

- Новые зависимости не добавляются.
- SSR включён; запрос проектов выполняется только в браузере после
  `AuthGate`.
- Нет доступа к `window`/`document` на верхнем уровне модулей.
- TypeScript strict, без `any`; типы — через `import type`.
- Файлы — `kebab-case`, компоненты — `PascalCase`, алиас `~/`.
- Все API-запросы — через `apiRequest`.
- Тесты — Vitest, `app/**/*.test.ts`; чистые функции — unit, компоненты —
  `renderToStaticMarkup`.
- Линтера в проекте нет; `npm run lint` не добавлять.
- Токены, refresh cookie и `initData` не логируются и не сохраняются.

## 6. Вне scope

- Создание, редактирование, архивация и удаление проектов.
- Экран списка проектов и экран детальной информации проекта.
- Загрузка/выбор иконок проекта.
- Поиск, фильтрация и пагинация списка проектов дальше первых 100.
- Архивные проекты в выборе.
- Мультивыбор проектов.
- Сохранение черновика между перезагрузками.
- Изменение остальных шагов, чипов и логики голосовой записи.
- E2E/браузерные тесты.

## 7. Критерии приёмки

- [ ] В строке чипов после «Метки» есть чип проекта; без выбора —
      иконка `no-project` и «Без проекта».
- [ ] Чип открывает шторку «Проект»; «Без проекта» всегда первая и
      выбрана по умолчанию.
- [ ] Проекты загружаются из `GET /projects?limit=100`; архивные не
      показываются.
- [ ] Иконка проекта берётся из `projects-icons` по `project.icon` и
      окрашена в `project.color.hex`.
- [ ] При `icon = null` или неизвестном имени показывается
      `no-project`.
- [ ] Одиночный выбор, галочка у выбранной строки, разделители и кнопка
      «Применить» соответствуют макету.
- [ ] «Применить» коммитит проект; закрытие без применения отбрасывает.
- [ ] При загрузке, ошибке и пустом списке «Без проекта» доступен;
      ошибка показывает «Повторить».
- [ ] `project_id` уходит в `POST /tasks` и `POST /task-series`;
      «Без проекта» отправляет `null`.
- [ ] При `404` (удалённый проект) обновляются метки и проекты, а при
      `400` с архивным выбранным проектом обновляются проекты; если
      выбранного проекта нет в свежем списке, выбор сбрасывается,
      черновик сохраняется.
- [ ] После успеха форма сбрасывается на «Без проекта», `["projects"]`
      инвалидируется.
- [ ] `npm test`, `npm run typecheck`, `npm run build` проходят.
- [ ] SSR-ответ главной не содержит защищённого контента;
      `curl -i http://localhost:3000/does-not-exist` отдаёт `404`.
- [ ] Вручную проверены light/dark, ширины `320 / 412 / 448px`,
      safe-area и клавиатура.

## 8. Принятые решения

- SDD-документы: `docs/specs/2026-11-06-quick-add-project/`.
- Чип проекта стоит после меток, перед приоритетом.
- Без выбора — «Без проекта» с иконкой `no-project`.
- Неизвестная/пустая иконка также маппится на `no-project`.
- «Без проекта» показывается всегда и является значением по умолчанию.
- Загружается первая страница активных проектов (до 100); архивные и
  пагинация вне scope.
- Текст `404` расширен до «Метки или проект больше недоступны.
  Обновите список.».
- Новые зависимости не добавляются.
