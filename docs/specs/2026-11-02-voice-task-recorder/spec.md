# Milly — запись задачи голосом (SDD Specification)

**Статус:** draft for approval
**Дата:** 2026-11-02
**Область:** `frontend/`
**Figma:** `27:1691` (светлая — неактивно), `33:6944` (светлая — запись),
`33:7049` (светлая — отправка), `33:6998` (светлая — отмена),
`33:7099` (тёмная — неактивно), `33:7149` (тёмная — запись),
`33:7199` (тёмная — отправка), `33:7249` (тёмная — отмена)

## 1. Контекст и цель

На главном экране уже есть карточка «Голосом» в блоке быстрого доступа.
Сейчас она даёт только haptic-отклик. Нужно открыть по ней модальное окно
записи голосового сообщения, записать звук и отправить его в будущий API.
Backend пока отсутствует, поэтому отправка выполняется mock-функцией с
задержкой 1,2 с.

Запись должна быть реальной (`getUserMedia` + `MediaRecorder`), чтобы
следующая итерация могла заменить mock на загрузку файла без переписывания
UI. Отправка, расшифровка, создание задачи и воспроизведение звука в этой
итерации не реализуются.

Модальное окно будет переиспользоваться и для других сценариев. Поэтому
общий примитив (`Modal` + `BottomSheet`: портал, overlay, focus trap,
блокировка скролла, Escape, анимация появления) отделяется от
voice-специфичной логики. В этой итерации примитив поставляется в варианте
bottom sheet; будущие модалки смогут использовать его без копирования
portal/focus-кода.

## 2. Пользовательские сценарии

1. Пользователь нажимает «Голосом» на главной. Появляется затемнение и
   нижняя шторка в неактивном состоянии; запрашивается доступ к микрофону,
   если он ещё не выдан.
2. Пользователь зажимает круг микрофона. Начинается запись: идут
   пульсирующие кольца, меняется инструкция. Пользователь отпускает —
   показывается «Отправляем...», через 1,2 с модалка закрывается, звучит
   success-haptic.
3. Во время записи пользователь ведёт палец вниз. После порога микрофон
   становится красным и немного смещается вниз, инструкция меняется на
   отмену. Отпускание отменяет запись, шторка остаётся открытой в
   неактивном состоянии.
4. Пользователь свайпнул вниз, но вернул палец выше порога. Микрофон снова
   синий; отпускание отправляет запись.
5. Слишком короткое нажатие, `pointercancel`, потеря фокуса, уход приложения
   в фон или закрытие шторки во время записи отменяют запись. Аудио не
   отправляется, микрофонные треки останавливаются.
6. Нет разрешения, микрофона или поддержки `MediaRecorder` — показывается
   понятное состояние ошибки; повторное нажатие на микрофон повторяет
   подготовку.
7. Пользователь меняет тему Telegram — шторка перекрашивается без
   перезагрузки, без `dark:`-классов.
8. Пользователь управляет клавиатурой: Tab внутри шторки, Space/Enter —
   удержание и отпускание, Escape — закрытие (активная запись при этом
   отменяется). Скринридер получает заголовок, описание и изменения
   состояния.

## 3. Функциональные требования

### FR-1. Открытие и закрытие

- Карточка «Голосом» в `QuickAccessSection` открывает модалку. Остальные
  быстрые действия сохраняют текущее поведение (haptic без навигации).
- Модалка открывается поверх главного экрана: полноэкранный overlay
  `rgba(0, 0, 0, 0.4)`, шторка снизу.
- Закрытие доступно тремя способами: кнопка «Закрыть», клик по overlay,
  `Escape`.
- Закрытие во время записи сначала отменяет запись и освобождает микрофон.
- Закрытие во время отправки прерывает mock-загрузку; success-haptic и
  автозакрытие после этого не выполняются.
- После закрытия фокус возвращается на элемент, который был активен до
  открытия (обычно — карточка «Голосом»).
- Модалка не выполняет навигацию и не меняет маршрут.

### FR-2. Переиспользуемая модалка

- Общий `Modal` отвечает за: портал в `document.body`, overlay, presence-
  анимацию, `role="dialog"`, `aria-modal`, Escape, клик по overlay, focus
  trap, блокировку скролла страницы, восстановление фокуса и стек модалок.
- Общий `BottomSheet` отвечает за: позиционирование снизу, ширину, safe-area,
  панель, заголовок, footer, максимальную высоту и внутренний скролл.
- Voice-компонент отвечает только за запись, состояние, копирайт и
  специфичные анимации.
- Одновременно проектируется одна открытая модалка. Примитив хранит стек
  открытых модалок, чтобы `Escape` и focus trap применялись только к
  верхней; визуальный сценарий двух модалок не проектируется.
- Блокировка скролла использует счётчик, чтобы вложенные/последовательные
  модалки не разблокировали страницу раньше времени.

### FR-3. Геометрия и адаптивность

- Ширина шторки: viewport минус `15px` слева и справа; на экране шире
  `max-w-md` ширина ограничивается `max-w-md` (`28rem`) и центрируется.
- На ширине 412 px панель занимает 382 px. Расхождение с макетом (380 px
  при отступах 16 px) допустимо: требование 15 px приоритетнее.
- Шторка прижата к низу. Нижний отступ — минимум `15px` с учётом
  `--app-inset-bottom`; левый/правый — минимум `15px` с учётом
  `--app-inset-left/right`.
- Панель: высота `380px`, радиус `25px`, padding `15px`, фон `app-card`.
- Footer «Закрыть»: отдельная кнопка высотой `50px`, радиус `25px`, фон
  `app-card`, gap до панели `10px`.
- Если высоты экрана не хватает, панель уменьшается по `max-height` и
  контент прокручивается внутри; footer остаётся видимым.
- На ширине 320 px не должно быть горизонтального скролла и обрезанного
  текста. Шторка не растягивается шире `max-w-md`.

### FR-4. Состояния и копирайт

| Состояние | Заголовок инструкции | Подзаголовок | Акцент подзаголовка |
|---|---|---|---|
| `idle` | `Зажмите, чтобы записать` | `Отпустите, чтобы отправить` | `app-text-secondary` |
| `recording` | `Идёт запись...` | `Проведите вниз для отмены` | `app-accent` |
| `cancelling` | `Запись будет отменена` | `Отпустите для отмены` | `app-destructive` |
| `sending` | `Отправляем...` | `сообщение уже в пути` | `app-text-secondary` |
| `error` | по таблице ошибок | по таблице ошибок | `app-destructive` |

- `cancelling` — не отдельный статус рекордера, а подсостояние записи,
  включаемое порогом свайпа.
- `preparing` (проверка/запрос доступа к микрофону) визуально использует
  `idle`-копирайт; кнопка микрофона недоступна до завершения подготовки.
- Заголовок модалки всегда `Голосовое сообщение`.
- Описание всегда
  `Расскажите какую задачу или трату необходимо записать`.
- Кнопка закрытия всегда `Закрыть`.
- Тексты не менять самовольно: это часть макета.

Ошибки:

| Причина | Заголовок | Подзаголовок |
|---|---|---|
| `permission-denied` | `Нет доступа к микрофону` | `Разрешите доступ в настройках и попробуйте снова` |
| `unsupported` | `Запись недоступна` | `Это устройство не поддерживает запись звука` |
| `no-microphone` | `Микрофон не найден` | `Подключите микрофон и попробуйте снова` |
| `recorder` | `Не удалось записать` | `Попробуйте ещё раз` |
| `upload` | `Не удалось отправить` | `Попробуйте ещё раз` |

- В состоянии ошибки микрофон остаётся красным; нажатие повторяет
  подготовку/запись.
- Ошибки не закрывают модалку автоматически.

### FR-5. Запись

- Используется реальный `navigator.mediaDevices.getUserMedia({ audio: true })`
  и `MediaRecorder`.
- При открытии модалки выполняется подготовка доступа:
  1. если `navigator.permissions.query({ name: "microphone" })` сообщает
     `granted` — ничего не запрашивать;
  2. если `denied` — сразу показать ошибку;
  3. если `prompt`/`unknown` — один раз запросить поток и сразу остановить
     его треки, чтобы получить разрешение, не удерживая микрофон открытым.
- Это осознанное решение: модалка существует только для записи, поэтому
  запрос разрешения при открытии уместен и не ломает press-and-hold на
  первом использовании.
- Запись начинается по `pointerdown` (или `keydown` Space/Enter) на круг
  микрофона. Поток не удерживается между записями.
- MIME выбирается из поддерживаемых: `audio/webm;codecs=opus`, `audio/mp4`,
  `audio/webm`, `audio/ogg;codecs=opus`. Если `MediaRecorder.isTypeSupported`
  недоступен, MIME не задаётся.
- `MediaRecorder.start(100)` — чанки по 100 мс.
- При остановке возвращается `{ blob, mimeType, durationMs }`; все треки
  останавливаются.
- При отмене blob отбрасывается, треки останавливаются.
- Запись короче `300ms` или пустой blob не отправляются; шторка
  возвращается в `idle`.
- Максимальная длительность — 5 минут, после чего запись автоматически
  останавливается и уходит в отправку. Это защита от неограниченной памяти,
  отдельного таймера в UI нет.
- При уходе страницы в фон (`visibilitychange === "hidden"`) или
  `isActive === false` от Telegram активная запись отменяется.
- Аудио не воспроизводится и не сохраняется между открытиями модалки.

### FR-6. Свайп вниз для отмены

- Свайп отслеживается только во время записи.
- Начало свайпа — `pointerdown` на микрофоне; используется pointer capture,
  поэтому палец можно уводить за пределы кнопки.
- Смещение вниз `dy = max(0, clientY - startY)`.
- Визуальное смещение микрофона — `min(dy * 0.15, 8px)`; масштаб плавно
  уменьшается до `0.97`.
- Порог отмены — `64px` вниз. При пересечении порога:
  - микрофон и внешнее кольцо становятся красными;
  - заголовок/подзаголовок меняются на `cancelling`;
  - кольца пульсации становятся красными;
  - срабатывает `haptics.impact("rigid")`.
- При возврате выше порога состояние отмены снимается, цвета возвращаются,
  срабатывает `haptics.selection()`.
- Отпускание ниже порога отменяет запись; отпускание выше порога отправляет.
- `pointercancel`, потеря pointer capture и `blur` во время записи отменяют
  запись.
- На каждое движение пальца не должно быть React-рендера: позиция и масштаб
  обновляются через MotionValues; React-состояние меняется только при
  пересечении порога.

### FR-7. Клавиатура

- `Space`/`Enter` на кнопке микрофона: `keydown` начинает запись, `keyup`
  отправляет. Повторный `keydown` игнорируется.
- `Escape` закрывает модалку. Если в этот момент идёт запись, она
  отменяется, треки останавливаются, а `keyup` после закрытия ничего не
  отправляет.
- `blur` во время удержания отменяет запись.
- Tab не выходит за пределы модалки; фокус зациклен между микрофоном и
  кнопкой «Закрыть».

### FR-8. Отправка

- После успешной остановки записи статус меняется на `sending`.
- `uploadVoiceTask(recording, { signal })` — mock: ждёт 1200 мс и
  resolves. Реальный `fetch` не выполняется.
- В состоянии `sending` микрофон зелёный, кольца не пульсируют, кнопка
  микрофона недоступна.
- Через 1200 мс: `haptics.notification("success")`, модалка закрывается.
- Если mock/будущий API rejects — статус `error`, причина `upload`, без
  автозакрытия.
- Закрытие/отмена во время отправки абортирует mock-загрузку через
  `AbortController`.
- Контракт mock заменяем на реальный API без изменения UI:
  `uploadVoiceTask(recording): Promise<void>`.
- `initData`, `fetch`, авторизация и backend-валидация в этой итерации не
  используются.

### FR-9. Haptics

- Открытие карточки «Голосом»: `impact("light")` (уже есть).
- Старт записи: `impact("medium")`.
- Вход в зону отмены: `impact("rigid")`; выход: `selection()`.
- Отмена отпусканием: `notification("warning")`.
- Успешная отправка: `notification("success")`.
- Ошибка подготовки/записи/отправки: `notification("error")`.
- Все вызовы идут через существующий `useTelegram().haptics`, вне Telegram
  ничего не происходит.

## 4. Данные и состояния

### 4.1. Контракты

```ts
interface VoiceRecording {
  blob: Blob;
  mimeType: string;
  durationMs: number;
}

interface VoiceRecordingSession {
  stop(): Promise<VoiceRecording>;
  cancel(): void;
}

type MicrophoneErrorReason =
  | "unsupported"
  | "permission-denied"
  | "no-microphone"
  | "recorder";

type VoiceRecorderStatus =
  | "idle"
  | "preparing"
  | "recording"
  | "sending"
  | "error";

type VoiceRecorderError = MicrophoneErrorReason | "upload";
```

- `prepareMicrophone(): Promise<{ ok: true } | { ok: false; reason: MicrophoneErrorReason }>`
- `startVoiceRecording(): Promise<{ ok: true; session: VoiceRecordingSession } | { ok: false; reason: MicrophoneErrorReason }>`
- `uploadVoiceTask(recording: VoiceRecording, options?: { signal?: AbortSignal }): Promise<void>`

### 4.2. Состояния

```text
idle
  -> preparing (открытие модалки / retry)
  -> idle (успех подготовки)
  -> error (ошибка подготовки)

idle
  -> recording (pointerdown/keydown)
  -> error (getUserMedia/MediaRecorder)

recording
  -> cancelling (dy >= 64px) -> recording (dy < 64px)
  -> idle (отмена / слишком коротко / закрытие)
  -> sending (отпускание без отмены)

sending
  -> idle (закрытие/abort)
  -> error (upload)
  -> закрытие модалки (mock success)
```

### 4.3. Mock

- Mock-загрузка живёт в `app/lib/voice/upload-voice-task.ts`.
- Задержка по умолчанию — 1200 мс; поддержан `AbortSignal`.
- Blob сейчас никуда не уходит и не логируется.
- После подключения backend заменяется только тело функции; UI и hook не
  меняются.

## 5. Визуальная спецификация

### 5.1. Токены

Используются существующие `app-*` токены; новые цвета не добавляются.
Тёмная тема — через `data-app-theme`, без `dark:`-классов.

| Элемент | Light | Dark |
|---|---|---|
| Overlay | `rgba(0,0,0,0.4)` | `rgba(0,0,0,0.4)` |
| Панель и footer | `app-card` `#FFFFFF` | `app-card` `#212121` |
| Заголовок модалки/инструкции | `app-text` `#303033` | `app-text` `#FFFFFF` |
| Описание | `app-text-secondary` `#7A7D83` | `app-text-secondary` `#7A7D83` |
| Внешнее кольцо (idle/recording) | `app-accent-soft` `#EAF3FF` | `app-accent-soft` `#31373F` |
| Внешнее кольцо (cancel/error) | `app-destructive` 10% | `app-destructive` 10% |
| Внешнее кольцо (sending) | `app-success` 15% | `app-success` 15% |
| Круг микрофона (idle/recording) | `app-accent` `#007AFF` | `app-accent` `#007AFF` |
| Круг микрофона (cancel/error) | `app-destructive` `#E53935` | `app-destructive` `#E53935` |
| Круг микрофона (sending) | `app-success` `#31D158` | `app-success` `#32E55E` |
| Иконка микрофона | белая | белая |
| Текст footer | `app-accent` | `app-accent` |

- Тень круга микрофона: `0 8px 20px rgba(0, 122, 255, 0.15)` во всех
  состояниях, как в макете.
- Overlay не размывает фон.

### 5.2. Геометрия

- Внешний слой шторки: `max-w-md`, центрирование по горизонтали, прижатие
  к низу, отступы safe-area.
- Панель: `380px` высота при достаточном viewport, `border-radius: 25px`,
  `padding: 15px`.
- Заголовок модалки: блок высотой 24 px, по центру.
- Тело: `flex-1`, горизонтальные отступы 24 px, вертикальные 15 px,
  контент распределён `space-between`; описание сверху, микрофон в центре,
  инструкция снизу. Заголовок и подзаголовок инструкции разделены gap 5 px.
- Микрофон: внешний круг `156px`, внутренний круг `116px` (по 20 px
  разницы), иконка 44×44 px с векторной формой ~26×37 px и stroke 2.5 px.
- Footer: `50px`, `border-radius: 25px`; gap между панелью и footer 10 px.
- Максимальная высота панели:
  `calc(var(--tg-viewport-stable-height, 100dvh) - var(--app-inset-top) - var(--app-inset-bottom) - 90px)`;
  при нехватке высоты скроллится тело, footer остаётся видимым.

### 5.3. Типографика

|---|---|---|
| Заголовок модалки | 17 px / 600 | 1.4 |
| Описание | 15 px / 400 | 1.3 |
| Заголовок инструкции | 15 px / 600 | 18 px |
| Подзаголовок инструкции | 13 px / 400 | 1.4 |
| Кнопка «Закрыть» | 15 px / 600 | auto |

Шрифт — Inter, уже подключён.

### 5.4. Кольца пульсации

- В состоянии `recording` внутри 156 px области показываются 3 кольца.
- Кольцо стартует на размере внутреннего круга (116 px) и растёт до 156 px
  (`scale(1) -> scale(1.34)`), одновременно теряя opacity `0.32 -> 0`.
- Длительность одного цикла — 2,1 с; задержки — 0 / 700 / 1400 мс.
- В `cancelling` кольца красные; в `sending` и `idle` не рендерятся.
- Кольца декоративные, `aria-hidden`, `pointer-events: none`.

### 5.5. Анимации

| Событие | Анимация |
|---|---|
| Появление overlay | opacity `0 -> 1`, 180 ms ease-out |
| Появление шторки | `y: 48 -> 0`, opacity `0 -> 1`, spring stiffness 380 / damping 34 / mass 0.9 |
| Исчезновение | `y: 0 -> 40`, opacity `1 -> 0`, 180 ms ease-in |
| Нажатие микрофона | scale `1 -> 0.97`, ~120 ms |
| Свайп вниз | `y` до 8 px, scale до 0.97, spring |
| Цвет круга/кольца | background-color/box-shadow 200 ms |
| Пульсация | CSS keyframes, только transform/opacity |

- Анимации появления/исчезновения и свайпа — Motion (`motion/react`).
- Бесконечная пульсация и смена цветов — CSS transitions/keyframes, чтобы
  не нагружать JS.
- В анимационном цикле не анимируются layout-свойства (top/height/width/
  margin) и не вызывается React-рендер на каждый pointermove.
- `MotionConfig reducedMotion="user"` ставится рядом с корнем приложения.
- При `prefers-reduced-motion: reduce`: пульсация отключается, transform-
  анимации не выполняются, остаются opacity/color-переходы.

## 6. Темы и Telegram

- Тема приходит из `TelegramProvider` через `data-app-theme`; компоненты
  используют только `app-*` токены.
- Safe-area применяется самой шторкой, потому что портал рендерится вне
  `AppShell`: `max(15px, var(--app-inset-left/right))` и
  `max(15px, var(--app-inset-bottom))`.
- Высота стабильного viewport берётся из `100dvh` с fallback
  `--tg-viewport-stable-height` там, где это нужно для max-height.
- `disableVerticalSwipes()` уже вызывается в `TelegramProvider`; конфликта
  со свайпом микрофона быть не должно.
- Haptics — только через `useTelegram()`.
- Нативный header Telegram не дублируется и не меняется.
- `setBottomBarColor`/`setHeaderColor` не трогаются.

## 7. Доступность

- `role="dialog"`, `aria-modal="true"`, `aria-labelledby` на заголовок,
  `aria-describedby` на описание.
- Focus trap внутри шторки; начальный фокус — на контейнере диалога, а не
  на микрофоне, чтобы Enter не начал запись случайно.
- После закрытия фокус возвращается на ранее активный элемент (обычно —
  карточка «Голосом»).
- Кнопка микрофона имеет доступное имя, зависящее от состояния:
  «Начать запись», «Идёт запись. Отпустите, чтобы отправить»,
  «Отпустите, чтобы отменить запись», «Повторить попытку записи» и т.д.
- Блок инструкции имеет `aria-live="polite"`, чтобы смена состояния
  озвучивалась.
- Декоративные кольца и иконка — `aria-hidden="true"`.
- Кнопки имеют `type="button"` и видимый focus-visible outline.
- Tap-target микрофона — 116 px, кнопки закрытия — 50 px.
- Клавиатурное управление описано в FR-7.
- При reduced motion остаётся текстовый статус, поэтому смысл не теряется.

## 8. Нефункциональные требования

- SSR включён; модалка не рендерится в SSR-ответе, пока `open === false`.
- Нет доступа к `window`, `document`, `navigator`, `MediaRecorder` на
  верхнем уровне модулей — только в эффектах и обработчиках.
- Портал создаётся только после монтирования на клиенте.
- Новые зависимости не добавляются; `motion@14.9.0` уже установлен,
  импорт — только из `motion/react`.
- TypeScript strict, без `any`; типы импортируются через `import type`.
- Все таймеры, `MediaStreamTrack`, `MediaRecorder`, `AbortController` и
  event listener'ы очищаются при отмене/закрытии/unmount.
- Секреты и `initData` не попадают в клиентский код.
- Файлы — kebab-case; компоненты — PascalCase; алиас `~/`.
- Тестового фреймворка и линтера нет; новые инструменты не добавляются.
- Целевая производительность — 60 fps на среднем мобильном устройстве:
  только composited transform/opacity в бесконечных анимациях.

## 9. Вне scope

- Реальный backend, авторизация, загрузка blob, валидация `initData`.
- Расшифровка речи и создание задачи/траты из текста.
- Воспроизведение записанного аудио и waveform по реальному звуку.
- Таймер длительности, прогресс загрузки, очередь повторной отправки.
- Переход в настройки Telegram для выдачи разрешения.
- Свайп вниз по самой шторке для её закрытия.
- Одновременное отображение нескольких модалок.
- Изменение главного экрана за пределами обработчика «Голосом».
- Тесты, линтер, настройка CI.

## 11. Принятые решения

- SDD-документы лежат в `docs/specs/2026-11-02-voice-task-recorder/`.
- Общий `Modal` и `BottomSheet` выносятся в `app/components/ui/`; voice-
  логика — отдельно.
- Motion используется для появления шторки и свайпа; CSS — для пульсации
  и смены цветов.
- Запись реальная (`MediaRecorder`), отправка — mock с задержкой 1,2 с.
- Разрешение микрофона готовится при открытии модалки, а не во время
  первого press-and-hold.
- После отправки шторка закрывается автоматически.
- После отмены шторка остаётся открытой в `idle`.
- Порог отмены — 64 px; визуальное смещение — до 8 px.
- Минимум записи — 300 ms; максимум — 5 минут.
- Ошибки — расширение сверх макета; копирайт из таблицы § FR-4.
- 15 px приоритетнее 16 px из Figma.
- Пульсирующие кольца выбраны вместо waveform-полосок.
- Новые цвета и зависимости не добавляются.
