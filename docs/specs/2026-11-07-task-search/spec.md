## 1. Контекст и цель

Сегментированный переключатель на `/tasks` уже содержит три раздела:
«Сегодня», «Поиск задач» и «Проекты». Раздел «Поиск задач» отрисован, но
отключён; отдельного экрана поиска нет.

Цель итерации — реализовать экран «Поиск задач» в состояниях из шести
перечисленных фреймов: дефолт, активный фильтр и «задач не нашлось», в
светлой и тёмной темах. Поиск выполняется на сервере через `GET /tasks`
(`q` по `title`/`description`). Список показывает задачи выбранного
локального дня; по умолчанию это сегодняшний день пользователя.

Шторки фильтров («Окно фильтров»: все фильтры, дата, проект, приоритет,
статус, регулярность) в эту итерацию **не входят**. Кнопки и чипы панели
фильтров остаются визуальными заглушками и не меняют запрос. Состояние
«Активен фильтр» доступно только через dev-preview для визуальной
проверки.

## 2. Пользовательские сценарии

1. Пользователь открывает `/tasks`, нажимает сегмент «Поиск задач».
   Срабатывает haptic selection, открывается `/tasks/search`; активен
   сегмент «Поиск задач», нижняя вкладка «Задачи».
2. Пользователь открывает `/tasks/search` напрямую. Видит заголовок
   «Поиск задач», подзаголовок, поисковое поле, панель фильтров и список
   задач на сегодня с количеством.
3. Пользователь вводит текст в поле «Поиск». Запрос уходит на сервер с
   `q`; список показывает совпадения по названию или описанию. Пустой
   запрос возвращает весь список за день.
4. Совпадений нет. Заголовок списка показывает `Задачи на DD.MM.YYYY (0)`,
   под ним — карточка с эмодзи и текстом «К сожалению задач не найдено».
5. Пользователь отмечает задачу выполненной или возвращает её в работу.
   Список обновляется оптимистично; при ошибке изменение откатывается и
   показывается сообщение.
6. Пользователь нажимает «Сегодня» — возвращается на `/tasks`.
   «Проекты» остаётся недоступным. Повторное нажатие активного сегмента
   даёт только haptic, без навигации.
7. Пользователь нажимает «Главная» или «Задачи» в нижней навигации —
   переходит на `/` или `/tasks`. Кнопка добавления ведёт на `/`.
8. В dev-режиме пользователь открывает `?state=filter` и видит визуальное
   состояние активного фильтра: бейдж «1» на кнопке фильтров и активный
   чип «Проект». Данные при этом не фильтруются.
9. Первая загрузка показывает скелетон области результатов; ошибка без
   данных — карточку «Не удалось загрузить задачи» с «Повторить».

## 3. Функциональные требования

### FR-1. Маршрут и навигация

- Новый защищённый маршрут — `/tasks/search`, файл
  `app/routes/task-search.tsx`, добавляется в `app/routes.ts` внутри
  `layout("routes/_app.tsx", [...])` после `tasks`.
- На экране активна нижняя вкладка «Задачи»; «Главная» ведёт на `/`,
  «Задачи» — на `/tasks`.
- Кнопка добавления задачи (`AddTaskButton`) закреплена над нижней
  навигацией справа, как на `/tasks`; по нажатию — haptic selection и
  переход на `/`.
- Сегмент «Поиск задач» на `/tasks` становится доступным и навигирует на
  `/tasks/search` с haptic selection. Остальные правила сегментов — в
  FR-2.
- Маршрут использует существующий `AppShell` и `AuthGate`; данные
  загружаются React Query после `AuthGate`, не в loader.
- `loader` маршрута читает только dev-preview состояние (FR-9) и не
  обращается к защищённым данным.
- `meta`: заголовок `Поиск задач — Milly`, публичное описание
  `Поиск задач в Milly`.
- SSR не должен содержать защищённых данных задач (названий, проектов,
  счётчиков, прогресса).

### FR-2. Сегментированный переключатель

- Общий список и компонент выносятся из `TodayTasksView`:
  `app/components/tasks/task-segments.tsx` экспортирует `TaskSegmentId`,
  `TASK_SEGMENTS` и `TaskSegments`.
- Опции и порядок: `today` «Сегодня» (`circle-check.svg`), `search`
  «Поиск задач» (`search.svg`), `projects` «Проекты» (`dashboard.svg`).
  `today` и `search` доступны, `projects` — `disabled`.
- `TaskSegments` принимает `value: TaskSegmentId` и
  `onSelect: (id: TaskSegmentId) => void`, рендерит существующий
  `SegmentedControl` с `ariaLabel="Разделы задач"`.
- `/tasks` передаёт `value="today"`, `/tasks/search` — `value="search"`.
- Выбор `today` на `/tasks/search` ведёт на `/tasks`; выбор `search` на
  `/tasks` ведёт на `/tasks/search`. Выбор уже активного сегмента даёт
  только haptic. Выбор `projects` не навигирует.
- Визуальные параметры `SegmentedControl` не меняются (высота `50px`,
  радиус `36px`, фон `app-card`, padding `5px`, gap `2px`, активный
  сегмент `bg-app-track text-app-accent`, иконки скрываются ниже
  `360px`).
- `TodayTasksView` и `TodayTasksError` получают проп
  `onSelectSegment: (id: TaskSegmentId) => void`; маршрут `/tasks`
  передаёт обработчик навигации.

### FR-3. Заголовок и поисковое поле

- Заголовок показывается всегда, на всех состояниях:
  - `h1` «Поиск задач», `24px`, bold, `line-height: 29px`,
    `letter-spacing: -0.8px`, `text-app-text`;
  - подзаголовок «Ищите, фильтруйте и сортируйте старые или новые
    задачи», `13px`, `line-height: 1.4`, `text-app-text-secondary`;
  - отступы `px-[15px]`, промежуток `5px`.
- Поисковое поле — существующий `SearchField` со значением, `ariaLabel`
  «Поиск задач» и placeholder «Поиск».
- Для страницы используется вариант поля с фоном `app-stroke` (в Figma
  фон поля совпадает с цветом обводки), а не `app-track`. В
  `SearchField` добавляется проп `variant?: "track" | "stroke"` со
  значением по умолчанию `"track"`; существующие шторки быстрого
  создания не меняются.
- Поле управляемое: ввод хранится в локальном состоянии маршрута.
  Запрос использует `value.trim()`; `q` не отправляется при пустой
  строке.
- Поиск выполняется при каждом изменении значения, без debounce.
  Предыдущие результаты остаются на экране до ответа нового запроса
  (`placeholderData: keepPreviousData`); скелетон показывается только
  при первой загрузке.
- Значение поиска не сохраняется в URL и не переживает уход со
  страницы.
- Регистр не нормализуется на клиенте; сервер выполняет поиск без учёта
  регистра. Пробелы по краям обрезаются.

### FR-4. Панель фильтров

- Под поисковым полем — одна горизонтально прокручиваемая строка без
  переноса, с промежутком `5px` и скрытым скроллбаром
  (`[scrollbar-width:none] [&::-webkit-scrollbar]:hidden`). Строка
  выходит за пределы контентного отступа: первый элемент начинается в
  `16px` от края экрана, правый край обрезается краем экрана.
- Состав по порядку:
  1. Кнопка-иконка «Все фильтры»: `adjustments-horizontal.svg`, `45×45`,
     радиус `50`, фон `app-card`, обводка `app-stroke`, иконка `24×24`.
  2. Кнопка-иконка «Фильтр по дате»: `calendar.svg`, те же размеры.
  3. Чип «По приоритету».
  4. Чип «Проект».
  5. Чип «Периодичность».
- Чипы: высота `45px`, радиус `50px`, фон `app-card`, обводка
  `app-stroke`, padding `10px`, gap `5px`, текст `13px`, иконка
  `chevron-down.svg` `16×16`; `ariaLabel` — «Фильтр по приоритету»,
  «Фильтр по проекту», «Фильтр по периодичности».
- В этой итерации все элементы панели — заглушки:
  `aria-disabled="true"`, `tabIndex={-1}`, без `aria-haspopup`, шторки
  не открываются, запрос не меняется.
- Активное состояние (только dev-preview, FR-9):
  - кнопка «Все фильтры» получает обводку и цвет `app-accent` и бейдж;
  - бейдж: `10×10`, круглый, фон `app-accent`, белый текст `6px`
    semibold, позиция справа сверху (`right: 4px`, `top: 5px`),
    `aria-hidden="true"`; доступное имя кнопки — «Все фильтры,
    активно: 1»;
  - чип «Проект» получает `border-app-accent text-app-accent`.
- Скролл-контейнер не является интерактивным элементом управления в
  этой итерации; клавиатурная доступность заглушек не требуется,
  поскольку они исключены из tab-порядка.

### FR-5. Заголовок и список результатов

- Секция результатов: верхний отступ `16px`, промежуток `8px`.
- Заголовок `h2`: `Задачи на DD.MM.YYYY (N)`, `15px`, semibold,
  `line-height: 18px`, `text-app-text-secondary`, `px-[15px]`.
  Дата — выбранный день (сейчас всегда сегодняшний в
  `AuthUser.timezone`). `N` — количество элементов в ответе (0…100).
  Количество показывается всегда, включая `(0)`.
- Карточка списка: `rounded-[25px] bg-app-card px-[15px] py-[15px]`.
  Внутри — строки `TodayTaskRow` без группировки «В планах»/
  «Выполнено»; завершённые и незавершённые задачи идут вперемешку в
  порядке API `(due_at, id)`.
- Строка рендерится существующим `TodayTaskRow`: чекбокс `35×35`
  (`28×28` визуально), название `15px`, проект (иконка `15px` цветом
  проекта, название или «Без проекта»), `· HH:mm`,
  `· Регулярные` при `series_id !== null`, флаг `18×18` у незавершённых
  задач с приоритетом, отличным от `neither`, декоративный chevron
  `24×24`, разделитель `1px app-stroke` между строками.
- Строка не является ссылкой; интерактивен только чекбокс. Переход в
  детали задачи не добавлен.
- Проекты для строк берутся из `GET /projects?limit=100`; ошибка или
  отсутствие проекта не блокируют список — строка показывает «Без
  проекта».
- Ошибка завершения задачи показывается над заголовком списка:
  `role="alert"`, `13px`, `text-app-destructive`, текст «Не удалось
  обновить задачу. Попробуйте ещё раз.».
- Пустое состояние (успешный ответ, `items.length === 0`):
  - заголовок `Задачи на DD.MM.YYYY (0)`;
  - карточка `rounded-[25px] bg-app-card p-[15px]`;
  - внутри по центру вертикально: эмодзи 😔 `50px` (декоративный,
    `aria-hidden="true"`) и текст «К сожалению задач не найдено»,
    `15px`, `text-app-text-secondary`; промежуток `6px`, минимальная
    высота содержимого `90px`.

### FR-6. Состояния экрана

- Статическая часть — сегменты, заголовок, поисковое поле и панель
  фильтров — показывается всегда, включая загрузку и ошибку.
- Первая загрузка (нет данных): скелетон только области результатов:
  плейсхолдер заголовка и карточка с тремя строками, `role="status"`,
  `aria-busy="true"`, `aria-label="Загружаем задачи"`.
- Ошибка без данных: карточка `rounded-[25px] bg-app-card p-[15px]`,
  `role="alert"`, заголовок «Не удалось загрузить задачи» `17px`
  semibold и кнопка «Повторить» `15px` semibold `app-accent`;
  нажатие вызывает `refetch()`.
- Ошибка при наличии ранее загруженных или кэшированных данных: список
  остаётся на экране, полноэкранная ошибка не показывается.
- Пустое состояние показывается только после успешного ответа, не во
  время загрузки.
- Во время ввода нового запроса предыдущий список остаётся видимым до
  прихода нового ответа; отдельный индикатор загрузки не добавляется.

### FR-7. Завершение задач

- Чекбокс строки вызывает `POST /tasks/{id}/complete` или
  `POST /tasks/{id}/uncomplete` через новую мутацию поиска.
- Мутация оптимистично обновляет кэш поиска: `completed_at` выбранной
  задачи и `updated_at`; `next_cursor` сохраняется. При ошибке кэш
  возвращается к снимку, показывается сообщение из FR-5 и haptic
  `notification("error")`.
- При успехе задача заменяется ответом сервера, haptic
  `notification("success")`.
- При `onSettled` инвалидируются `["tasks"]` и `["projects"]`.
- На время запроса чекбокс строки disabled, `aria-busy="true"`,
  прозрачность `50%`; остальные строки остаются доступными.

### FR-8. Данные и запросы

- `TaskListQuery` расширяется полем `q?: string`; `buildTaskListPath`
  добавляет `q` в конец query string, если значение задано и не пустое.
- Запрос экрана:
  `GET /tasks?date=<today>&status=all&limit=100&q=<query>`.
  `date` — `formatZonedToday(new Date(), AuthUser.timezone ?? "UTC")`;
  `q` опускается при пустой строке; `cursor` не передаётся.
- Ключ запроса: `["tasks", "search", timeZone, date, query]` — под
  префиксом `["tasks"]`, чтобы существующие инвалидации обновляли и
  поиск.
- `useSearchTasksData(timeZone, date, query)` использует
  `placeholderData: keepPreviousData`.
- Пагинация не реализуется: `next_cursor` игнорируется, отображаются
  первые 100 результатов; больше 100 — вне scope.
- Проекты загружаются существующим запросом `["projects"]` через
  `fetchProjects`.
- Фильтры (`project_ids`, `priorities`, `recurrence`,
  `include_archived_projects`) не передаются.

### FR-9. Dev-preview «Активен фильтр»

- `loader` маршрута читает query-параметр `state`.
- Только в dev-режиме (`import.meta.env.DEV`) значение
  `state=filter` возвращает `{ activeFilterPreview: true }`; во всех
  остальных случаях — `{ activeFilterPreview: false }`.
- Preview не выполняет запросов, не содержит защищённых данных и не
  меняет выборку.
- При `activeFilterPreview: true` панель фильтров показывает
  `activeFilterCount = 1` и `activeChip = "project"`; при `false` —
  `0` и `null`.
- В production preview никогда не активен, бейдж и активный чип не
  показываются.

### FR-10. Доступность

- Сегменты: `role="tablist"`, `aria-label="Разделы задач"`,
  `role="tab"`, `aria-selected`; «Проекты» — `aria-disabled`,
  `tabIndex={-1}`.
- Поисковое поле: `type="search"`, `aria-label="Поиск задач"`,
  placeholder «Поиск», видимый focus-ring.
- Заглушки фильтров: `aria-disabled="true"`, `tabIndex={-1}`, без
  `aria-haspopup`; бейдж `aria-hidden`, количество входит в доступное
  имя кнопки.
- Секция результатов: `section` с `aria-labelledby` заголовка `h2`,
  список `ul/li`, чекбокс `role="checkbox"` с `aria-checked`,
  `aria-busy` и доступным именем из `TodayTaskRow`.
- Ошибка — `role="alert"`; скелетон — `role="status"` и
  `aria-busy="true"`; эмодзи пустого состояния — `aria-hidden`.
- Все интерактивные элементы имеют `focus-visible:outline-*` из
  существующих компонентов.

## 8. Принятые решения

- Итерация ограничена шестью фреймами самой страницы; шторки
  «Окно фильтров» и фактическая фильтрация — следующая итерация.
- Заголовок «Поиск задач» с подзаголовком показывается всегда, хотя на
  пяти из шести фреймов его нет: так экран консистентен и понятен.
- Экран ищет задачи за сегодняшний локальный день, как показывают
  заголовки `Задачи на DD.MM.YYYY`. Выбор даты появится вместе со
  шторкой фильтра по дате.
- Количество в заголовке списка показывается всегда, включая `(0)`;
  светлый фрейм «Задач не нашлось» без количества считается устаревшим.
- Состояние «Активен фильтр» реализуется визуально и доступно только в
  dev-preview `?state=filter`; в production его нельзя включить, пока
  нет шторок фильтров.
- Поисковое поле на странице использует фон `app-stroke`; вариант
  `track` остаётся для шторок быстрого создания.
- Поиск выполняется без debounce при каждом изменении; старые
  результаты остаются до ответа нового запроса.
- Список переиспользует `TodayTaskRow` без группировки на «В планах» и
  «Выполнено».
- Поисковый запрос не сохраняется в URL.
- Пагинация не реализуется; отображаются первые 100 результатов.
- На экране поиска активна вкладка «Задачи», а не «Главная», как на
  фреймах: это соответствует принятому решению для `/tasks`.
