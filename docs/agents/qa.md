# Проверка перед завершением

Базовые команды (`npm test`, `npm run typecheck`, `npm run build`) — в `AGENTS.md`.
Читай только разделы, относящиеся к изменённым экранам.

## Общие проверки

- Для UI-изменений дополнительно проверить SSR-ответ: `npm run build && PORT=3000 npm start`, затем `curl -s http://localhost:3000/`. В SSR не должно быть защищённого контента — только экран загрузки.
- Для error-экранов проверить `curl -i http://localhost:3000/does-not-exist`: должен вернуться HTTP `404` и тексты 404-экрана с нижней навигацией.
- DEV preview `?state=429` и `?state=5xx` работает только в dev-режиме (`import.meta.env.DEV`); в production он не активен.
- Error-экраны вручную проверить на ширине 320 px, в light/dark теме и с учётом safe-area.

## `/tasks`

- `/tasks` вручную проверить в light/dark теме, на ширинах 320/412/448 px и
  с учётом safe-area; активна вкладка «Задачи», переходы «Главная»/«Задачи»
  работают и сопровождаются haptics.
- Завершение/возврат задачи, обновление прогресса и откат при ошибке,
  раскрытие групп «В планах»/«Выполнено» проверить вручную.
- Кнопка добавления задачи закреплена над нижней навигацией справа, не
  скроллится, учитывает safe-area и ведёт на `/`; блоки «Голосом» и
  «Интерактивно» на `/tasks` отсутствуют (проверить вручную).
- SSR `/tasks` проверить: в `<body>` ответа
  `curl -s http://localhost:3000/tasks` не должно быть защищённых данных
  задач (`В планах`, `Выполнено`, названий задач/проектов, прогресса);
  публичное meta description `Задачи на сегодня в Milly` в `<head>`
  допускается.

## Быстрое создание

- Быстрое создание задачи вручную проверить на ширине 320 px: inline-форма
  между прогрессом и FAQ, счётчик внутри поля, активация кнопки отправки;
  каждый чип открывает свою шторку. Закрытие оверлеем отбрасывает
  неприменённые изменения шага, фокус возвращается на чип; микрофон
  открывает голосовую шторку, голосовая и detail-шторки не открываются
  одновременно.
- Состояние быстрого создания (Zustand) вручную проверить: черновик
  переживает открытие/закрытие детали; изменение шага не обновляет чип до
  «Применить»; закрытие без «Применить» отбрасывает правки шага,
  «Применить» коммитит их и возвращает фокус на чип; просроченная дата
  подрезается до сегодня при открытии шага даты; сумма напоминания
  очищается, остаётся пустой и блокирует «Применить»; успешная отправка
  сбрасывает форму, закрывает шаг и ревалидирует главный экран; submit
  после apply отправляет применённые значения; при `404` метки и удалённый
  проект вычищаются из формы и из открытого шага, `["labels"]` и
  `["projects"]` обновляются; при `400` с архивным выбранным проектом
  обновляется `["projects"]`, а выбор сбрасывается, если проекта нет в
  свежем списке; счётчик и активация кнопки обновляются из стора.
- Выбор проекта вручную проверить: чип «Без проекта» сразу после «Метки»
  открывает шторку «Проект»; «Без проекта» есть всегда и выбрано по
  умолчанию; выбор и «Применить» обновляют чип и `project_id`, закрытие без
  «Применить» отбрасывает выбор; ошибка загрузки показывает «Повторить»;
  задача и серия создаются с `project_id` или `null`, после успеха и `404`
  список проектов обновляется.
- Быстрое создание задачи проверить в light/dark теме, на ширинах
  320/412/448 px, с клавиатурой и safe-area.
- При фокусе на поле внутри шторки (поиск меток/проекта, сумма или время
  напоминания) клавиатура не меняет высоту и позицию панели: она
  перекрывает нижнюю часть, тело прокручивается к полю, нижняя кнопка
  доступна над клавиатурой или прокруткой. После закрытия клавиатуры
  панель не прыгает.
- Шторки «Метки» и «Проект» проверить вручную: поиск фильтрует списки без
  учёта регистра, при пустой выдаче видно «Ничего не найдено»; «Без
  проекта» всегда первая строка и не фильтруется; проекты — с круглым
  бейджем `28×28`, метки — с `tag-raw.svg`; строки `50px` без зазоров,
  разделитель под каждой, кроме последней; скрытые фильтром выбранные
  значения не теряются при «Готово»; в light/dark теме используются
  только токены `app-*`.

## Auth, bootstrap, Telegram

- Для изменений auth поднять backend на `http://127.0.0.1:8000` и проверить dev proxy: `curl -i http://localhost:5173/api/v1/auth/refresh -X POST` должен вернуть `401`, а не `404`.
- Для изменений bootstrap/watchdog вручную проверить блокировку JS-бандла и `telegram-web-app.js` (DevTools → Network → Block request URL): через 5 секунд должен появиться статический fallback с «Повторить», а при нормальной загрузке — не появляться.
- Если менялись Telegram-интеграция или тема, проверить экран в браузере и в Telegram: светлая/тёмная тема, safe-area, клавиатура, fullscreen.
- Локальный запуск в Telegram: HTTPS-туннель на `http://localhost:5173` (`cloudflared tunnel --url ...` или `ngrok http 5173`) и URL в BotFather через `/setmenubutton` или `/newapp`. Quick-туннель меняет URL после перезапуска.

## Шторки фильтров

- Шторки фильтров вручную проверить в light/dark, на ширинах
  320/412/448 px, с safe-area и клавиатурой в поиске проектов/меток:
  дата открывается только с иконки календаря, метки и статус — только из
  «Все фильтры», приоритет, проект и периодичность — с чипов и из
  «Все фильтры»; кнопка «Все фильтры» открывает общий шаг; back, крестик,
  оверлей, Escape и свайп вниз работают; под-шаг, открытый напрямую с
  чипа, по «Применить»/«Готово» применяет фильтр и закрывает шторку;
  под-шаг из «Все фильтров» по «Применить»/«Готово» меняет только
  черновик и возвращает в «Все фильтры»; back отбрасывает неприменённые
  правки шага, крестик — весь черновик, общий «Применить» применяет;
  «Сбросить фильтры» мгновенно закрывает шторку и возвращает сегодня.

## Фильтры

- Фильтры вручную проверить: проект — поиск, мультивыбор и
  `project_ids`, «Сбросить» видна только при выбранных проектах; метки — AND, пустое
  состояние, ошибка и «Повторить»; статус/регулярность — повторный тап
  снимает; дата — заголовок и список меняются, сброс возвращает
  сегодня; периодические серии не имеют отдельной опции. Завершение
  задачи при активном статус-фильтре скрывает/возвращает строку и
  откатывается при ошибке.

## Детали `/tasks/:id`

- Детали `/tasks/:id`: завершение меняет текст кнопки, идёт оптимистично,
  при ошибке откатывается и показывает alert; удаление открывает модалку
  с двумя панелями, «Отмена»/оверлей/Escape закрывают, для каскадной
  задачи серии видно предупреждение; после успеха или `404` кэш очищается,
  `["tasks"]`/`["projects"]` инвалидируются, возврат по истории (fallback
  `/tasks`); ошибка удаления остаётся в модалке и повтор работает.

## Шторка «Дата и время задачи»

- Шторка «Дата и время задачи» на `/tasks/:id`: тап по «Срок» открывает
  шторку, крестик/оверлей/Escape/свайп закрывают; смена даты/времени у
  разовой задачи отправляет только `due_at`; включение «Регулярной задачи»
  у разовой отправляет `regular`; выключение у ежедневной отправляет
  `one_off`; у периодической смена только времени не меняет интервал;
  ошибка PATCH показывается над «Готово», pending блокирует кнопку;
  открыть шторку, выбрать другой месяц/дату, закрыть без «Готово» и
  открыть снова — календарь показывает месяц срока задачи; успешный
  PATCH закрывает шторку; light/dark, 320/412/448 px, safe-area,
  клавиатура в поле времени.
