# Экран «Выбор проекта» (`/tasks/:id/project`)

- `/tasks/:id/project` («Выбор проекта») открывается из строки «Проект»
  на `/tasks/:id` и использует `GET /tasks/{id}` с детальным ключом
  `["tasks","detail",id]`, `GET /projects?limit=100` с ключом
  `["projects"]` и `PATCH /tasks/{id}`. Loader/action нет: данные
  загружаются React Query после `AuthGate`; задача и проекты грузятся
  параллельно. Невалидный `id` показывает «Задача не найдена» без
  запросов, `404` задачи — «Задача не найдена», другая ошибка — «Не
  удалось загрузить задачу» с «Повторить». `meta` — «Проект — Milly».
- Экран показывает заголовок «Выбор проекта», подсказку «Выберите
  к какому проекту привязать задачу», карточку `app-card` с
  `role="radiogroup"` и пояснение «Это позволит вам группировать и
  фильтровать свои задачи». Строки `47px`, `role="radio"` с
  `aria-checked`; текущий выбор отмечен `check.svg` цвета `app-accent`,
  в остальных строках на месте отметки пустое место. Активна вкладка
  «Задачи», FAB не показывается.
- Строки строго в порядке: «Без проекта» (`null`) всегда первая, затем
  активные проекты из `GET /projects?limit=100` в порядке backend.
  Архивные проекты не показываются; если текущий проект задачи в список
  не попал, ни одна строка не отмечена.
- Бейдж проекта — `ProjectIconBadge`: фон `project.color.hex` из
  backend и белая иконка `getProjectIcon(project.icon)`; «Без проекта» —
  `NO_PROJECT_ICON` (`no-project.svg`) на `bg-app-track` с `app-text`.
  Значение проекта на `/tasks/:id` остаётся текстом без бейджа.
- Выбор другого проекта сразу отправляет `PATCH /tasks/{id}` с
  `{ project_id }` (при «Без проекта» — явный `{ project_id: null }`),
  оптимистично меняет `project_id` в детальном кэше через
  `applyTaskDetailProject` и немедленно возвращает назад: `navigate(-1)`
  при наличии истории, иначе `/tasks/{id}`. Отдельной кнопки сохранения
  и pending-состояния нет. Успех заменяет детальный кэш ответом backend
  (если `updated.id === taskId`) и вызывает success haptic; `onSettled`
  инвалидирует детальный ключ, `["tasks"]`, `["task-series"]` и
  `["projects"]`.
- Выбор текущего проекта (или «Без проекта», когда проекта нет) `PATCH`
  не отправляет и только возвращает назад.
- Ошибка `PATCH` любого статуса: снимок кэша восстанавливается, звучит
  error haptic и показывается toast «Не удалось изменить проект.
  Попробуйте ещё раз.». При `404` дополнительно инвалидируются детали и
  `["projects"]`; toast тоже показывается, потому что `404` может
  означать как отсутствие задачи, так и недоступность проекта.
- Пока проекты загружаются, «Без проекта» доступна сразу, под списком
  видно «Загружаем проекты…». Ошибка проектов показывает «Не удалось
  загрузить проекты» и «Повторить» (`projectsQuery.refetch`); «Без
  проекта» остаётся доступной, а уже закэшированный список продолжает
  отображаться. Ошибки `PATCH` переход назад не блокируют.
- Загрузка задачи — `TaskProjectSkeleton` (`role="status"`,
  `aria-busy`, `aria-label="Загружаем проект"`); фоновый refetch не
  скрывает данные. Скелетон используется и в `RouteSkeleton`.
- В Telegram показывается нативная `BackButton` (Bot API 6.1+),
  скрывается при размонтировании; в браузере работает история. Haptics —
  только через `useTelegram().haptics`.

## Связанные общие правила

- Строка «Проект» на деталях — в `docs/agents/features/task-detail.md`.
- Бейдж проекта — в `docs/agents/ui.md`.
- Проверки — в `docs/agents/qa.md` (раздел «`/tasks/:id/project`»).
