# Экран «Приоритет задачи» (`/tasks/:id/priority`)

- `/tasks/:id/priority` («Приоритет задачи») открывается из строки
  «Приоритет» на `/tasks/:id` и использует `GET /tasks/{id}` с детальным
  ключом `["tasks","detail",id]` и `PATCH /tasks/{id}`. Loader/action нет:
  данные загружаются React Query после `AuthGate`; невалидный `id`
  показывает «Задача не найдена» без запроса. `meta` — «Приоритет — Milly».
- Экран показывает заголовок «Приоритет задачи», подсказку «Выберите
  приоритет задачи по Матрице Эйзенхауэра», карточку из четырёх
  `PRIORITY_OPTIONS` в фиксированном порядке и пояснение про матрицу.
  Текущий `task.priority` отмечен галочкой `check.svg` цвета `app-accent`;
  строки — `button role="radio"` с `aria-checked`, карточка —
  `role="radiogroup"` с `aria-label="Приоритет задачи"`. Только токены
  `app-*`; активна вкладка «Задачи», FAB не показывается.
- Выбор другого приоритета сразу отправляет `PATCH { priority }`,
  оптимистично меняет `priority` в детальном кэше через
  `applyTaskDetailPriority` и немедленно возвращает назад: `navigate(-1)`
  при наличии истории, иначе `/tasks/{id}`. Отдельной кнопки сохранения и
  pending-состояния нет. Успех заменяет детальный кэш ответом backend (если
  `updated.id === taskId`) и вызывает success haptic; `onSettled`
  инвалидирует детальный ключ, `["tasks"]` и `["task-series"]`, но не
  `["projects"]`.
- Выбор текущего приоритета `PATCH` не отправляет и только возвращает
  назад. Для невалидного `id` виден только экран «Задача не найдена» без
  вариантов выбора; `/tasks` — fallback возврата без истории, а не
  результат выбора.
- Не-`404` ошибка `PATCH`: снимок кэша восстанавливается, звучит error
  haptic и показывается toast «Не удалось изменить приоритет. Попробуйте
  ещё раз.». `404`: снимок восстанавливается, error haptic тоже звучит,
  детальный ключ инвалидируется, экран деталей показывает «Задача не
  найдена»; отдельный toast не показывается.
- Загрузка: `TaskPrioritySkeleton` (`role="status"`, `aria-busy`,
  `aria-label="Загружаем приоритет"`) при `isPending`; ошибка без кэша —
  `TaskDetailError` («Задача не найдена» для `404`, «Не удалось загрузить
  задачу» с «Повторить» для остальных). Фоновый refetch не скрывает
  данные. Скелетон используется и в `RouteSkeleton`.
- В Telegram показывается нативная `BackButton` (Bot API 6.1+), скрывается
  при размонтировании; в браузере работает история. Haptics — только через
  `useTelegram().haptics`.

## Связанные общие правила

- Строка «Приоритет» на деталях — в `docs/agents/features/task-detail.md`.
- Проверки — в `docs/agents/qa.md` (раздел «`/tasks/:id/priority`»).
