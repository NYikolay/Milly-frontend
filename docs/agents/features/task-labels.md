# Экран «Выбор меток задачи» (`/tasks/:id/labels`)

- `/tasks/:id/labels` открывается из строки «Метки» на `/tasks/:id` и
  использует `GET /tasks/{id}` с детальным ключом `["tasks","detail",id]`,
  `GET /labels` с существующим ключом `["labels"]` и `PATCH /tasks/{id}`.
  Loader/action нет: данные загружаются React Query после `AuthGate`;
  задача и метки грузятся параллельно. Невалидный `id` показывает
  «Задача не найдена» без запросов, `404` задачи — «Задача не найдена»,
  другая ошибка — «Не удалось загрузить задачу» с «Повторить». `meta` —
  «Метки — Milly» (`description` — «Изменение меток задачи в Milly»).
- Экран показывает заголовок «Выбор меток задачи», подзаголовок
  «Выберите или создайте метки для текущей задачи.» (при пустом списке —
  «На данный момент у вас отсутствуют какие-либо метки, но вы можете
  создать первую прямо сейчас.»), кнопку «Создать метку», поле поиска
  «Поиск», карточку меток и пояснение «Это позволит вам группировать и
  фильтровать свои задачи». Кнопка «Создать метку» — визуальная
  заглушка: она кликабельна и фокусируема, но обработчика нет, нажатие
  не отправляет запрос, не переходит, не показывает toast и не вызывает
  haptic. Активна вкладка «Задачи», FAB не показывается.
- Метки берутся из `GET /labels` в порядке backend (`lower(name)`, затем
  `id`), дубликаты по `id` отбрасываются. Цвет иконки `tag-raw.svg` и
  названия — `label.color.hex` из backend; выбранное состояние строка
  показывает залитым кружком, строки — `role="checkbox"` с
  `aria-checked`. Если текущая метка задачи отсутствует в `GET /labels`,
  она не показывается и не отмечается.
- Автосохранение: каждое нажатие на метку сразу отправляет
  `PATCH /tasks/{id}` с `{ label_ids }`, где массив — полный новый набор
  в порядке `GET /labels`; снятие последней метки отправляет явный
  `label_ids: []` (отсутствие поля означает «не менять»). Страница не
  закрывается и не переходит назад, отдельной кнопки сохранения или
  «Готово» нет. Мутации сериализуются через `scope: "task-labels"`,
  поэтому быстрые нажатия уходят по порядку, а итоговый набор сервера
  совпадает с финальным выбором. Максимум — 100 меток: нажатие на
  невыбранную метку сверх лимита игнорируется без запроса и toast.
- Перед запросом детальный кэш обновляется оптимистично через
  `applyTaskDetailLabels` (снимок сохраняется для отката); при возврате
  на `/tasks/:id` значение «Метки» сразу показывает актуальный набор.
  Успех заменяет детальный кэш ответом backend (если
  `updated.id === taskId`), вызывает success haptic и не показывает
  toast; `onSettled` инвалидирует детали, `["tasks"]` и `["task-series"]`.
- Ошибка `PATCH` любого статуса: снимок кэша восстанавливается, звучит
  error haptic и показывается toast «Не удалось изменить метки.
  Попробуйте ещё раз.»; пользователь остаётся на странице. При `404`
  дополнительно инвалидируются детали и `["labels"]`; toast не
  подавляется, потому что `404` может означать как отсутствие задачи,
  так и удалённую/недоступную метку.
- Поиск показывается только при наличии хотя бы одной загруженной метки и
  фильтрует по названию без учёта регистра через `matchesSearchQuery`;
  при пустой выдаче видно «Ничего не найдено». Фильтр только визуальный:
  скрытые выбранные метки остаются выбранными и попадают в `PATCH`.
  Запрос хранится в локальном состоянии и не пишется в URL.
- Пока метки загружаются, под кнопкой создания видно «Загружаем метки…»;
  поля поиска и карточки нет, кнопка создания и пояснение остаются.
  Ошибка меток показывает «Не удалось загрузить метки» и «Повторить»
  (`labelsQuery.refetch`); уже закэшированный список продолжает
  отображаться, а ошибка — под ним. Пустой список показывает
  подзаголовок про отсутствие меток без поиска и карточки.
- Загрузка задачи — `TaskLabelsSkeleton` (`role="status"`, `aria-busy`,
  `aria-label="Загружаем метки"`); фоновый refetch не скрывает данные.
  Скелетон используется и в `RouteSkeleton` (путь
  `/^\/tasks\/[^/]+\/labels\/?$/`).
- В Telegram показывается нативная `BackButton` (Bot API 6.1+),
  скрывается при размонтировании; возврат — `navigate(-1)` при наличии
  истории, иначе `/tasks/{id}`, для невалидного `id` — `/tasks`.
  Haptics — только через `useTelegram().haptics`.
